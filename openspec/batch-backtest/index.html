    Batch Backtest

    Purpose¶

    Defines the vectorised batch backtester of alpha_engine: the tools/backtest.py CLI entry point, the AlphaPipeline orchestration (metrics -> alpha strategies -> optional rolling combination -> execution smoothing -> PnL), the AlphaStrategy interface and the ALPHA_REGISTRY, the weight operators in operators.py, the universe volume filter, the PnL / cost kernel (backtest/pnl.py), weight smoothing (backtest/smooth.py), strategy combination (portfolio/markowitz.py, which also hosts risk_parity and ew), turnover diagnostics (backtest/turnover.py), the summary() result dict, and the plotting surface (backtest/plots.py). It covers the offline path only; the live runtime is specified separately under alpha-engine/live-trading.

    Requirements¶

    Requirement: Backtest CLI contract¶

    The system SHALL expose a standalone tools/backtest.py tool (runnable both as python tools/backtest.py, thanks to a sys.path bootstrap that inserts the repo root, and as python -m tools.backtest) whose argparse surface is exactly: --since (default 2023-06-01), --until (default 2024-06-01), both declared type=str and converted to pd.Timestamp(..., tz="UTC") only later and separately inside _run_backtest, _resolve_backtest_reader and _build_go_metrics_provider (so a malformed date surfaces as a pandas parse error mid-run, not as an argparse error); --alphas (nargs+, choices=list(ALPHA_REGISTRY), default ["funding_reversion"]); --data-root (default data, Hive-layout parquet); --mock (store_true); --metrics-roots (nargs+, default None); --tickers (nargs+, default None); --execution (close|vwap, default vwap); --max-w (float, default 0.03); --fee-bps (float, default 1.6); --slippage-bps (float, default 0.0); --spread-default-bps (float, default 2.0); --combine (markowitz|risk_parity|ew, default markowitz); --max-strategy-weight (float, default 0.5); --alloc-lookback-days (int, default 30); --no-plot (store_true); --log-level (default INFO). --fee-bps SHALL be converted to the pipeline's fractional fee_rate by dividing by 1e4 (so the default 1.6 bps becomes 0.00016), while --slippage-bps and --spread-default-bps SHALL be passed through in basis points and converted inside the kernel. --alloc-lookback-days SHALL be passed as lookback_days (bars = days * 48). --log-level SHALL configure the root logger through logging.basicConfig with the format %(asctime)s %(levelname)s [%(name)s] %(message)s; an unrecognised level name SHALL silently fall back to INFO via getattr(logging, name.upper(), logging.INFO). The tool SHALL run the pipeline, print Multi-strategy summary: followed by pipeline.summary(), print a timing line reporting data-source init seconds, pipeline run seconds, and their total, and then render pipeline.plot("dashboard") plus plt.show() unless --no-plot is given. A KeyboardInterrupt SHALL print [Backtest] Stopped. and exit with status 0.

    The CLI SHALL NOT expose several pipeline knobs, which therefore keep their AlphaPipeline defaults on every CLI run: end_range=50, smooth_delta=0.005, smooth_method="cap" (so execution smoothing is always ON for a CLI backtest), rebalance_hours=24 (48 bars), min_strategy_weight (fixed at combine_strategies' 0.0), exchanges=None (which becomes ["binance", "binance-f"]), compute_alpha_pnl_correlation=True, and seed=42 (stored on the instance and never read - a dead knob).

    Scenario: Default backtest run¶

    • WHEN tools/backtest.py is run with no flags
    • THEN it backtests funding_reversion on raw parquet under data/ from 2023-06-01 to 2024-06-01 with VWAP execution, markowitz selected but unused (single strategy, so the combination step is skipped), and cap smoothing at delta=0.005 applied to the resulting weights

    Scenario: Knob not on the command line¶

    • WHEN an operator wants a different end_range, smoothing setting, rebalance cadence, or min_strategy_weight
    • THEN there is no flag for it and the CLI run uses the AlphaPipeline default, so the change requires constructing AlphaPipeline directly

    Requirement: Backtest CLI data source selection¶

    The system SHALL resolve the backtest data source in a fixed precedence: --metrics-roots first (checked as if args.metrics_roots:), which builds GoMetricsStore(roots, since, until, tickers=args.tickers) wrapped in GoExchangeData and passes it as data_provider together with tickers=args.tickers; otherwise _resolve_backtest_reader returns MockRawDataReader(since, until) when --mock is given, or MultiFileParquetReader(data_root) when the root exists. Because --metrics-roots is tested first, it SHALL override --mock and --data-root rather than conflicting with them. A --data-root that does not exist and no --mock SHALL raise SystemExit with an actionable three-option message (populate it with binance_parser, repoint --data-root, or pass --mock) before any pipeline work. --tickers SHALL be honoured only on the --metrics-roots path (it reaches both GoMetricsStore and AlphaPipeline.tickers); on the --data-root and --mock paths it is silently dropped, so an operator restricting the universe there gets the full universe with no warning. On the --metrics-roots path the restriction takes effect only through GoMetricsStore: --tickers is also forwarded as AlphaPipeline(tickers=...), but _load_data returns the supplied provider unchanged, so the pipeline-level tickers (like since, until and exchanges) is never read there.

    Scenario: Missing data root without mock¶

    • WHEN --data-root points to a missing directory and neither --mock nor --metrics-roots is given
    • THEN the tool exits with an actionable error message instead of crashing inside the pipeline

    Scenario: Precomputed metric roots¶

    • WHEN --metrics-roots is given
    • THEN the tool reads Backend-go precomputed metrics via GoMetricsStore wrapped in GoExchangeData and passes it as the pipeline data provider, skipping raw-tick aggregation, even if --mock was also passed

    Scenario: Ticker restriction on a raw source¶

    • WHEN --tickers BTCUSDT is combined with --data-root or --mock
    • THEN the flag is dropped without a warning and the backtest runs the full discovered universe

    Requirement: Pipeline construction and validation¶

    The system SHALL validate AlphaPipeline configuration in the constructor, before any computation: combine restricted to markowitz|risk_parity|ew (else ValueError), execution restricted to close|vwap (else ValueError), at least one of data_reader / data_provider supplied (else ValueError naming both accepted forms), and every entry of alpha_names present in ALPHA_REGISTRY (else ValueError listing the available names). Constructor defaults SHALL be since=2023-01-01 UTC and until=2025-01-01 UTC when omitted (deliberately wider than the CLI defaults), tickers=None, alpha_names=None (meaning the entire ALPHA_REGISTRY), exchanges=None, max_w=0.03, end_range=50, lookback_days=30, rebalance_hours=24, max_strategy_weight=0.5, combine="markowitz", seed=42, execution="close" (the CLI overrides this to vwap), fee_rate=0.00016, slippage_bps=0.0, spread_default_bps=2.0, smooth_delta=0.005, smooth_method="cap", and compute_alpha_pnl_correlation=True. Derived state SHALL be self.lookback = lookback_days * 48 bars and self.rebalance_every = rebalance_hours * 2 bars. Data loading SHALL return data_provider unchanged when one was supplied (its own window, ticker list and exchange mapping win, and since/until/tickers/exchanges on the pipeline are then ignored); otherwise it SHALL build ExchangeData(reader, since, until, exchanges, tickers), which defaults to the two exchanges binance and binance-f and lays every metric on a pd.date_range(since, until, freq="30min", tz="UTC") grid. Each exchange gets its own AggregatedMetricsDict, whose universe - when tickers is None - is the sorted union of the reader's available tickers for the trades and klines kinds only (no other kind can introduce a ticker). A metric read SHALL lazily aggregate that metric's whole source group for every ticker at once and cache it; a metric name matching no registered source SHALL raise KeyError rather than return a NaN frame; a ticker with no data for a group SHALL get an all-NaN column; and a group where NO ticker had data SHALL still be marked aggregated, so every later key from it raises KeyError - which is exactly the signal the vwap and spread fallbacks in the pipeline key off.

    AlphaPipeline SHALL NOT copy or subset the container: the same object is reused for prices, funding, spreads and every strategy read, so a metric loaded once is paid for once.

    Scenario: Unknown metric name¶

    • WHEN a strategy asks the raw-parquet container for a metric that matches no registered aggregator source
    • THEN the container raises KeyError instead of silently serving a NaN frame

    Scenario: Invalid combine method¶

    • WHEN combine is set to an unsupported value
    • THEN the pipeline raises ValueError before any computation

    Scenario: Invalid execution model¶

    • WHEN execution is neither close nor vwap
    • THEN the constructor raises ValueError("Unknown execution model ...")

    Scenario: Unknown alpha name¶

    • WHEN an alpha name is not present in ALPHA_REGISTRY
    • THEN the pipeline raises ValueError listing the available names

    Scenario: No data source¶

    • WHEN neither data_reader nor data_provider is passed
    • THEN the constructor raises ValueError naming MultiFileParquetReader and GoExchangeData as the two accepted forms

    Requirement: Pipeline execution phases¶

    The system SHALL execute AlphaPipeline.run() in four logged phases - [1/4] load data (lazy: the log line states that real reads happen on first metric access), [2/4] generate strategy weights, [3/4] combine weights (skipped for a single selected alpha), [4/4] compute PnL - plus an unlabelled "Layer 3.5" execution-smoothing step between combine and PnL. Before phase 1 it SHALL log the alpha list, exchanges, window, and a smoothing description that reads off when smooth_delta is None or smooth_method == "off". Phase 2 SHALL branch on _compute_alpha_pnl_correlation and set(alpha_names) == set(ALPHA_REGISTRY): when both hold it runs _run_strategies_all over list(ALPHA_REGISTRY) and sets strategy_weights to the entries whose names are in the selected list; otherwise it runs only the selected alphas and sets all_strategy_weights = dict(strategy_weights). Because the branch condition already requires the selected set to equal the whole registry, the two paths produce the same alpha set - the "correlation panel" branch SHALL never widen the run beyond the alphas the operator selected. Both branches SHALL log a [2/4] line naming the alpha count and a completion line listing the names selected for combination.

    Drift and Markowitz prices SHALL be data["binance-f"]["mark_price"], read fresh from the container at run time (and again in summary() and plot()). After smoothing, the pipeline SHALL pre-compute price_ret = prices.pct_change().fillna(0) and funding_aligned = realized_funding.reindex(index=price_ret.index, columns=price_ret.columns).fillna(0) once and reuse them for the combined PnL and for every per-alpha PnL. It SHALL then compute self.pnl for the combined book and self.alpha_pnls[name] for every frame in all_strategy_weights, each first passed through the same _maybe_smooth.

    _compute_pnl SHALL, on every call, re-read data["binance-f"]["realized_funding"] and pass it as funding even though a supplied funding_aligned takes precedence inside the kernel and makes it dead; SHALL resolve exec_prices from data["binance-f"]["vwap"] only when execution == "vwap"; and SHALL resolve the spread frame exactly once per pipeline instance, caching it on _spread_cache via a hasattr guard so a None result is cached too and the (potentially expensive) probe is paid on the FIRST call - the combined book - and never repeated for the per-alpha frames. Because the funding frame is aligned to the mark-price return grid while w_shift is 2 under VWAP execution, the funding leg SHALL be charged on the same 2-bar-lagged weights as the gross leg, and the pre-computed price_ret SHALL simply be discarded by the kernel in that mode.

    It SHALL expose result attributes data, strategy_weights, all_strategy_weights, combined_weights, allocations, pnl, and alpha_pnls, and SHALL return the (smoothed) combined weights. It SHALL finish with a headline INFO line (elapsed seconds, cumulative net PnL, annualized Sharpe of daily-resampled pnl_net scaled by sqrt(365) - 0.0 when the daily standard deviation is not > 0, which includes the single-row case where it is NaN - bar count and ticker count); any exception while building that headline SHALL be logged with a traceback via logger.exception and re-raised so the run exits non-zero rather than reporting success on a suspect result.

    Scenario: Single-strategy run skips combination¶

    • WHEN exactly one alpha is selected
    • THEN combined_weights is a copy of that strategy's weight frame, allocations is None, combine_strategies is never called, and the copy is still passed through smoothing before PnL

    Scenario: Headline summary failure¶

    • WHEN the final headline computation raises (for example the PnL frame is empty and iloc[-1] fails)
    • THEN the pipeline logs the traceback at ERROR and re-raises instead of returning a suspect result

    Requirement: Strategy gating and registry¶

    The system SHALL gate strategies by their declared data-kind requirements before running: filter_runnable(names, data, exchange="binance-f") looks each name up in ALPHA_REGISTRY and keeps it only when data.has_kinds("binance-f", cls.required_kinds) is true; otherwise it records the missing kinds and run_strategies logs Skipping strategy '<name>' - missing data kinds: [...] at WARNING (never silently emitting NaN weights). Gating SHALL be fully permissive for containers whose metrics dict exposes no reader (ExchangeData.missing_kinds returns an empty set), while GoExchangeData SHALL instead probe its store for per-kind key sets (trades, klines, markprice, orderbook, and go_metrics, the last probing ob__minor__spread_bps__mean and vwap) and mark any kind it does not know as missing. If EVERY selected strategy is skipped the run does not degrade gracefully: a single selected but skipped strategy makes run() raise KeyError when copying its weights, and two or more skipped strategies raise ValueError("Need at least one strategy") from combine_strategies - the operator gets an unhandled traceback, not NaN weights. When two or more alphas are selected and exactly one survives gating, combine_strategies SHALL short-circuit and return that strategy's frame with a constant 1.0 allocation column (so allocations is a DataFrame, not None). The ALPHA_REGISTRY SHALL map CLI names to strategy classes keyed by the class name attribute and SHALL contain 18 entries: the seven hand-written alphas (ob_mispricing, vol_ob_entropy, funding_reversion, trade_imbalance, vol_mean_reversion, book_depth_imbalance, flow_book_divergence) plus BOOK_CLASSES (wf_*_all, 6), BOOK_V2_CLASSES (wf2_*, 3), and BOOK_V4_CLASSES (wf4_*, 2). All eleven sleeve families declare required_kinds = {"klines", "go_metrics"} and are therefore skipped, with a warning, whenever the backtest runs on raw-tick parquet or mock sources instead of --metrics-roots. run_strategies(data, alpha_names, max_w=0.03, end_range=50) SHALL be the single entry point shared by the batch pipeline and the live engine (alpha_engine/live/engine.py and alpha_engine/live/trader.py import it directly), and SHALL best-effort batch-preload the union of every runnable class's required_metrics() through data["binance-f"].preload(...) in one disk pass, swallowing any exception at DEBUG level (containers without a preload method, such as AggregatedMetricsDict, simply fall back to the lazy per-key path). The preload SHALL be skipped when the union is empty or the container exposes no preload, and the whole preload block - including the data["binance-f"] lookup itself - SHALL be inside the swallowing try, so a spot-only container without a binance-f entry degrades to the lazy path instead of raising. Strategies SHALL be instantiated with data, max_w and end_range only, so spot_exchange and futures_exchange always keep their binance / binance-f defaults in the batch path. Iteration order SHALL follow alpha_names, and filter_runnable SHALL raise KeyError on a name absent from ALPHA_REGISTRY (the pipeline constructor validates first, so only direct callers can hit this).

    Scenario: Skipped strategy logs missing kinds¶

    • WHEN a selected strategy's required_kinds are not available in the data
    • THEN the strategy is skipped and a WARNING log names the missing kinds

    Scenario: Go-metrics sleeve on raw-tick source¶

    • WHEN a wf_*, wf2_*, or wf4_* sleeve is selected but the data source is raw tick parquet or --mock
    • THEN the sleeve is skipped with a warning because the reader reports no tickers for the go_metrics kind

    Scenario: Preload unavailable¶

    • WHEN the data container has no preload method or preloading raises
    • THEN the failure is logged at DEBUG and the run continues on the lazy per-metric read path

    Requirement: Strategy weight contract¶

    The system SHALL define AlphaStrategy as the strategy interface. Subclasses implement gen_weights_raw(), which returns a raw un-normalized signal (positive = long bias, negative = short bias) on a timestamps x tickers frame. The base gen_weights() SHALL apply exactly three steps in order: gen_weights_raw(), then _cut_to_top_by_volume, then trunc_normalize(w, self.max_w). trunc_normalize SHALL first normalize (subtract the row mean, then divide by the row's absolute sum with a zero sum replaced by NaN, giving a dollar-neutral row summing to |w|.sum() == 1), then run a clip-and-renormalize fixed-point iteration bounded at iters=10: each pass clips to [-max_w, max_w] and returns immediately once EVERY row's gross is within 1e-9 of 1 (the tolerance is a global max across rows, so one non-converging row keeps the loop running for all rows); otherwise it renormalizes by the clipped gross and iterates, and after the last pass returns the clipped frame, so the final clip wins and the gross lands at N_active * max_w when the cap is infeasible. The fixed point SHALL only exist when N_active * max_w >= 1. Constructor defaults SHALL be spot_exchange="binance", futures_exchange="binance-f", max_w=0.03, end_range=50, and the base required_kinds SHALL be frozenset({"klines"}) (every strategy implicitly needs klines for the volume filter) with required_metrics() returning ("volume_usd", "close_price"). Rows that are entirely NaN after the volume cut (or entirely zero before it) SHALL stay NaN rather than raise; the downstream smoothing and PnL kernel both convert NaN to 0.

    Scenario: Normalization of a raw signal¶

    • WHEN a raw signal DataFrame is normalized with a feasible cap
    • THEN every row sums to ~0 and the absolute weights sum to 1, with no weight exceeding max_w

    Scenario: Infeasible cap¶

    • WHEN N_active * max_w < 1
    • THEN trunc_normalize returns the clipped result with gross exposure equal to N_active * max_w rather than failing

    Requirement: Book sleeve weight funnels¶

    The system SHALL let the 2026 book sleeves override gen_weights with their own funnels, which deviate from the base contract. The wf_*_all sleeves (book2026._Sleeve) SHALL run signal -> ts_ema(span = 48 * span_days) -> volume cut -> trunc_normalize at cap = min(1.0, CAP_MULT / w.shape[1]) with CAP_MULT = 2.125 (a per-name cap derived from the frame's COLUMN count, i.e. the whole served universe rather than the post-cut active count, and ignoring the configured max_w and --max-w) -> no_trade_band(w, BAND, cap) with BAND = 0.6. The band SHALL be a stateful per-ticker filter over bars: NaN targets are first converted to 0, the carried position starts at zeros, and each bar the position moves to the new target only where |target - prev| >= 0.6 * cap, otherwise the previous weight is held (a turnover filter measured to cut turnover ~3x). Because the band emits held weights, sleeve output is NOT re-normalized: neither exact dollar-neutrality nor unit gross survives it. The wf2_* and wf4_* sleeves (book2026v2._SleeveV2, which book2026v4 reuses via _make) SHALL instead run signal -> ts_ema(span = 48 * span_days) -> volume cut -> explicit cross-sectional demean (w.sub(w.mean(axis=1), axis=0)) -> trunc_normalize(w, self.max_w), using the configured max_w (CLI --max-w, default 0.03) and NO no-trade band; on a small universe this cap is infeasible and the sleeve runs at N_active * max_w gross. Both sleeve families SHALL declare required_metrics() as ("volume_usd", "close_price", "mark_price") plus their signal's Backend-go order-book keys from BASE_METRICS, and both read signals from self.data[self.futures_exchange], which GoExchangeData resolves to the same spot-backed container as binance.

    Each sleeve class SHALL be produced by a type() factory that fixes only name, base and span_days, so the EMA span is 48 * span_days with mass_dist=3, depth_carry=7, mom_9d=10, lean_persist=3, notional_top1=3, skew_carry=7, wf2_retskew_pos=7, wf2_accel_fade=3, wf2_mass_tilt=14, wf4_sharpe_mom5=14 and wf4_accel_e1=1. book2026v4 SHALL carry no signal table of its own: importing it MUTATES book2026v2.SIGNALS in place (adding sharpe_mom5 and binding accel_e1 to the SAME lambda object as accel_fade, so the two sleeves differ only in EMA span), and because the v4 bases are absent from book2026v2.BASE_METRICS the v4 sleeves' required_metrics() adds no order-book keys at all. no_trade_band SHALL return its input unchanged when band is falsy - unreachable with the shipped BAND = 0.6. The module-level BOOK_NAMES, BOOK_V2_WIDE and BOOK_V4 name lists SHALL be reference book compositions only: nothing in the batch path reads them, so selecting a book is entirely the operator's --alphas.

    Scenario: Book sleeve cap¶

    • WHEN a wf_*_all sleeve generates weights on a frame with n ticker columns
    • THEN the per-name cap is min(1.0, 2.125 / n) regardless of --max-w, and the frame is then passed through the 0.6-of-cap no-trade band

    Scenario: v2 sleeve funnel¶

    • WHEN a wf2_* or wf4_* sleeve generates weights
    • THEN it demeans cross-sectionally and applies trunc_normalize at the configured max_w with no no-trade band

    Requirement: Reusable weight operators¶

    The system SHALL provide the operator helpers in alpha_engine/operators.py used by every strategy. Cross-sectional (row-wise, axis=1) operators SHALL be rank (percentile rank 0..1), normalize (demean then scale to |w|.sum() == 1, with a zero absolute sum replaced by NaN so the row becomes NaN instead of dividing by zero), and trunc_normalize. Time-series (column-wise, along the timestamp index) operators SHALL be ts_return (pct_change(periods)), ts_logreturn (log(x / x.shift(periods))), ts_ema (ewm(span, min_periods=1).mean()), ts_std (rolling(window, min_periods=1).std()), and ts_zscore ((x - rolling mean) / rolling std with both rollings at min_periods=1 and a zero std replaced by NaN) - all of them therefore emit partial-window values from the very first bars rather than NaN warm-ups. Element-wise helpers SHALL be norm_ratio ((a - b) / (a + b) with a zero denominator replaced by NaN), set_entropy (Shannon-like entropy across frames, zero shares and a zero total replaced by NaN, with the result finally fillna(0)), and set_mean (np.nanmean over the stacked .values, so it assumes the inputs are already aligned and takes index/columns from the first frame). Zero-variance and zero-sum denominators SHALL produce NaN, never a crash or a division-by-zero warning path.

    Scenario: Zero-variance denominator¶

    • WHEN ts_zscore or norm_ratio hits a zero standard deviation or a zero denominator
    • THEN the affected cells become NaN and the computation continues

    Scenario: Partial warm-up window¶

    • WHEN a rolling or EMA operator is evaluated on the first bars of the window
    • THEN it returns a value computed from the partial window because min_periods=1, not NaN

    Requirement: Universe volume filter¶

    The system SHALL restrict every strategy's tradable universe to the top-end_range tickers (default 50) by rolling USD volume. _cut_to_top_by_volume SHALL read volume_usd from the FUTURES exchange container, reindex it onto the weight frame's columns with fill_value=0 (so a ticker absent from the volume panel scores zero volume), and take rolling(window=48*30, min_periods=1).mean() - a 1440-bar (30-day) mean of 30-min bars, despite the in-code comment calling it a day. Per row it SHALL compute the threshold as row.nlargest(end_range).min() when the row has any non-NaN value, else 0.0, then keep cells where rolling_vol >= threshold and set the rest to NaN via w.where(mask). Because the comparison is >=, ties at the threshold SHALL keep more than end_range names. Rows whose volumes are entirely NaN (early bars) SHALL use the zero threshold, which - since NaN >= 0 is False - NaNs the entire row out rather than crashing. The filter SHALL never drop columns; it only masks cells, so the frame's column count (used by the wf_*_all cap rule) is unchanged.

    Scenario: Top-N cut by volume¶

    • WHEN a weights row contains more than end_range tickers with distinct volumes
    • THEN only the end_range tickers with the highest rolling USD volume remain; the rest are set to NaN

    Scenario: All-NaN volume row¶

    • WHEN the rolling volume row is entirely NaN (earliest bars)
    • THEN the threshold is 0.0, the mask is all-False, and the whole weight row becomes NaN instead of raising

    Requirement: PnL and cost kernel¶

    The system SHALL compute per-bar PnL through the single kernel in backtest/pnl.py (pnl_core + compute_pnl), which SHALL NOT be re-implemented elsewhere (tests/test_backtest_kernel.py pins it against a frozen reference); the only other return computation in the batch path is the allocator's cost-free _strategy_returns. compute_pnl SHALL select the return series and lag in a fixed precedence: exec_prices given -> ret = exec_prices.pct_change().fillna(0) and w_shift = 2 (decide at t, fill at VWAP(t+1), earn VWAP(t+1) -> VWAP(t+2)), ignoring any supplied price_ret; else a pre-computed price_ret is used as-is with w_shift = 1; else ret = prices.pct_change().fillna(0) with w_shift = 1 (instant fill at the signal bar's close). Weights SHALL then be reindex(index=ret.index, columns=ret.columns, fill_value=0).fillna(0), so unknown bars/tickers and NaN cells all become zero positions. Gross return SHALL be (w.shift(w_shift).fillna(0) * ret).sum(axis=1). Traded notional SHALL be |w_t - w.shift(1).fillna(0) * price_change.fillna(1.0)| where price_change = prices / prices.shift(1) is always derived from the drift price argument (mark price), never from exec_prices, and where the previous-position lag is always 1 bar regardless of w_shift; NaN is resolved at the inputs so that a fresh position pays full |w_t| and an unknown drift on an existing position charges only |dw| (never a free trade at a price gap). Costs SHALL be (traded * cost_rate).sum(axis=1). Funding SHALL be (-funding_aligned * w.shift(w_shift).fillna(0)).sum(axis=1), using funding_aligned when supplied (it takes precedence over funding), else funding.reindex_like(w).fillna(0), else a zero Series when both are absent. Net PnL SHALL be gross - costs + funding, and the returned frame SHALL expose exactly the columns pnl_gross, cumulative_pnl_gross (cumsum), pnl_net, cumulative_pnl_net (cumsum), all as unlevered fractions of notional. pnl_core SHALL also return the per-ticker traded frame, which compute_pnl discards.

    pnl_core(w_aligned, ret, w_shift, price_change, cost_rate) SHALL accept cost_rate as either a scalar or a per-ticker/per-bar frame and SHALL assume w_aligned is already reindexed onto ret and NaN-free - it performs no alignment or NaN-filling of its own beyond the two documented fillnas. Its traded output SHALL therefore be NaN-free, and costs non-negative for any non-negative cost_rate. There SHALL be no leverage, no position sizing, no compounding and no per-bar equity curve: cumulative_* is a plain cumsum of per-bar fractional returns, so drawdowns and totals are additive, not geometric. The kernel SHALL be indifferent to bar spacing - nothing in it assumes 30-min bars; the 48-bars-per-day convention lives entirely in the callers.

    Scenario: Weights outside the price grid¶

    • WHEN the weight frame carries bars or tickers the price frame does not
    • THEN they are reindexed away with fill_value=0 and contribute no return, no cost and no funding, instead of raising or producing NaN

    Scenario: VWAP execution shifts fills¶

    • WHEN exec_prices (VWAP) are provided
    • THEN the position taken at bar t is filled at the VWAP of bar t+1 and earns the move from t+1 to t+2, while costs are still charged against the 1-bar-lagged drifted position

    Scenario: Missing vwap metric¶

    • WHEN execution="vwap" is requested but data["binance-f"]["vwap"] raises KeyError (only the raw-parquet / mock container raises; a --metrics-roots container serves an all-NaN frame instead, which yields zero exec returns and therefore zero gross PnL with no warning)
    • THEN the pipeline logs a WARNING and silently degrades to close-fill PnL (w_shift = 1) instead of failing

    Scenario: Funding leg¶

    • WHEN funding data is present
    • THEN net PnL includes the funding leg charged on the lagged weight, and absent funding contributes exactly zero

    Scenario: Zero weights¶

    • WHEN the weight frame is all zeros
    • THEN both pnl_gross and pnl_net are exactly zero on every bar

    Requirement: Cost rate and spread sourcing¶

    The system SHALL build the per-ticker, per-bar cost rate as fee_rate + slippage_bps / 1e4 (a flat frame over the aligned weight index and columns) plus, when a spread frame is supplied, spread_bps.reindex_like(w).clip(lower=0.0, upper=50.0) / 2 / 1e4 with remaining NaN cells filled from spread_default_bps / 2 / 1e4. When no spread frame is supplied at all, no spread cost is charged and the rate is fee plus slippage only. Half the spread SHALL be charged on every unit of traded notional (one side per trade), and the whole cost rate SHALL apply to traded, never to the held position - a book that does not trade pays nothing.

    The pipeline SHALL choose the spread frame once per instance (cached as _spread_cache), best basis first: (1) the EFFECTIVE spread from the tape, effective_spread_bps(buy_vwap, sell_vwap, vwap) where the two VWAP legs (but NOT the denominator vwap) have zeros replaced by NaN first; (2) on KeyError, the quoted L2 metric ob__minor__spread_bps__mean; (3) on KeyError again, None, which leaves only the flat spread_default_bps fallback for a frame that does not exist - i.e. no spread cost at all. The quoted L2 metric SHALL be documented as the less trusted basis (negative or zero on BTC, roughly 2x inflated on thin alts versus what takers actually paid), which is why the tape-derived effective spread is preferred.

    effective_spread_bps(buy_vwap, sell_vwap, vwap, window=48*7, floor_bps=0.2, cap_bps=50.0) SHALL compute (buy_vwap - sell_vwap) / vwap * 1e4, then rolling(window, min_periods=window // 7) .median(), then clip(lower=floor_bps, upper=cap_bps). min_periods SHALL be derived as window // 7, which is 48 only because the pipeline always uses the default 7-day window; the warm-up is therefore the first 47 bars, which stay NaN and fall back to spread_default_bps inside compute_pnl. Note the floor of 0.2 bps applies to the frame while compute_pnl re-clips it to a floor of 0.0, so the effective-spread basis can never reach zero but a caller-supplied frame can.

    The KeyError-based fallback chain SHALL be understood as a raw-parquet-path mechanism only. On the --metrics-roots path the Go name resolver passes unknown metric names through unchanged, so a key that no root populates yields an all-NaN frame plus a WARNING rather than a KeyError: the pipeline then keeps that all-NaN effective-spread frame as its chosen basis, and every cell falls back to spread_default_bps / 2 / 1e4. The quoted-metric branch is unreachable there.

    Scenario: Effective spread unavailable on precomputed metrics¶

    • WHEN the --metrics-roots dataset does not populate buy_vwap / sell_vwap
    • THEN the store logs a WARNING and serves NaN frames, the pipeline caches that all-NaN spread basis, and every bar is costed at the flat spread_default_bps half-spread instead of falling through to the quoted L2 metric

    Scenario: Spread default fill¶

    • WHEN a provided spread frame has NaN cells (warm-up bars or data holes)
    • THEN those cells cost spread_default_bps / 2 / 1e4 per unit traded, while an entirely absent spread frame charges no spread cost at all

    Scenario: Spread clipping¶

    • WHEN a spread frame carries a negative or extreme value
    • THEN compute_pnl clips it into [0.0, 50.0] bps before halving it into the cost rate

    Requirement: Weight smoothing¶

    The system SHALL smooth combined weights to simulate real portfolio transition limits. smooth_weights(w, prices, delta, method="cap") SHALL always fillna(0.0) first (even when smoothing is off, so NaN never leaks into the cost kernel and flips pnl_net to NaN), and SHALL return that frame unchanged when delta is None or method == "off" - this short-circuit happens BEFORE method validation, so an unknown method name is only rejected when delta is set and method != "off", in which case anything outside {"cap", "normalize"} raises ValueError. With smoothing active it SHALL reindex prices onto the weight frame, ffill it, and drift the carried position by ratio = (px / px.shift(1)).fillna(1.0), iterating bar by bar with the carried position starting at zeros and the first bar deliberately not drifted (prev_drifted = prev when i == 0). With method="cap" each ticker's per-bar change SHALL be clipped independently to +/-delta against the drifted previous position; with method="normalize" the whole delta vector SHALL be scaled by delta / max|dw| only when max|dw| > delta and max|dw| > 0. The result SHALL be the drifted previous position plus the adjusted delta, and it SHALL NOT be re-normalized, so gross exposure can sit below 1 while the book is still transitioning. AlphaPipeline._maybe_smooth SHALL always delegate to smooth_weights (never skip the call) and SHALL be applied both to the combined weights and to each per-alpha frame before its PnL.

    The loop SHALL be a plain Python bar loop over a float64 numpy copy, and the result SHALL be rebuilt as a DataFrame carrying the WEIGHT frame's index and columns, so smoothing never changes the frame's shape, order or labels. prices SHALL be reindexed on BOTH axes onto the weight frame before the ffill, so a ticker the price panel does not carry becomes an all-NaN price column whose drift ratio is fillna(1.0)-ed to 1.0 - such a position is carried at constant weight rather than dropped. Neither method SHALL cap the LEVEL of a weight: delta bounds only the per-bar change, so a smoothed book can exceed max_w on a name only if the unsmoothed target already did.

    Scenario: Cap smoothing¶

    • WHEN smoothing is active with method="cap" and delta=0.005
    • THEN no ticker's weight changes by more than 0.005 per bar relative to its drifted prior position

    Scenario: NaN handling with smoothing off¶

    • WHEN delta is None (smoothing off)
    • THEN the weights still pass through the NaN-to-zero normalization and are returned unchanged, without validating method

    Requirement: Strategy combination¶

    The system SHALL combine per-strategy weight frames into one portfolio via combine_strategies(strategy_weights, prices, method, lookback=48*30, rebalance_every=48, max_strategy_weight=0.5, min_strategy_weight=0.0), with an unknown method raising ValueError, an empty dict raising ValueError("Need at least one strategy"), and a single entry short-circuiting to that frame with a constant 1.0 allocation column. The common index and ticker columns SHALL be taken from the FIRST strategy's frame; every other strategy is reindexed onto it with fill_value=0. ew SHALL hold a constant 1 / n_strategies on every row. The rolling methods (markowitz, risk_parity) SHALL derive per-strategy PnL with _strategy_returns as sum(w.shift(1) * prices.pct_change().fillna(0)) - gross, cost-free, and always 1-bar-lagged regardless of the pipeline's --execution setting - reindexed onto the common index with fill_value=0; then walk bars, holding the previous allocation whenever i < lookback or i % rebalance_every != 0 and starting from equal weight so the warm-up trades an EW book instead of silently flattening to zero. On a rebalance bar the estimator SHALL use strat_returns.iloc[i - lookback : i] (strictly prior bars, no look-ahead) resampled to daily sums, because raw 30-min bars are too noisy for a mean estimate; the resulting allocation is applied from bar i itself. Markowitz SHALL solve the Tobin tangency w* = V^-1 mu / (e^T V^-1 mu) on a covariance stabilised by a 1e-12 ridge, raise when e^T V^-1 mu is non-finite or |.| < 1e-15, reject infeasible boxes (min*n > 1 or max*n < 1), enforce [min_strategy_weight, max_strategy_weight] by active-set water-filling that pins the single worst violator per pass and redistributes the remaining mass proportionally to the tangency direction, and raise if the pinned result sums to a non-positive total; the caller SHALL catch ValueError and np.linalg.LinAlgError and fall back to equal weight for that window. risk_parity SHALL allocate proportionally to 1 / vol of the daily-resampled window (zero-vol strategies get 0) and fall back to equal weight when the inverse-vol sum is not positive. The combined portfolio SHALL be sum(w_name.fillna(0) * allocation_name) per name, with the number of NaN weight cells per strategy logged as a WARNING so a broken strategy silently zeroing out is distinguishable from a legitimate all-zero row. markowitz_combine SHALL remain as a thin backwards-compatible wrapper returning only the combined frame.

    The single-strategy short-circuit SHALL return the caller's frame object itself, not a copy (the pipeline's own single-alpha path is the one that copies). The allocations frame SHALL be created all-NaN and then fully written: ew assigns every row, and the rolling methods assign every row too (warm-up and hold bars get the carried allocation), so no NaN survives into allocations for any method. _strategy_returns SHALL recompute prices.pct_change().fillna(0) itself rather than reuse the pipeline's price_ret, and SHALL reindex each strategy onto that return frame's index and columns with fill_value=0 before shifting.

    Beyond the documented tangency and box failures, _solve_markowitz SHALL also raise ValueError for an empty mu, for a cov whose shape is not (n, n), when the free subset's tangency direction sums to ~0 during water-filling, and when the pin loop runs n + 1 passes without converging; it SHALL skip box handling entirely when the box is exactly (-inf, +inf). Every one of these is caught by combine_strategies and turned into an equal-weight allocation for that window, so no solver failure can abort a backtest. risk_parity SHALL have no box constraint at all - max_strategy_weight and min_strategy_weight are markowitz-only.

    Scenario: Markowitz solver failure fallback¶

    • WHEN the tangency solve fails (singular covariance, undefined tangency denominator, or an infeasible box)
    • THEN the allocation for that window falls back to equal weight instead of aborting

    Scenario: Warm-up allocation¶

    • WHEN fewer than lookback bars of history are available
    • THEN allocations hold equal weight rather than zero or NaN, so the portfolio is not flattened during warm-up

    Scenario: Between rebalances¶

    • WHEN a bar index is not a multiple of rebalance_every
    • THEN the previous allocation is carried forward unchanged

    Requirement: Turnover diagnostics¶

    The system SHALL compute turnover from drifted positions: per_bar_turnover(weights, prices) SHALL reindex prices like the weights, form price_change = prices / prices.shift(1), and return sum(|w_t - w_{t-1} * price_change|) per bar - the "real trade" after price drift. It SHALL NOT fill NaN, so NaN cells (masked-out universe names) are skipped by the sum and the first bar sums to 0.0; this deliberately differs from the cost kernel, which fills the previous position with 0 and the drift with 1.0 and therefore charges entries the kernel sees as real trades. daily_turnover SHALL be the per-bar series resampled to daily sums, and it is what the summary and the turnover plot report. Turnover SHALL be a pure diagnostic: nothing feeds it back into weights, costs or PnL, so a fee or spread change moves PnL without moving reported turnover. Both callers SHALL pass the SMOOTHED combined_weights and the mark price, so the reported number describes the executed book rather than the raw alpha targets.

    Scenario: Turnover of a held position¶

    • WHEN weights are unchanged but prices move
    • THEN per-bar turnover reflects only the drifted difference, not the full weight

    Scenario: First bar¶

    • WHEN turnover is computed for the first bar of the frame
    • THEN the shifted weights are NaN and the row sums to 0.0 rather than to the full opening notional

    Requirement: Run summary¶

    The system SHALL expose AlphaPipeline.summary(), which raises RuntimeError("Call .run() first") before a run and otherwise returns a dict with n_strategies and strategy_names (from strategy_weights, i.e. the RUNNABLE subset of the selected alphas - a gated-out alpha silently drops out of this list), n_tickers and n_timestamps (shape of the smoothed combined_weights), date_range as "<first> -> <last>", smoothing rendered as "<method> (delta=<delta>)" or "off", mean_daily_turnover and median_daily_turnover from daily_turnover(combined_weights, mark_price), and two nested blocks gross and net, each holding total_pnl (last cumulative value), annualized_sharpe (daily-resampled mean/std times sqrt(365), 0 when the daily std is not > 0), and max_drawdown (minimum of cumulative - cumulative.cummax(), so a non-positive number). The CLI SHALL print this dict verbatim.

    The summary SHALL report NO cost breakdown, NO per-strategy or per-ticker attribution, NO win rate, NO exposure or leverage statistic, and NO holding period: the only cost visibility is the gross-minus- net gap the caller computes for itself. It SHALL recompute turnover on every call (nothing is cached) and SHALL read mark_price from the container again, so calling summary() on a pipeline whose data container has been mutated can disagree with the run's own headline line.

    Scenario: Summary before run¶

    • WHEN summary() is called before run()
    • THEN it raises RuntimeError telling the caller to run first

    Scenario: Flat daily PnL¶

    • WHEN the daily-resampled PnL has zero or NaN standard deviation (for example a single-bar backtest)
    • THEN the reported annualized Sharpe is 0 rather than an infinity or NaN

    Requirement: Plotting surface¶

    The system SHALL expose AlphaPipeline.plot(kind="dashboard", top_n=10) supporting kinds dashboard, pnl, drawdown, weights, turnover, allocations, and correlation, each returning a single matplotlib Figure. Calling plot before run() SHALL raise RuntimeError("Call .run() first"); allocations on a single-strategy run SHALL raise ValueError("No allocations (single-strategy run)"); unknown kinds SHALL raise ValueError. The dashboard SHALL stack, in order, cumulative PnL (gross and net), net drawdown, daily turnover (annotated with its mean), and a weights heatmap of the top 30 tickers by mean absolute weight, appending an allocations stack-plot only when allocations is not None; plot_dashboard returns (main_fig, corr_fig) where corr_fig is built only when more than one alpha PnL exists, and AlphaPipeline.plot SHALL discard that second handle to keep the uniform single-Figure return, leaving the caller unable to close it. The correlation view SHALL dispatch on allocations is None: a multi-strategy run gets side-by-side 30-min and daily pairwise pnl_net correlation heatmaps with the diagonal masked to gray, and a single-strategy run gets a top-top_n horizontal bar chart of alphas correlated with the active alpha, annotated with each alpha's sqrt(365) daily Sharpe. plot_pnl_correlation SHALL raise RuntimeError when alpha_pnls is empty. The panel is fed by alpha_pnls, which covers every registered alpha only when compute_alpha_pnl_correlation is true AND the selected alpha set equals the whole ALPHA_REGISTRY; otherwise it covers just the selected alphas. Consequently the single-strategy bar chart has no comparison set under the current wiring (one selected alpha implies one entry in alpha_pnls) and renders empty, and the dashboard skips the correlation figure entirely in that case. Per-alpha PnL used in these panels SHALL come from post-smoothing weights (_maybe_smooth), so it represents achievable rather than paper performance.

    plot_dashboard SHALL itself raise RuntimeError("Call pipeline.run() first") when pnl is None, and SHALL lay out its rows with height ratios [2, 1, 1, 3] plus a trailing 1 only when allocations exist. The Sharpe annotations on the correlation bar chart SHALL come from _alpha_sharpe, which returns 0.0 whenever the daily-resampled series has zero standard deviation OR fewer than two daily points - a stricter guard than the summary() and headline versions, which only test std > 0. The pairwise heatmaps SHALL be built from pnl_net only (gross is never correlated), at both raw 30-min and daily-summed resolutions, and the bar chart SHALL sort descending by correlation and keep the top top_n on each resolution independently. No plotting function SHALL write a file: every one returns a Figure and only the CLI's plt.show() displays it.

    Scenario: Plot before run¶

    • WHEN plot is called before run()
    • THEN it raises RuntimeError telling the caller to run first

    Scenario: Allocations plot on single strategy¶

    • WHEN plot("allocations") is called on a single-strategy run
    • THEN it raises ValueError because allocations are undefined

    Scenario: Correlation panel on a subset of alphas¶

    • WHEN several but not all registered alphas are selected
    • THEN only those alphas are run and the correlation heatmaps cover just that subset

    Requirement: Raw-tick data sources¶

    The system SHALL support two raw-tick backtest sources behind the RawDataReader interface (read(...) -> DataFrame | None and available_tickers(exchange, kind) -> list[str]). MultiFileParquetReader SHALL read the binance_parser Hive layout (market={spot|usdm}/type={event}/dt=YYYY-MM-DD/symbol={SYMBOL}/part-*.parquet), mapping the alpha-engine exchange tags binance -> market=spot and binance-f -> market=usdm and each RawDataKind to one or more type= partitions; it SHALL prune by dt= partition before opening any file, keep a day whose span overlaps [since, until], normalise the live-writer column names to what the aggregators expect, then re-filter and sort by timestamp. An unparseable dt= directory or an unreadable shard SHALL be skipped with a WARNING (never silently), and a query with no matching files SHALL return None, which the aggregator treats as "this ticker has no data" and turns into an all-NaN column.

    MockRawDataReader SHALL synthesise structurally identical data from one seeded random walk per ticker (default seed=42, 500 trades per 30-min bar, 5 order-book snapshots per bar of 50 levels a side) and SHALL claim ONLY the kinds it can synthesise - trades, orderbook, klines, funding, markprice - returning an empty ticker list for anything else. That is what makes required_kinds gating meaningful on --mock: a go_metrics sleeve is skipped with a warning instead of crashing on a missing key. The CLI SHALL construct it with the run window only, so the universe is the module default ticker list.

    Scenario: Unreadable shard¶

    • WHEN one parquet shard in the requested window cannot be read
    • THEN the reader logs a WARNING, skips that shard, and returns the remaining data instead of aborting the backtest

    Scenario: Mock source and kind gating¶

    • WHEN the backtest runs with --mock
    • THEN only trades / orderbook / klines / funding / markprice strategies are runnable and every go_metrics sleeve is skipped with a warning

    Requirement: Precomputed metrics data source¶

    The system SHALL serve the --metrics-roots backtest from GoMetricsStore + GoExchangeData over Backend-go Hive parquet ({root}/market={market}/type=metrics/dt=*/symbol=*/part-*.parquet, one keys list-of-(name, value) column per 30-min bar). The store SHALL default to market="spot", cache_dir=".metrics_cache" and workers=8, SHALL log a WARNING and skip any supplied root without the market=/type=metrics partition, SHALL raise FileNotFoundError when NO root has it, and SHALL raise ValueError("No symbols found in the requested window") when the symbol scan comes back empty after the optional tickers filter. Symbols SHALL be discovered from the first and last day directory of each root only (an upper-cased set intersection with tickers), and the bar index SHALL be pd.date_range(since, until, freq="30min", tz="UTC") - every served frame is reindexed onto it, so a gap becomes NaN rather than a missing row.

    Because the Go writer emits the full key schema everywhere, zero-filled for groups it did not compute, the store SHALL probe up to three sampled day directories per root to learn which keys that root actually populates non-zero, and SHALL read each requested key only from roots that carry it. A key populated by NO root SHALL produce an all-NaN frame plus a WARNING - never a KeyError.

    GoExchangeData SHALL map BOTH binance and binance-f to ONE shared GoMetricsDict (the Go datasets are spot-only), SHALL batch-preload a fixed metric tuple at construction unless preload=False, and SHALL gate required_kinds from its own _KIND_PROBES table rather than from a reader. Name resolution SHALL alias alpha-engine names to Go keys (close_price/mark_price from close on spot, volume_usd from quote_volume, buy_cost/sell_cost from the quote-volume legs, bid_25_cost_avg-style names to ob__..pct__..__..__mean), SHALL serve predicted_funding as a zero frame, and SHALL PASS THROUGH any unrecognised name as a raw Go key - which is why a misspelled or unpopulated metric surfaces as a NaN frame instead of an error on this path. Price-like frames SHALL have 0.0 replaced by NaN and then forward-filled, since 0.0 is the Go writer's "no data this bar" marker.

    realized_funding SHALL be served with settlement semantics: zero on every bar except the 00/08/16 UTC settlement bars, which carry the value observed in the bar immediately BEFORE settlement; a dataset without the key SHALL serve an all-zero frame. This exists so compute_pnl, which charges funding every bar, charges each 8h period exactly once instead of ~16x.

    Scenario: Key absent from every root¶

    • WHEN a strategy or the cost model asks for a Go key no configured root populates
    • THEN the store logs a WARNING and serves an all-NaN frame on the standard index, and the backtest continues with NaN-driven zeros rather than failing

    Scenario: Funding on a settlement bar¶

    • WHEN a bar is 00:00, 08:00 or 16:00 UTC and the dataset carries realized_funding
    • THEN that bar carries the previous bar's rate and every other bar carries 0.0, so the PnL funding leg charges each 8h period once

    Requirement: Backtest outputs and side effects¶

    The system SHALL treat the batch backtest as an in-memory, side-effect-free job: no module in alpha_engine/pipeline.py, alpha_engine/backtest/, alpha_engine/portfolio/, alpha_engine/strategies/, alpha_engine/operators.py, or tools/backtest.py writes a report, CSV, parquet, or image to disk. Results SHALL be surfaced only through the returned/attached objects, the log lines, the printed summary() dict, and the interactive plt.show() window. The single persistent artifact in the whole path SHALL be the GoMetricsStore per-key frame cache on the --metrics-roots path: one parquet per Go metric key under cache_dir (default .metrics_cache relative to the working directory), keyed by a SHA1 over roots, window, ticker list, a data fingerprint (shard count plus newest mtime), and the key name, so a rebuilt dataset invalidates it; a failed cache write SHALL log a WARNING and continue.

    Scenario: No files produced¶

    • WHEN a backtest completes with --no-plot
    • THEN nothing is written to disk except (on the --metrics-roots path) the .metrics_cache parquet frames, and all results live in the pipeline object and stdout

    Scenario: Cache write failure¶

    • WHEN writing a cached metric frame fails
    • THEN the store logs a WARNING and the backtest proceeds by reading the shards
