    Batch Backtest

    Purpose¶

    Defines the vectorised batch backtester of alpha_engine: the tools/backtest.py CLI entry point, the AlphaPipeline orchestration (metrics -> alpha strategies -> optional Markowitz combination -> PnL), the AlphaStrategy interface and the ALPHA_REGISTRY, weight normalization and universe-filtering operators, the PnL / cost kernel (backtest/pnl.py), weight smoothing, strategy combination (portfolio/markowitz.py), turnover diagnostics, and the plotting surface. It covers the offline path only; the live runtime is specified separately under alpha-engine/live-trading.

    Requirements¶

    Requirement: Backtest CLI contract¶

    The system SHALL expose a standalone tools/backtest.py tool (runnable both as python tools/backtest.py and python -m tools.backtest) that accepts --since / --until (UTC YYYY-MM-DD, defaults 2023-06-01 / 2024-06-01), --alphas (nargs+, choices from ALPHA_REGISTRY, default funding_reversion), --data-root (default data, Hive-layout parquet), --mock (synthetic data), --metrics-roots (Backend-go precomputed metric roots, bypassing raw-tick aggregation), --tickers, --execution (close|vwap, default vwap), --max-w (default 0.03), --fee-bps (default 1.6), --slippage-bps (default 0.0), --spread-default-bps (default 2.0), --combine (markowitz|risk_parity|ew, default markowitz), --max-strategy-weight (default 0.5), --alloc-lookback-days (default 30), --no-plot, and --log-level. The tool SHALL run the pipeline, print pipeline.summary(), and display the dashboard plot unless --no-plot is given.

    Scenario: Default backtest run¶

    • WHEN tools/backtest.py is run with no flags
    • THEN it backtests funding_reversion on raw parquet under data/ from 2023-06-01 to 2024-06-01 with VWAP execution (single strategy, so the combination step is skipped)

    Scenario: Missing data root without mock¶

    • WHEN --data-root points to a missing directory and --mock is not given
    • THEN the tool exits with an actionable error message instead of crashing inside the pipeline

    Scenario: Precomputed metric roots¶

    • WHEN --metrics-roots is given
    • THEN the tool reads Backend-go precomputed metrics via GoMetricsStore wrapped in GoExchangeData and passes it as the pipeline data provider, skipping raw-tick aggregation

    Requirement: Pipeline execution phases¶

    The system SHALL execute AlphaPipeline.run() in four logged phases: load data, generate strategy weights, combine weights (skipped for a single strategy), and compute PnL. The pipeline SHALL validate its configuration up front: combine restricted to markowitz|risk_parity|ew, execution restricted to close|vwap, at least one of data_reader / data_provider provided, and every alpha name resolvable in ALPHA_REGISTRY (unknown names raise ValueError listing available names). It SHALL expose result attributes strategy_weights, combined_weights, allocations, pnl, and alpha_pnls, and SHALL finish with a headline summary (cumulative net PnL, annualized Sharpe from daily-resampled net PnL with sqrt(365), bar and ticker counts) that is re-raised on failure rather than silently swallowed.

    Scenario: Single-strategy run skips combination¶

    • WHEN exactly one alpha is selected
    • THEN the combined weights are the strategy's own weights, allocations is None, and the Markowitz step is skipped

    Scenario: Invalid combine method¶

    • WHEN combine is set to an unsupported value
    • THEN the pipeline raises ValueError before any computation

    Scenario: Unknown alpha name¶

    • WHEN an alpha name is not present in ALPHA_REGISTRY
    • THEN the pipeline raises ValueError listing the available names

    Requirement: Strategy gating and registry¶

    The system SHALL gate strategies by their declared data-kind requirements before running: a strategy is runnable only if the data layer has every kind in its required_kinds for the futures exchange; otherwise it is skipped with a WARNING log naming the missing kinds (never silently emitting NaN weights). If EVERY selected strategy is skipped the run does not degrade gracefully: a single selected but skipped strategy makes run() raise KeyError when copying its weights, and two or more skipped strategies raise ValueError("Need at least one strategy") from combine_strategies - the operator gets an unhandled traceback, not NaN weights. The ALPHA_REGISTRY SHALL map CLI names to strategy classes by the class name attribute. Sleeve families from the 2026 books (wf_*_all, wf2_*, wf4_*) SHALL declare the go_metrics kind and are therefore skipped, with a warning, when the backtest runs on raw-tick parquet sources instead of --metrics-roots.

    Scenario: Skipped strategy logs missing kinds¶

    • WHEN a selected strategy's required_kinds are not available in the data
    • THEN the strategy is skipped and a WARNING log names the missing kinds

    Scenario: Go-metrics sleeve on raw-tick source¶

    • WHEN a wf_* book sleeve is selected but the data source is raw tick parquet
    • THEN the sleeve is skipped with a warning because go_metrics data is absent

    Requirement: Strategy weight contract¶

    The system SHALL define AlphaStrategy as the strategy interface: gen_weights_raw() produces a raw un-normalized signal (positive = long bias, negative = short bias), and gen_weights() SHALL normalize every strategy's output to be dollar-neutral (row sum ~ 0) with unit gross exposure (|w|.sum() == 1 per row), applying a per-ticker cap max_w via trunc_normalize (clip-and-renormalize fixed-point iteration with a tolerance of 1e-9, terminating early when converged; after the iteration limit the final clip wins and the gross is N_active * max_w when the cap is infeasible). The fixed point SHALL require N_active * max_w >= 1. The book-2026 sleeves (wf_*_all) SHALL deviate from the uniform cap: they cap at min(1.0, CAP_MULT / n) with CAP_MULT = 2.125 (ignoring max_w``) and then pass the frame through a no-trade band filter (BAND = 0.6) that holds the previous weight until the target moves by at least0.6 * cap(turnover filter, cuts turnover ~3x). Reusable operators (rank,normalize,trunc_normalize,ts_return,ts_logreturn,ts_ema,ts_std,ts_zscore,norm_ratio,set_entropy,set_mean`) SHALL operate row-wise on timestamps x tickers DataFrames, and zero-variance denominators SHALL produce NaN, not crashes.

    Scenario: Normalization of a raw signal¶

    • WHEN a raw signal DataFrame is normalized
    • THEN every row sums to ~0 and the absolute weights sum to 1, with no weight exceeding max_w

    Scenario: Infeasible cap¶

    • WHEN N_active * max_w < 1
    • THEN trunc_normalize returns the clipped result with gross exposure equal to N_active * max_w rather than failing

    Requirement: Universe volume filter¶

    The system SHALL restrict every strategy's tradable universe to the top-end_range tickers (default 50) by rolling USD volume, computed as the rolling mean over a 48-by-30 bar window (one month of 30-min bars, min_periods=1); rows whose volumes are entirely NaN (early bars) SHALL use a zero threshold so the whole row is filtered out rather than crashing.

    Scenario: Top-N cut by volume¶

    • WHEN a weights row contains more than end_range tickers
    • THEN only the end_range tickers with the highest rolling USD volume remain; the rest are set to NaN

    Requirement: PnL and cost kernel¶

    The system SHALL compute per-bar PnL through the single kernel in backtest/pnl.py (pnl_core + compute_pnl), which SHALL NOT be re-implemented elsewhere. Gross return SHALL be (w.shift(w_shift).fillna(0) * ret).sum(axis=1). Costs SHALL be charged on traded notional |w_t - prev * price_change| (with NaN price drift resolved at the inputs: a fresh position pays full |w_t|, an unknown drift on an existing position charges |dw|) times a per-ticker cost rate. Two execution models SHALL be supported: instant fill at the signal bar's close (w_shift=1), and VWAP fill at the next bar (w_shift=2, decision at t, fill at VWAP(t+1), earn VWAP(t+1) -> VWAP(t+2)). Requesting execution="vwap" while the data carries no vwap metric SHALL log a warning and degrade silently to close-fill PnL rather than fail. The cost rate SHALL be fee_rate + slippage/1e4, plus half the effective spread derived from tape VWAPs (effective_spread_bps = rolling median over 48*7 bars of (buy_vwap - sell_vwap)/vwap * 1e4, clipped to [0.2, 50.0] bps); when the tape spread is unavailable, the fallback chain SHALL first use the quoted L2 metric ob__minor__spread_bps__mean and only then the flat spread_default_bps (default 2.0), which fills NaN cells inside a provided spread frame - and if no spread frame exists at all (all three sources absent), no spread cost is charged. --tickers SHALL restrict the universe only on the --metrics-roots path; on the raw-parquet (--data-root) and --mock paths it is silently dropped, so an operator restricting the universe there gets the full universe with no warning. Funding SHALL be charged as (-funding_aligned * w_aligned.shift(w_shift)).sum(axis=1). Net PnL SHALL be gross - costs + funding, and the output SHALL expose exactly the columns pnl_gross, cumulative_pnl_gross, pnl_net, cumulative_pnl_net.

    Scenario: VWAP execution shifts fills¶

    • WHEN exec_prices (VWAP) are provided
    • THEN the position taken at bar t is filled at the VWAP of bar t+1 and earns the move from t+1 to t+2

    Scenario: Spread default fill¶

    • WHEN no tape spread is available for a bar
    • THEN the fallback chain first uses the quoted L2 spread metric; only NaN cells inside a provided spread frame fall back to spread_default_bps / 2 / 1e4, and an entirely absent spread frame charges no spread cost at all

    Scenario: Funding leg¶

    • WHEN funding data is present
    • THEN net PnL includes the funding leg charged on the lagged weight, and absent funding contributes zero

    Requirement: Weight smoothing¶

    The system SHALL smooth combined weights to simulate real portfolio transition limits: smooth_weights SHALL always replace NaN with 0 before anything else (even when smoothing is off, so NaN never leaks into the cost kernel). With method="cap" each ticker's per-bar change SHALL be clipped to +/-delta against the price-drifted previous position; with method="normalize" the whole delta vector SHALL be scaled so the maximum change is delta; delta=None SHALL pass through unchanged regardless of method (the method check never runs, so no error if method="cap" with delta=None); with delta set, method="off" passes through unchanged and any other method SHALL raise ValueError.

    Scenario: Cap smoothing¶

    • WHEN smoothing is active with method="cap" and delta=0.005
    • THEN no ticker's weight changes by more than 0.005 per bar relative to its drifted prior position

    Scenario: NaN handling with smoothing off¶

    • WHEN delta is None (smoothing off)
    • THEN the weights still pass through a NaN-to-zero normalization

    Requirement: Strategy combination¶

    The system SHALL combine per-strategy weight frames into one portfolio via combine_strategies with methods markowitz, risk_parity, or ew. A single-strategy run SHALL short-circuit to that strategy with a trivial allocation of 1.0. ew SHALL hold constant 1/n_strategies. The rolling methods SHALL estimate on daily-resampled strategy PnL over a 48*30-bar lookback, rebalance every 48 bars, hold the previous allocation between rebalances, and start from equal weight during the warm-up (never silently flattening to zero). Markowitz SHALL solve the Tobin tangency w* = V^-1 mu / (e^T V^-1 mu) with a 1e-12 ridge, enforce box constraints [min_strategy_weight, max_strategy_weight] by active-set water-filling, and SHALL fall back to equal weight when the solve fails (non-finite denominator, infeasible constraints, or a linear-algebra error). The combined portfolio SHALL be sum(w_name.fillna(0) * allocation_name) per name, with NaN weight cells logged as warnings.

    Scenario: Markowitz solver failure fallback¶

    • WHEN the tangency solve fails (e.g. singular covariance or infeasible box)
    • THEN the allocation for that window falls back to equal weight instead of aborting

    Scenario: Warm-up allocation¶

    • WHEN fewer than lookback bars of history are available
    • THEN allocations hold equal weight rather than zero, so the portfolio is not flattened during warm-up

    Requirement: Turnover diagnostics¶

    The system SHALL compute turnover from drifted positions: per_bar_turnover SHALL be sum(|w_t - w_{t-1} * price_change|) per bar (the "real trade" after price drift), and daily_turnover SHALL be the per-bar series resampled to daily sums.

    Scenario: Turnover of a held position¶

    • WHEN weights are unchanged but prices move
    • THEN per-bar turnover reflects only the drifted difference, not the full weight

    Requirement: Plotting surface¶

    The system SHALL expose AlphaPipeline.plot(kind, top_n) supporting kinds dashboard, pnl, drawdown, weights, turnover, allocations, and correlation, each returning a matplotlib Figure. Calling plot before run() SHALL raise RuntimeError; allocations on a single-strategy run SHALL raise ValueError; unknown kinds SHALL raise ValueError. The dashboard SHALL compose PnL, drawdown, turnover, and a weights heatmap, plus allocations when present. The correlation view SHALL show per-alpha PnL correlations as daily and 30-min heatmaps and requires the selected alpha set to equal the full ALPHA_REGISTRY: only then the pipeline runs every registered strategy (not just the chosen subset) to feed the panel, and the per-alpha PnL used there SHALL come from post-smoothing weights (_maybe_smooth). A single active alpha falls back to a top-N bar chart instead of a heatmap.

    Scenario: Plot before run¶

    • WHEN plot is called before run()
    • THEN it raises RuntimeError telling the caller to run first

    Scenario: Allocations plot on single strategy¶

    • WHEN plot("allocations") is called on a single-strategy run
    • THEN it raises ValueError because allocations are undefined
