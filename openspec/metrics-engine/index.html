    Metrics Engine

    Purpose¶

    Defines the real-time metrics engine of alpha_engine (metrics_engine/), a Python port of the Go pkg/metrics engine. It folds per-symbol tick streams (trades, liquidations, orderbook scalars, klines, mark price, funding) into 1-second aggregate slots, keeps a rolling ring of slots inside a fixed window (default 30 minutes), and emits one canonical 791-key metric row per aligned bar boundary. The engine serves two paths: the in-process LiveMetricsBridge (subscribes to binance_parser's live tick stream and serves rolling windows to the live trader, replacing the Go parquet handoff) and the offline replay path (tick_reader + tools/replay_metrics.py, which replays Hive-partitioned parquet ticks through the same engine). Every number in a row is a Python float (IEEE float64); the row never carries NaN or Inf.

    Requirements¶

    Requirement: Tick model and event adaptation¶

    The system SHALL model every engine input as a Tick dataclass (slots=True) with ts (int64 milliseconds), symbol (str), a TickKind, and ten optional typed payload fields defaulting to None (depth, agg_trade, mark_price, force, funding, open_int, ls_ratio, taker_ratio, kline, snapshot). TickKind SHALL be an IntEnum with the fixed ordinals UNKNOWN=0, DEPTH=1, AGG_TRADE=2, MARK_PRICE=3, FORCE_ORDER=4, FUNDING=5, OPEN_INT=6, LS_RATIO=7, TAKER_RATIO=8, KLINE=9, SNAPSHOT=10. Measurement fields SHALL be float64, while identity/timestamp fields stay int: Tick.ts, DepthUpdate.first_u/last_u/prev_u, Snapshot.last_update_id, AggTrade.agg_id/first_trade_id/last_trade_id, MarkPrice.next_funding_time_ms, Funding.funding_time_ms, Kline.open_time/close_time/trades are int; AggTrade.is_buyer_maker is bool; ForceOrder.side/status and Kline.interval are str; every other payload field (prices, quantities, rates) is float64.

    The adapter (tick_adapter.event_to_tick) SHALL convert binance_parser MarketEvent objects (float32, parquet-oriented) to float64 Ticks: aggtrades, markprice, forceorder, klines, booksnapshot, funding map to their kinds; every other event_type (including orderbook and trades) and any object without an event_type attribute SHALL map to None; a kline whose bar is not closed SHALL map to None (closed defaults to True when the attribute is absent); a force-order side outside the venue contract SHALL be normalized to SELL with a warning (never silently skewing liq-imbalance metrics). The adapter SHALL stamp each Tick.ts from the event kind's own timestamp field: open_time for klines, funding_time_ms for funding, and timestamp_ms for all other kinds. Side SHALL be normalized case-insensitively: is_buyer_maker is str(side).lower() == "sell" for agg trades, and the force-order side is upper-cased before the BUY/SELL check. Optional source attributes SHALL be defaulted rather than raising: last_filled_qty -> 0.0, cum_filled_qty -> 0.0, order_status -> "", taker_buy_base_vol/taker_buy_quote_vol -> 0.0, trades -> 0, mark_price (funding) -> 0.0, update_id (snapshot) -> 0, and a None next_funding_time_ms -> 0. The snapshot adapter SHALL default bids_price, bids_size, asks_price and asks_size to empty lists and SHALL pair them with zip, so mismatched price/size column lengths truncate to the shorter one instead of raising. Agg-trade, mark-price and force-order conversion SHALL read their required attributes directly (no defaulting), so a malformed event raises rather than being silently zero-filled.

    Scenario: Closed-kline filter¶

    • WHEN a kline event has closed=False
    • THEN the adapter returns no Tick, so running bars are never folded into the engine

    Scenario: Unknown force-order side¶

    • WHEN a force-order event carries a side other than BUY/SELL (case-insensitively)
    • THEN the adapter warns and classifies the event as SELL

    Scenario: Non-metric event¶

    • WHEN an OrderBookUpdate (event_type="orderbook"), a raw Trade (event_type="trades"), or an object with no event_type is passed to event_to_tick
    • THEN it returns None and the caller skips it

    Requirement: Per-symbol engine ingestion¶

    The system SHALL run one Engine per symbol (single-threaded, __slots__-based, no locks) constructed with window_ms (default 30*60*1000) and tick_ms (default 1000). Invalid values SHALL be clamped, never raised: window_ms <= 0 becomes 30*60*1000, tick_ms <= 0 becomes 1000, and a window_ms below tick_ms is raised to tick_ms. wall_clock_anchor SHALL default to False and is a public attribute the caller flips after construction (the live bridge sets True, the offline replay sets False). The Engine SHALL ignore Tick.symbol entirely: symbol is stored for identification only and no method filters on it, so fanning ticks out to the right engine is the caller's responsibility.

    push(tick) SHALL fold a tick into the current 1-second slot: ticks with ts <= 0 are ignored before anything else; the bucket is tick.ts // tick_ms; out-of-order ticks (earlier bucket) are folded into the current slot latest-wins without rolling back; a forward gap larger than _max_slot_jump (a fixed 3600 slots, independent of the ring capacity and of tick_ms) SHALL clear the ring and drop the in-flight slot; otherwise intermediate slots are closed and opened one by one to catch up. The giant-gap branch SHALL set the current bucket to bucket - 1 so the catch-up loop that follows runs exactly once, opening a single fresh slot at the tick's own bucket inside the same push call; it SHALL NOT touch _next_bar or the liquidation deque, so the stale bar boundary survives the gap (the caller's drain loop then emits every intervening bar over an empty ring) and pre-gap liquidations keep contributing to the shock series until horizon eviction removes them.

    The wall-clock re-anchor SHALL apply only where push finds no slot open on entry - the first push ever and the first push after a bar flush closed the in-flight slot. With wall_clock_anchor=True the newly opened slot SHALL be re-based on the wall clock (int(time.time()*1000) // tick_ms) so stale poller ticks cannot back-date bar alignment; the tick's own bucket is then recomputed from tick.ts, so a live tick behind the wall clock immediately takes the out-of-order path. Because the giant-gap branch reopens the slot within the same push, a gap discard SHALL NOT trigger a wall-clock re-anchor on the following push.

    Liquidations SHALL additionally feed a rolling LiqDeque of LiqEvent(ts, side, notional) - but only for in-order ticks: an out-of-order tick (older bucket) returns from push() before the deque feed, so its shock-notional contribution is silently absent from the rolling shock series (latest-wins fold still applies to the slot itself). Horizon eviction (evict_before(tick.ts - (window_ms + 10000)), dropping events with ts strictly below the cutoff) SHALL run on every in-order push regardless of tick kind; eviction SHALL drop only from the front of the push-ordered list, so the deque assumes ticks arrive roughly in time order. Digested book scalars installed via feed_book SHALL be stamped into the current slot on the next push (before the out-of-order early return, so even a late tick carries the stamp), skipping the copy when the BookScalars object is identical (identity comparison) to the one already stamped; callers MUST therefore hand feed_book a freshly built BookScalars per update (compute_book_scalars returns a new dataclass per call) - mutating and re-feeding the same object would be skipped. _open_slot SHALL re-stamp the latest book into every newly opened slot, so the book state persists across 1-second slots until a new book arrives. The Engine SHALL never reconstruct a book itself: DEPTH ticks are ignored and SNAPSHOT ticks only advance slot time; books enter only through feed_book.

    Scenario: Out-of-order tick¶

    • WHEN a tick's bucket is older than the current slot
    • THEN it is folded into the current slot (latest-wins), no slot is rolled back, and the early return means a liquidation in that tick does not feed the LiqDeque and no horizon eviction runs

    Scenario: Giant forward gap¶

    • WHEN a tick arrives more than 3600 slots ahead of the current slot
    • THEN the ring is cleared and the in-flight slot dropped, because every pre-gap aggregate is out of window, and a single new slot is opened at the tick's own bucket in the same call

    Scenario: Bar boundary survives a gap¶

    • WHEN the ring is cleared by a giant forward gap
    • THEN _next_bar keeps its original anchor, so the next drain loop emits one bar per missed boundary against the now-empty ring before catching up

    Scenario: Wall-clock re-anchor scope¶

    • WHEN wall_clock_anchor=True and a giant forward gap discards the in-flight slot
    • THEN the slot is reopened at the tick's own bucket inside the same push, so the next push sees an open slot and no wall-clock re-anchor happens - only the first push ever and the first push after a bar flush re-anchor

    Scenario: Clamped construction¶

    • WHEN an Engine is built with window_ms=0 and tick_ms=0
    • THEN it runs with window_ms=1800000, tick_ms=1000 and a ring capacity of 1800 instead of raising

    Scenario: Book persists across slots¶

    • WHEN a slot closes and a new one opens with no new feed_book call in between
    • THEN the new slot is stamped with the same latest BookScalars, so have_book stays true for every slot after the first book arrives

    Requirement: Bar emission¶

    The system SHALL emit metric rows at window-aligned bar boundaries: emit_if_ready(now_ms) SHALL return (row, True) at most once per call when now_ms has reached or crossed _next_bar, flushing the in-flight slot first if it starts before the boundary, and ({}, False) otherwise (including while _next_bar == 0, i.e. before the first push); in live mode now_ms SHALL be replaced by the wall clock. The first bar boundary SHALL anchor to the next whole-window edge strictly above the first slot's start ((start_ms // window_ms + 1) * window_ms) and SHALL then advance by exactly window_ms per emitted bar, keeping close timestamps aligned to absolute window edges for the lifetime of the engine (a ring clear does not re-anchor it). The caller SHALL loop until ok == False to drain catch-up bars; catch-up bars re-read the same ring content, so only _bar_close_ts and the liq-shock family differ between them. Every emitted row SHALL be sanitized so every metric value is finite (NaN and Inf become 0.0), and SHALL then carry the extra key _bar_close_ts (bar close timestamp in milliseconds, added after sanitization and not one of the 791 metric keys), so an emitted row holds exactly 792 entries. An in-flight slot whose start_ms is at or after the boundary SHALL be left open and therefore excluded from the bar. _next_bar SHALL advance by window_ms on every emission whether or not the ring held any slot, so an empty window still consumes its boundary.

    Scenario: Drain of catch-up bars¶

    • WHEN the caller keeps calling emit_if_ready after a gap
    • THEN each call returns at most one row and the loop drains every missed boundary before returning ({}, False)

    Scenario: Sanitized row¶

    • WHEN an emitted row contains NaN or Inf values
    • THEN they are replaced with 0.0 before the row is handed to the caller

    Scenario: No tick yet¶

    • WHEN emit_if_ready is called before any tick has been pushed
    • THEN it returns ({}, False) because _next_bar is still 0

    Requirement: One-second aggregate slots¶

    The system SHALL fold all ticks arriving in the same second into a single Aggregate slot, an 80-field __slots__ object whose reset(start_ms) assigns the integer 0 to every one of the 80 slots by name (so float fields and the four boolean flags has_trade, have_book, have_kline, have_mark_price/have_funding all start as int 0, matching Go zero-value semantics) and then sets start_ms and end_ms = start_ms + 1000 (a hardcoded 1000 ms, not tick_ms, so a non-default tick_ms does NOT change end_ms - start_ms).

    add_tick SHALL dispatch by kind and ignore every other kind (UNKNOWN, DEPTH, OPEN_INT, LS_RATIO, TAKER_RATIO, SNAPSHOT) and every tick whose payload is None: - AGG_TRADE maintains OHLC, trade/buy/sell counts, volumes, quote volumes, per-side and overall max trade size, first/last timestamps, and the sums used for Herfindahl (sum_square_vol) and Kyle's lambda (sum_abs_dp_x_vol); it also accumulates sum_abs_dp and tracks prev_px, and the buyer/seller split is driven by is_buyer_maker (maker-buy counts as a SELL aggression). Trades with qty <= 0 SHALL be dropped. The |dp| terms SHALL be measured against the previous trade in the same slot only, so the first trade of a slot contributes no dp. - FORCE_ORDER maintains per-side liquidation counts, size sums, notional sums, price sums and average-price sums, plus per-side size/notional/price maxima, with the effective size resolved through the shared resolve_liquidation_size fallback chain orig_qty -> last_fill_qty -> cum_fill_qty (each step taken when the previous is <= 0); a resolved size <= 0 logs a warning and is skipped; a side that is neither exactly BUY nor exactly SELL SHALL contribute to nothing, silently. Per-event averages are NOT stored in the slot - only the sums, from which the liquidation group derives means. - KLINE keeps the last-standing kline (open/high/low/close/volume/quote volume) and sets have_kline. - MARK_PRICE keeps the latest mark, index, predicted funding rate and next funding time and sets have_mark_price; FUNDING keeps the latest realized funding rate and sets have_funding.

    set_book SHALL copy the digested BookScalars (including the three health counters verbatim) and derive spread_abs = best_ask_px - best_bid_px, mid = 0.5*(best_bid_px + best_ask_px), per-cone imbalance (bid_size - ask_size)/(bid_size + ask_size) only when that cone's size sum is > 0, and microprice = (best_bid_px*best_ask_size + best_ask_px*best_bid_size)/(best_bid_size + best_ask_size) only when the best sizes sum is > 0.

    set_book SHALL be last-write-wins for every unguarded field, but the three guarded fields (imbalance_5pct, imbalance_25pct, microprice) are written only inside their > 0 guard and are never reset, so a later set_book in the same slot whose denominator is 0 leaves the EARLIER book's value standing; they are 0.0 only when no set_book in that slot ever passed the guard. have_book SHALL likewise only ever be set to true, never cleared, within a slot's lifetime - reset is the only thing that clears it.

    Scenario: Liquidation size fallback¶

    • WHEN a force order reports orig_qty <= 0 (zero or negative; negative sizes also enter the chain)
    • THEN the effective size is taken from last_fill_qty when that is also <= 0, then cum_fill_qty, before any liquidation metric is updated

    Scenario: Empty force order¶

    • WHEN the resolved liquidation size is zero or negative in the aggregate path
    • THEN a warning is logged and the event contributes nothing to the aggregate metrics

    Scenario: Non-positive force order in the engine path¶

    • WHEN the engine's liq-shock path resolves a zero or negative liquidation size (e.g. from a negative cum_fill_qty)
    • THEN the shock-notional price * size is still pushed to the rolling shock series - a negative size contributes negative notional (the aggregate skip-with-warning guard does not exist on the engine's live path)

    Scenario: Zero-quantity trade¶

    • WHEN an AGG_TRADE tick carries qty <= 0 or a missing agg_trade payload
    • THEN the slot is left untouched, so trades_count and OHLC never move on it

    Scenario: Sticky guarded book fields¶

    • WHEN a slot receives a second set_book whose 5% size sum is 0 after a first one that was positive
    • THEN imbalance_5pct keeps the first book's value instead of falling back to 0.0, because the guarded assignments have no else-branch

    Requirement: Book scalars digest¶

    The system SHALL digest an order book into BookScalars, a 19-field float dataclass: best_bid_px, best_ask_px, best_bid_size, best_ask_size, the 5% and 25% per-side cost/size/levels triples (12 fields), and the three health counters updates_count, seq_gaps, resync_count. compute_book_scalars(order_book) SHALL accept any object exposing best_bid(), best_ask() and full() (the parser's OrderBook, or BookReplay's _SimpleBook which sorts bids descending and asks ascending), and SHALL return None when either best quote is missing or either side of full() is empty. Cones SHALL be centered on the mid: bid_5pct_cut = mid * (1 - 0.05), bid_25pct_cut = mid * (1 - 0.25), ask_5pct_cut = mid * (1 + 0.05), ask_25pct_cut = mid * (1 + 0.25). Each side SHALL be walked best-first, accumulating price * size cost, size and a level count into the 5% cone while the price is inside the 5% cut and into the 25% cone while it is inside the 25% cut, and SHALL break out of the walk at the first level outside the 25% cut (the book is sorted, so everything beyond is further away). compute_book_scalars SHALL leave the three health counters at their 0.0 default - only the caller (BookReplay) fills them.

    Scenario: Empty book¶

    • WHEN the book has no bids or no asks
    • THEN compute_book_scalars returns None and nothing is fed to the engine

    Scenario: Cone membership¶

    • WHEN a bid level sits between the 25% and the 5% cut
    • THEN it contributes to bid_25pct_cost/size/levels only, and the walk continues to the next level

    Requirement: Snapshot-driven book replay¶

    The system SHALL reconstruct the book for replay with BookReplay(book_tick_ms=60_000): non-SNAPSHOT ticks and ticks with no snapshot payload SHALL be ignored, and every snapshot SHALL replace the whole book (diffs are never replayed) while incrementing both updates_count and resync_count by one; seq_gaps SHALL stay 0 on this path. Scalars SHALL be emitted at most once per book_tick_ms bucket: the bucket start ts - (ts % book_tick_ms) must be strictly greater than the last fed bucket start (which begins at 0), and the marker SHALL advance even when compute_book_scalars returns None, so an empty book consumes its bucket. The two counters SHALL be incremented on EVERY snapshot, including snapshots whose bucket emits nothing, so the values fed to the engine are cumulative snapshot counts since construction rather than per-bucket deltas. One BookReplay instance SHALL serve exactly one symbol: the book state and the bucket marker are single-valued and the tick's symbol is never used as a key.

    Scenario: Replay cadence¶

    • WHEN multiple snapshots arrive within one minute
    • THEN BookReplay emits scalars once per minute bucket (strictly-bucket advance: emission happens only when the current bucket is greater than the last fed bucket), with every snapshot counted as a resync

    Scenario: First-bucket suppression¶

    • WHEN a snapshot arrives with a timestamp inside the first book_tick_ms bucket (ts < 60 s, so its bucket start is 0, and the last-fed bucket also starts at 0)
    • THEN no scalars are emitted for that first bucket - the strictly-greater comparison suppresses it, so the first snapshot's book is never fed to the engine

    Scenario: Replay health counters¶

    • WHEN the engine consumes replayed book scalars
    • THEN book_updates_count equals book_resync_count (one per snapshot seen so far) and book_seq_gaps is always 0

    Requirement: Rolling ring buffer¶

    The system SHALL keep the window of 1-second slots in a fixed-capacity ring (Ring, capacity window_ms // tick_ms, default 1800 slots for 30 min at 1 s; non-positive capacity coerced to 1). The ring SHALL pre-allocate capacity Aggregate objects at construction and append SHALL copy the source slot field-by-field over Aggregate.__slots__ into the pre-allocated item at the head, so the ring never stores a reference to the engine's in-flight slot. Append SHALL be O(1) and SHALL overwrite the oldest slot when full (no other eviction); clear() SHALL reset head and size only - it does NOT zero the pre-allocated Aggregate objects, whose stale contents simply become unreachable until the next append overwrites them; snapshot() SHALL return shallow copies (copy.copy) of the live slots in chronological order (oldest first) and an empty list when the ring is empty. cap and size SHALL be exposed as read-only properties.

    Scenario: Ring overwrite¶

    • WHEN more slots are appended than the ring capacity
    • THEN the oldest slot is overwritten, so the window holds exactly the last capacity slots

    Scenario: Snapshot isolation¶

    • WHEN a consumer mutates a slot returned by snapshot()
    • THEN the ring's own buffer is unaffected, because each returned slot is a shallow copy

    Requirement: Canonical 791-key row¶

    The system SHALL emit exactly 791 canonical metric keys per bar plus _bar_close_ts, generated from the fixed layout in keys.py: 33 trade keys, 721 orderbook keys (ob__{5pct|25pct}__{bid|ask}__{11 bases}__{7 suffixes} = 308, ob__cross__{11 d_ bases}__{7 suffixes} = 77, ob__minor__{43 bases}__{7 suffixes} = 301, ob__{bid|ask}__best_size__{7 suffixes} = 14, ob__liq_shock_{bid|ask|mid}__{7 suffixes} = 21), 24 liquidation keys, 12 kline/funding/mark keys, and 1 spread key. Suffixes SHALL be exactly mean, median, sum, q95, min, max, skew. The 11 cone bases SHALL be cost, size, vwap, levels_count, weighted_distance, imbalance, slope, microprice, depth_ratio, log_return_cost, log_return_vwap, and the 11 cross bases the same list prefixed with d_. The key list SHALL be sorted (canonical order matching Go sort.Strings) and its count, uniqueness and sortedness SHALL be asserted at import time against the module constants N_TRADES=33, N_ORDERBOOK=721, N_LIQUIDATIONS=24, N_KLINES_ETC=12, N_SPREAD=1, N_TOTAL=791.

    empty_row() SHALL pre-fill all 791 keys with 0.0, so every metric a group cannot compute (empty window, zero denominator, absent data kind) is served as 0.0 - the row never contains NaN, Inf or a missing key. Rows SHALL be produced by compute_all in the fixed order trades -> orderbook -> spread -> liquidations -> klines/funding/mark; each group is a pure function that reads only the ring snapshot, never mutates it, and writes a disjoint subset of the key space, so no group in fact consumes another group's output (the ordering mirrors Go's buildRow sequence; the package docstring's claim that spread and klines depend on compute_orderbook is stale - both read Aggregate fields written by set_book, not row entries, and reordering the calls would not change any value). keys.py SHALL also expose the building blocks by name (SUFFIXES, ORDERBOOK_OFFSETS, ORDERBOOK_SIDES, ORDERBOOK_BASES, ORDERBOOK_CROSS_BASES, ORDERBOOK_MINOR_BASES, TRADE_KEYS, LIQUIDATION_KEYS, KLINE_FUNDING_MARK_KEYS, SPREAD_KEYS), and the orderbook group SHALL import those lists rather than re-declaring them, so the row schema has exactly one source of truth.

    Scenario: Row schema invariant¶

    • WHEN a row is built
    • THEN it contains exactly 791 metric keys plus _bar_close_ts, every key finite, and the key order is the canonical sorted layout

    Scenario: Missing data kind¶

    • WHEN a symbol has no funding, no liquidations and no book in the window
    • THEN the corresponding keys are 0.0 rather than NaN or absent

    Requirement: Suffix statistics¶

    The system SHALL derive every suffixed key from seven_stats(xs), which SHALL return mean, median, sum, q95, min, max, skew for a series: min/max from the sorted copy; median linearly interpolated as the mean of the two middle values for even n and the middle value for odd n; q95 as the linearly interpolated 95th percentile over pos = 0.95*(n-1) (the single value when n == 1); sum and mean = sum/n; and skew as Fisher-Pearson g1 m3 / m2**1.5 with m2, m3 the biased central moments, returning 0.0 unless n > 1 and m2 > 0. seven_stats SHALL return all-zero stats for an empty series and SHALL operate on a sorted COPY, never mutating the caller's vector (the same holds for the trade group's _quantile helper). write_suffixed(out, prefix, xs) SHALL write the seven prefix__<suffix> keys, and SHALL write nothing at all for an empty series, leaving those keys at the 0.0 default from empty_row(). write_suffixed SHALL live in the orderbook group module and be re-used by the engine for the liq-shock keys, so all 791 suffixed keys go through one implementation.

    Scenario: Degenerate series¶

    • WHEN a suffixed series holds a single sample or a constant series
    • THEN skew is 0.0 while mean, median, q95, min and max all equal that value

    Scenario: Empty series¶

    • WHEN a book-derived series is empty because no slot in the window carried a book
    • THEN write_suffixed writes nothing and all seven keys stay 0.0

    Requirement: Liquidation shock series¶

    The ob__liq_shock_{bid|ask|mid} keys SHALL be the only metric keys written by the engine itself rather than by a group. At each bar the engine SHALL compute the shock series with LiqDeque.rolling_shock(bar_start, bar_close, step_ms=1000, window_ms=10000): a 10-second window stepped in 1-second increments across the whole bar [bar_close_ms - window_ms, bar_close_ms] with BOTH endpoints inclusive (1801 samples for a 30-minute bar at 1-second steps), mapping BUY notional to the bid leg, SELL notional to the ask leg, and their sum to the mid leg, via a two-pointer scan (O(n_steps + n_events)) in which each step sums the events with t - 10000 < ts <= t and sides other than exactly BUY/SELL contribute nothing. The shock notional SHALL be price * resolve_liquidation_size(force) (the same orig_qty -> last_fill_qty -> cum_fill_qty chain as the aggregate path). rolling_shock SHALL return three empty vectors when step_ms <= 0 or bar_close < bar_start; otherwise it always returns non-empty vectors, so the 21 liq-shock keys are written (as zeros) even when no liquidation is in the deque. After the bar the engine SHALL trim the deque with evict_before(bar_close_ms - (window_ms + 10000)).

    Scenario: Bar with no liquidations¶

    • WHEN a bar closes with an empty liq deque
    • THEN rolling_shock returns three all-zero vectors of 1801 samples and every ob__liq_shock_* key is written as 0.0

    Scenario: Shock window membership¶

    • WHEN a liquidation lands exactly 10000 ms before a sample point t
    • THEN it has already been evicted from that sample (the window is (t - 10000, t])

    Requirement: Trade group computations¶

    The trade group (33 keys) SHALL accumulate over the ring snapshot: ticks counted for EVERY slot in the window (including slots with no trades, counted before the no-trade skip, so it measures window occupancy in seconds rather than trades); counts, volumes and quote volumes summed over trading slots only; trade_size_max/buy_size_max/sell_size_max as maxima of the per-slot maxima; per-side volume quantiles buy_volume_q50/q95/q99 and their sell mirrors computed over the slots with strictly positive volume on that side; OHLC taken as first-slot open, max of slot highs, min of slot lows, last-slot close; first_ts/last_ts as floats of the first and last trade timestamps. vwap = quote_volume/volume, buy_vwap, sell_vwap SHALL be written only when the matching volume is > 0; herfindahl = sum_square_vol / volume^2 only when volume > 0; kyle_lambda = sum_abs_dp_x_vol / sum_square_vol only when sum_square_vol > 0 (the slot's sum_abs_dp accumulator is not consumed by any group); imbalance = (buy_volume - sell_volume)/(buy_volume + sell_volume) only when that sum is > 0; signed_volume and signed_quote_volume SHALL be written unconditionally. OHLC and first_ts/last_ts SHALL stay 0.0 when the window holds no trade at all. The quantile helper SHALL return 0.0 for an empty series, the minimum for q <= 0, the maximum for q >= 1, and a linear interpolation over the sorted copy otherwise.

    Scenario: Per-side volume quantiles¶

    • WHEN computing trade metrics
    • THEN buy_volume_q95 is the 95th percentile over slots with positive buy volume only

    Scenario: Tick count¶

    • WHEN a 30-minute window holds 1800 slots of which only 12 carried trades
    • THEN ticks is 1800, not 12

    Scenario: Silent window¶

    • WHEN no slot in the window carried a trade
    • THEN open, high, low, close, first_ts, last_ts, vwap, herfindahl and kyle_lambda are all 0.0

    Requirement: Orderbook group computations¶

    The orderbook group SHALL fill 700 of the 721 orderbook keys (the remaining 21 liq-shock keys come from the engine) and SHALL return immediately on an empty ring snapshot. It SHALL skip every slot without have_book, so all its vectors are indexed by book-bearing slots only. Per book-bearing slot it SHALL derive, for each of the four (offset, side) cones, vwap = cost/size (0.0 when size <= 0), weighted_distance = |vwap - mid|, slope = size/weighted_distance (0.0 when the distance is not > 0), depth_ratio = own size / opposite size (0.0 when the opposite side is not > 0), log_return_cost = log(cost/prev_cost) and log_return_vwap = log(vwap / prev_vwap) where prev_vwap is reconstructed as prev_cost / _safe_one(prev_size) and _safe_one(x) returns 1.0 when x == 0 and x otherwise (so a previous slot with zero size divides by 1 instead of raising). Both log returns SHALL be 0.0 unless the current value and the reconstructed previous value are both strictly positive, which is what makes the first book-bearing slot's log returns 0.0 (the prev_* state starts at 0.0). The per-cone imbalance base SHALL be the slot's imbalance_5pct for both 5% cones and imbalance_25pct for both 25% cones, and the per-cone microprice base SHALL be the same slot microprice for all four cones. ob__bid__best_size and ob__ask__best_size SHALL be fed from the per-slot best_bid_size / best_ask_size.

    Cross-snapshot diffs SHALL be computed from the second book-bearing slot onwards (so their vectors are one sample shorter) against the immediately previous book-bearing slot, using the 5% cone: d_cost/d_size on the bid+ask sums, d_vwap and d_slope on the mean of the two side values, d_levels_count and d_weighted_distance on the bid+ask sums, d_imbalance on imbalance_5pct, d_microprice, d_depth_ratio on the bid depth ratio only, and the two d_log_return_* on the same log-return guard.

    The 43 minor bases SHALL be: the cumsize ladder (bid_cumsize_5 = bid_5pct_size, bid_cumsize_25 = bid_25pct_size, the extrapolated bid_cumsize_10 = 1.5 * bid_5pct_size and bid_cumsize_50 = 1.25 * bid_25pct_size, plus the ask mirrors); *_cumcost_5/25 from the cone costs; book_curvature_{bid,ask} = (size_25 - size_5)/size_25 (0.0 when size_25 == 0); slope_ratio_{bid,ask} = slope_5/slope_25 (0.0 when the denominator is 0); spread_abs and spread_ticks both equal to the raw spread_abs (no tick size is available); spread_bps = spread/mid*1e4 (0.0 when mid <= 0); midprice and midprice_log_return against the previous book-bearing slot's mid; imbalance_top1 from the best sizes, imbalance_top5 = imbalance_5pct, imbalance_top10 = imbalance_5pct * 0.9, imbalance_top25 = imbalance_25pct; book_age_ms = end_ms - start_ms, i.e. a constant 1000 for every slot; the three book-health counters copied from the slot; levels_total_{bid,ask} from the 25% level counts and levels_above_5pct = ask_25pct_levels - ask_5pct_levels, levels_below_5pct = bid_25pct_levels - bid_5pct_levels; notional_top1_{bid,ask} = best price * best size and notional_top5_{bid,ask} = the 5% cone cost; pressure_{bid,ask} = size_5 * max(0, 1 - weighted_distance/(0.05*mid)) (weight 0.0 when mid <= 0), pressure_signed = bid_5pct_size - ask_5pct_size, pressure_log = log(1 + bid_5pct_size) - log(1 + ask_5pct_size) (0.0 when both sizes are 0); and resilience_{bid,ask} equal to the 5% depth ratios.

    Scenario: Extrapolated cumulative sizes¶

    • WHEN computing minor orderbook bases
    • THEN bid_cumsize_10 equals 1.5 * bid_5pct_size and bid_cumsize_50 equals 1.25 * bid_25pct_size

    Scenario: Book-less slots¶

    • WHEN only 30 of the 1800 slots in the window carry a book
    • THEN every orderbook vector holds 30 samples (29 for the cross-diff family) and the suffixed stats are computed over those samples only

    Scenario: Constant book age¶

    • WHEN ob__minor__book_age_ms__mean is read
    • THEN it is 1000, because the base is the slot duration and not a real staleness measure

    Requirement: Liquidation, kline, funding, mark and spread group computations¶

    The liquidation group (24 keys) SHALL accumulate each side independently and only from slots whose count on that side is > 0: counts, size sums, notional sums, price sums and average-price sums are summed; liq_*_size_max, liq_*_notional_max and liq_*_price_max are maxima of the per-slot maxima. liq_*_size_mean, liq_*_notional_mean, liq_*_price_mean and liq_*_avg_price_mean SHALL be written only when that side's count is > 0 (per-event means, dividing by the event count, not by the slot count). liq_count, liq_size_sum and liq_notional_sum SHALL be the two-sided totals, and liq_imbalance = (buy_size_sum - sell_size_sum)/(buy_size_sum + sell_size_sum) only when the total is > 0.

    The kline/funding/mark group (12 keys) SHALL scan the window once: open_price from the first kline-bearing slot, high_price/low_price as the extremes of the per-slot kline highs/lows, close_price from the last kline-bearing slot, and kline_volume/kline_volume_usd cumulative across kline-bearing slots - all six written only when at least one kline was seen. mark_price, index_price, predicted_funding and next_funding_time_ms SHALL be the latest mark-price observation and are written only when at least one was seen. last_price SHALL be the trade close of the last slot with a trade (a trade field, not the kline close) and realized_funding SHALL be the latest observed funding rate; both are written unconditionally and are 0.0 when never observed.

    compute_spread SHALL write the single spread_max key as the maximum spread_abs across book-bearing slots (0.0 when none carries a book).

    Scenario: Kline bar aggregation¶

    • WHEN computing kline/funding/mark metrics
    • THEN open is the first kline's open, high/low are the extremes, close is the last kline's close, and volume / quote volume are cumulative across slots

    Scenario: Last price from trades¶

    • WHEN the window carries trades but no klines
    • THEN last_price is the last trade price while close_price stays 0.0

    Scenario: One-sided liquidations¶

    • WHEN only SELL liquidations occurred in the window
    • THEN every liq_buy_* key is 0.0, the liq_sell_*_mean keys divide by the sell event count, and liq_imbalance is -1.0

    Requirement: Historical tick reading¶

    The system SHALL read raw ticks from the binance_parser Hive-partitioned parquet layout {data_root}/market={spot|usdm}/type={kind}/dt=YYYY-MM-DD/symbol={SYM}/part-*.parquet via TickReader(data_root, market="usdm"), streaming kind-by-kind while holding at most one parquet file per kind in memory. Exactly five kinds SHALL be read: aggtrades/aggTrades, klines, markprice, funding, booksnapshot; the reader has no converter for forceorder or depth diffs, so a replayed range produces NO FORCE_ORDER tick and every liquidation key and ob__liq_shock_* key in replayed output is 0.0. Day directories SHALL be filtered by overlap at day granularity (day_end < since or day > until is skipped), a dt= directory whose date cannot be parsed SHALL be skipped with a warning, and files SHALL be located by lexicographic path order (relying on dt=YYYY-MM-DD / part-HHMMSS naming) with an extra per-file sort by ts for safety. Kind names aggtrades / aggTrades SHALL be probed as one logical kind and deduplicated through a set[Path] of the globbed paths (plain Path equality, NOT Path.resolve()), which collapses the two spellings on Windows because PureWindowsPath compares case-insensitively; both spellings SHALL then be converted under the first name (aggtrades), since they share a schema. An empty parquet file SHALL be skipped, and _df_to_ticks SHALL return an empty list for any kind it has no converter for. The merged stream (read_ticks_stream) SHALL be a heapq.merge of the per-kind streams keyed on ts, so it is globally ordered by timestamp; read_ticks SHALL materialise the same stream as a list. The per-kind list APIs (read_aggtrades, read_klines, read_markprice, read_funding, read_booksnapshots) SHALL remain available and each SHALL sort its own output by ts; only read_aggtrades goes through the dedup path, the other four glob a single kind directory.

    The vectorized converters SHALL map parquet columns to Tick payloads, with Tick.ts taken from timestamp_ms except for klines (open_time) and funding (funding_time_ms), and with optional columns defaulted: side absent -> the is_buyer_maker column, otherwise is_buyer_maker = (side == "sell"); funding mark_price absent or NaN -> 0.0. Book snapshots SHALL be converted row-by-row from the parallel bids_price/bids_size/asks_price/asks_size list columns plus update_id.

    Scenario: Chronological merge¶

    • WHEN read_ticks_stream consumes all five kinds over a range
    • THEN the emitted Ticks are globally sorted by ts, even when kinds interleave across files

    Scenario: Case-insensitive kind collision¶

    • WHEN both aggtrades and aggTrades spellings resolve to the same directory on a case-insensitive filesystem
    • THEN the set[Path] dedup collapses them and the reader does not double-read

    Scenario: No liquidations offline¶

    • WHEN a range is replayed from raw parquet
    • THEN the 24 liquidation keys and the 21 liq-shock keys are all 0.0, because the reader emits no FORCE_ORDER ticks

    Requirement: Offline replay driver¶

    The system SHALL provide tools/replay_metrics.py as the offline batch driver: run_replay(data_root, output_root, symbols, since, until, market="usdm", window_ms=30*60*1000, tick_ms=1000, book_tick_ms=60_000), with the same defaults exposed on the CLI (--market, --window-ms, --tick-ms, --book-tick-ms) and --from/--to interpreted as inclusive UTC dates (until becomes end-of-day, +1 day - 1 ms). Per symbol it SHALL build one Engine with wall_clock_anchor=False (so bar boundaries follow tick time, never the wall clock) and one BookReplay, hand EVERY streamed tick to book_replay.handle_tick(tick, engine.feed_book) (the replay itself ignores non-snapshots) before engine.push(tick), and then drain emit_if_ready(tick.ts) in a loop so a multi-window gap cannot drop catch-up bars. After the stream ends the driver SHALL drain once bounded by the last tick timestamp and once bounded by the first window boundary after it, so the trailing partial window is emitted exactly once and no zero-filled bars are produced past the data.

    Bars SHALL be written as {output_root}/market={market}/type=metrics/dt=YYYY-MM-DD/symbol={SYM}/part-{first_bar_close_ms}.parquet, batched per bar-close day (a single drain may span midnight), zstd-compressed, with columns ts (int64, the bar close), symbol (string) and keys (map<string, double>) holding the 791 metric keys sorted by name with the transport field _bar_close_ts stripped out. Bars SHALL be buffered per symbol and flushed when the TICK day changes (and once more after the final drain), while _flush_bars regroups the buffer by BAR-CLOSE day; the file name SHALL be part-{ts} where ts is the first buffered bar close of that day group, so two flushes touching the same day produce two files unless their first bar close collides. The driver SHALL print per-day progress, and SHALL exit with status 1 and an ERROR line when zero bars were written across all symbols.

    Scenario: Trailing partial window¶

    • WHEN the last tick of a range lands mid-window
    • THEN the driver drains to the first boundary after that tick so the final bar is emitted, and stops there instead of draining to wall-clock now

    Scenario: Persisted schema¶

    • WHEN a metrics parquet file is written
    • THEN it has ts, symbol and a sorted keys map of 791 float64 entries, and _bar_close_ts appears only as the ts column

    Requirement: Live metrics bridge¶

    The system SHALL deliver live metrics in-process via LiveMetricsBridge(symbols, market="usdm", lookback_days=30, window_ms=30*60*1000, tick_ms=1000, book_tick_ms=60_000): one Engine per symbol (all wall_clock_anchor=True), subscribed to binance_parser's live tick stream, with ticks for symbols outside the constructor list dropped. The two ingestion paths (on_tick for direct tick pushes and consume_bus for the async bus consumer) SHALL be mutually exclusive - a tick pushed while the bus consumer is active SHALL be error-logged and dropped, and a second consume_bus SHALL raise RuntimeError; the active flag SHALL be released in a finally block so a WS reconnect can re-subscribe. consume_bus SHALL convert events with the adapter, skip unconvertible events and unknown symbols, feed SNAPSHOT events through a per-symbol BookReplay (whose callback binds the symbol eagerly and routes to on_book_scalars, which caches the latest scalars per symbol and calls Engine.feed_book) and then push the same tick into the engine, and drain rows via emit_if_ready into a per-symbol deque. Both paths SHALL build rows OUTSIDE the bar lock and take the lock only to publish finished bars; the engines themselves are single-threaded per symbol.

    Bars SHALL be stored as (bar_close_ms, row) pairs and evicted when older than lookback_days (default 30) measured from the WALL CLOCK at store time, and eviction only runs when new bars arrive. exchange_data(until_ts, lookback_days=None) SHALL serve a rolling window as a dict-like metrics container over a UTC pd.date_range(since, until_ts) index whose frequency is window_ms // 60000 minutes (30min by default), exposed under BOTH the binance and binance-f exchange keys as the SAME container object. A lookback_days argument of 0 SHALL fall back to the constructor default (the code uses lookback_days or self.lookback_days). Frames SHALL be built per metric by scanning bars in [since_ms, until_ts_ms], dropping NaN values, keeping the last bar per timestamp, and reindexing to the served index (missing timestamps become NaN); a symbol with no in-window value for that key SHALL get an all-NaN column of the served index; price-like frames SHALL then have 0.0 replaced by NaN and be forward-filled; per-key frames SHALL be cached under the REQUESTED name (so zero frames and the funding frame are cached too). latest_metric_ts SHALL return the newest bar close across symbols as a UTC timestamp, or None.

    The bridge SHALL also expose the GoExchangeData-compatible introspection surface the trader relies on: has_key(go_key), which is True only when some bar in the served window holds a value that is present, non-zero AND non-NaN (so a genuinely zero metric reads as absent) and which probes RAW row keys without passing them through go_name; has_kinds/missing_kinds for kind-gating against the _KIND_PROBES table - trades -> (vwap, buy_volume_q95), klines -> (close, quote_volume), markprice -> (close,), orderbook -> (ob__25pct__bid__cost__mean,), go_metrics -> (ob__minor__spread_bps__mean, vwap) - where ALL probes of a kind must pass, an unknown kind name is always reported missing, and the exchange argument is accepted but ignored; __contains__, which is False only for zero-served metrics; and get, which returns its default only on KeyError (in practice unreachable, because go_name passes unknown names through and __getitem__ then serves an all-NaN frame).

    warm_start_from_parquet(root) SHALL load {root}/market={market}/type=metrics/symbol={SYM}/*.parquet (columns ts and keys only, 8 worker threads), keep only rows with ts >= now - lookback_days, re-add _bar_close_ts to each row, sort per symbol, and replace that symbol's deque wholesale - a symbol that loaded no row keeps whatever deque it already had. The glob SHALL have NO dt= partition level, so it matches a flat type=metrics/symbol=<SYM>/ layout and does NOT match the type=metrics/dt=YYYY-MM-DD/symbol=<SYM>/ layout written by tools/replay_metrics.py; a warm start pointed at replay output therefore loads 0 bars and only logs the zero-bar warning. It SHALL skip unreadable files with a warning, raise FileNotFoundError only when the type=metrics directory is missing, log a warning when the total is 0, and return the number of bars loaded.

    Scenario: Ingestion mutual exclusion¶

    • WHEN a tick arrives through on_tick while consume_bus is active
    • THEN the tick is logged as an error and dropped, so engines are never double-fed

    Scenario: Rolling window eviction¶

    • WHEN a finished bar is older than lookback_days relative to the current wall clock
    • THEN it is removed from the served deque on the next store

    Scenario: Zero reads as absent¶

    • WHEN every bar in the window carries ob__25pct__bid__cost__mean = 0.0
    • THEN has_key reports False and missing_kinds reports orderbook as missing

    Scenario: Warm start replaces deque¶

    • WHEN warm_start_from_parquet loads at least one bar for a symbol
    • THEN the loaded bars replace that symbol's deque entirely rather than merging with live bars

    Scenario: Warm start against replay output¶

    • WHEN warm_start_from_parquet is pointed at a root written by tools/replay_metrics.py
    • THEN the symbol={SYM}/*.parquet glob finds nothing under the dt=-partitioned layout, 0 bars are returned and a warning is logged instead of an exception

    Requirement: Metric-name resolution¶

    The system SHALL resolve backtest metric names to live 791-key names through keys.go_name(metric, market="spot"), which returns (go_key, price_like): predicted_funding is the only name in _ZERO_METRICS and SHALL resolve to (None, False) so the bridge serves a zero frame; price-like aliases (close_price -> close, open_price -> open, high_price -> high, low_price -> low, last_price, vwap) SHALL return price_like=True; mark_price/index_price SHALL alias to close ONLY on spot, and SHALL pass through unchanged (still price-like) on any other market, because derivatives carry a genuine mark and index price. Flow aliases SHALL map volume -> volume (an explicit identity entry that classifies volume as NOT price-like, so it is never zero-to-NaN forward-filled), volume_usd -> quote_volume, buy_cost -> buy_quote_volume, sell_cost -> sell_quote_volume, and every {buy,sell}_cost_0.XX, {buy,sell}_cost_quantile_0.XX and {buy,sell}_volume_quantile_0.XX_usd spelling onto {buy,sell}_volume_q{50,95,99}. Orderbook names matching ^(bid|ask)_(\d+)_(cost|vwap|size|slope|imbalance|depth_ratio|levels_count|microprice)_(avg|mean|median|min|max|sum|q95|skew)$ SHALL map to ob__{pct}pct__{side}__{feat}__{stat} with the backtest stat avg aliased to mean, and SHALL be price-like only for vwap and microprice. Resolution order SHALL be zero-metrics -> price-like aliases -> flow aliases -> orderbook regex -> pass-through. Any other name SHALL pass through unchanged (never raising, despite the docstring's KeyError claim) so callers can request a raw Backend-go key directly; in the live bridge an unmapped name therefore resolves to an all-NaN frame rather than an error.

    realized_funding SHALL be served with settlement semantics: the underlying stream repeats the accruing 8h rate in every bar, so the bridge SHALL zero the frame everywhere except rows at minute 0 of the hours in FUNDING_SETTLEMENT_HOURS ({0, 8, 16}), where it charges the PRIOR bar's rate (a one-row shift, NaN filled with 0.0).

    Scenario: Funding settlement hours¶

    • WHEN a realized_funding series is served
    • THEN the rate is charged only on rows at minute 0 of hours 0, 8, and 16 (the prior bar's rate), and is zero elsewhere

    Scenario: Unmapped name¶

    • WHEN a strategy asks for a name no alias covers
    • THEN go_name returns it unchanged and the live container serves an all-NaN frame instead of raising

    Requirement: Offline metrics container divergence¶

    The offline container (AggregatedMetricsDict / ExchangeData in alpha_engine/metrics/metrics_dict.py) SHALL diverge deliberately from the live bridge. Unknown metric names SHALL raise KeyError from _resolve_source (never resolving to NaN frames - the opposite of the live bridge's pass-through), and a name that resolves to a group whose aggregator did not produce it SHALL also raise KeyError. Group aggregation SHALL be lazy and cached: the first access of any metric in a group aggregates that group for ALL tickers over a 30min UTC index, and tickers with no data for a metric SHALL be filled with an all-NaN column. When NO ticker in a group produced data, the group SHALL still be marked aggregated and nothing written, so the pending lookup falls through to the "aggregator did not produce it" KeyError rather than looping. When the caller passes no explicit ticker list, the ticker set SHALL be the sorted union of the reader's available_tickers for the trades and klines kinds only. ExchangeData SHALL default to the exchanges ["binance", "binance-f"], one AggregatedMetricsDict each. has_kinds/missing_kinds SHALL gate against the underlying reader's available_tickers per kind - fully permissive (always True / empty set) when no reader is attached (mock mode), and treating a reader exception as a missing kind - a different mechanism from the live bridge's _KIND_PROBES table.

    Scenario: Unknown metric is fatal offline¶

    • WHEN a strategy asks the offline container for a name no aggregator registers
    • THEN a KeyError is raised instead of a NaN frame, so the typo surfaces in the backtest

    Scenario: Mock mode gating¶

    • WHEN has_kinds is called on a container with no reader attached
    • THEN it returns True for every kind, because there is nothing to probe
