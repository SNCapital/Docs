    Metrics Aggregation

    Purpose¶

    Defines the offline metric aggregation layer of alpha_engine (metrics/): raw data readers over the binance_parser parquet tree, the lazy metric container (AggregatedMetricsDict / ExchangeData) with its metric-to-group registry, and the per-kind 30-minute aggregators (klines / funding / markprice, trades, orderbook, liquidations, trades v2, multilevel, maker orders, market stats, orderbook updates). It covers the data contract shared by the batch backtester (AlphaPipeline) and the live runtime (LiveEngine over LiveRawDataReader); real-time metric computation lives in alpha-engine/metrics-engine, and the live trading runtime in alpha-engine/live-trading. Canonical Backend-go key names plus the alpha-engine to Go resolver (go_name, FUNDING_SETTLEMENT_HOURS) live in alpha_engine/metrics_engine/keys.py; the Backend-go reader is alpha_engine/metrics/go_metrics_reader.py.

    Requirements¶

    Requirement: Raw data readers and parquet layout¶

    The system SHALL expose a RawDataReader abstraction with read(exchange, kind, ticker, since, until) and available_tickers(exchange, kind). The primary MultiFileParquetReader SHALL read the Hive-partitioned layout {data_root}/market={spot|usdm}/type={event_type}/dt=YYYY-MM-DD/symbol={SYMBOL}/part-*.parquet, mapping alpha-engine exchange tags (binance, binance-f) to parser market= partitions and RawDataKind to the type= partition(s): aggtrades (lowercase, live writer) and aggTrades (camelCase, historical download) SHALL both resolve to the trades kind without double-reading (files are deduped by path across the two partitions); raw per-fill trades shards SHALL be a distinct kind (trades_raw) and never mixed into the aggregated trades stream; forceorder SHALL feed the liquidations kind; market_stats SHALL union five partitions (open_interest_now, global_long_accounts, top_long_accounts, top_long_positions, daily_interest_rate); the periodic-poll kinds open_interest, taker_ratio, long_short_ratio SHALL map to their own type= partitions under market=usdm; orderbook SHALL resolve exclusively to type=booksnapshot - diff updates are deliberately excluded (diffs are not snapshots); a kind with no _KIND_TO_TYPES entry SHALL fall back to type={kind} verbatim, and an unknown exchange tag SHALL yield no partition root at all. The RawDataKind enumeration is exactly trades, trades_raw, orderbook, klines, funding, markprice, liquidations, open_interest, taker_ratio, long_short_ratio, market_stats. The reader SHALL prune by dt= partition before reading any file, keeping a day iff day + 1 day >= since and day <= until; a directory whose name does not start with dt= is skipped silently and an unparseable dt= name is skipped with a WARNING (a garbage name would otherwise be an invisible whole-day hole). read SHALL return None when no shard matches, concatenate the matching shards, apply the per-kind column normalisation, filter timestamp inclusively on both ends of [since, until], then sort_values("timestamp") and reset the index; a shard that fails to load is skipped with a WARNING (fail-open per shard) and None is returned when every shard fails. available_tickers SHALL scan every dt= directory of every mapped type= partition WITHOUT window pruning, collect the symbol= directory names and return them sorted (no parquet file is opened). A ParquetFileReader SHALL additionally support the legacy flat layout data_root/{exchange}/{kind}/{TICKER}.parquet plus CSV and zip archives, probing extensions in the order .parquet, .csv, .zip, taking the first .parquet-or-.csv member inside an archive and raising ValueError for an archive with neither or for an unsupported suffix; it SHALL apply NO per-kind normalisation (raw columns pass through), only coercing timestamp to UTC and filtering inclusively without sorting, and its available_tickers SHALL be the sorted file stems of the directory.

    Scenario: AggTrades case-insensitive collision¶

    • WHEN both type=aggtrades and type=aggTrades partitions exist for a symbol
    • THEN they are read once as one trades stream instead of being double-counted

    Scenario: Raw fills stay separate¶

    • WHEN reading the trades kind
    • THEN raw per-fill type=trades shards are not mixed in, so aggregated and raw streams never double-count

    Scenario: dt pruning¶

    • WHEN a date range is requested
    • THEN only dt= directories overlapping the range are opened, and unparseable dt= names are skipped with a warning

    Scenario: Unreadable shard¶

    • WHEN one part file of a multi-shard read cannot be parsed
    • THEN it is skipped with a WARNING and the remaining shards still produce a frame, but a read where every shard fails returns None

    Scenario: Ticker discovery ignores the window¶

    • WHEN available_tickers is called for a kind
    • THEN every dt= directory of the mapped partitions is scanned regardless of since / until, so gating sees a symbol that only has data outside the backtest window

    Requirement: Per-kind column normalisation¶

    The system SHALL normalise live-writer and historical-archive column names to the aggregator contract inside MultiFileParquetReader.read (helper _normalise_columns, operating on a copy of the concatenated frame) in a fixed order. Timestamp resolution: when a timestamp column is absent, timestamp_ms SHALL be converted (ms, UTC) and the source column DROPPED, else open_time SHALL be used as the klines bar start (ms, UTC, source column KEPT), else transaction_time (ms, UTC); when timestamp already exists it SHALL be coerced with pd.to_datetime(..., utc=True); a frame with no resolvable timestamp SHALL be returned unfiltered and unsorted. Then: trades and trades_raw SHALL rename qty to size and derive side from is_buyer_maker (True -> sell, False -> buy), both only when the target column is absent; klines SHALL synthesise volume_usd when absent, preferring Binance's own quote_volume cast to float64 and only otherwise close * volume (if neither source exists the column stays absent); funding SHALL map funding_time_ms to timestamp; markprice SHALL rename predicted_funding_rate to predicted_funding; liquidations SHALL rename cum_filled_qty to size with a legacy orig_qty fallback used only when cum_filled_qty is missing, and SHALL promote avg_price into price as float (overwriting the order's requested price); market_stats SHALL coerce the nine known numeric columns (open_interest, long_short_ratio, global_long_account_ratio, global_short_account_ratio, top_long_account_ratio, top_short_account_ratio, top_long_position_ratio, top_short_position_ratio, daily_interest_rate) with pd.to_numeric(errors="coerce") so the object-dtype union of five differently shaped partitions never reaches the aggregator as strings. The side value is already lowercased by the parser DTO before the reader ever sees it (the reader does no case conversion). ParquetFileReader, MockRawDataReader and LiveRawDataReader SHALL NOT call this helper - they emit the normalised names directly.

    Scenario: Liquidation size fallback¶

    • WHEN a legacy forceOrder shard has orig_qty but no cum_filled_qty
    • THEN orig_qty is renamed to size, and when both exist only cum_filled_qty is used

    Scenario: Quote volume preferred¶

    • WHEN a klines shard carries quote_volume
    • THEN volume_usd is that column as float64, and the close * volume approximation is used only when quote_volume is absent

    Scenario: Historical archive side¶

    • WHEN a trades shard carries is_buyer_maker and no side
    • THEN side becomes sell where the buyer was the maker and buy otherwise

    Requirement: Mock raw data generation¶

    MockRawDataReader SHALL generate structurally identical synthetic data for the five kinds it can synthesise (trades, orderbook, klines, funding, markprice); every other kind (liquidations, trades_v2, market_stats, trades_multilevel, maker_orders, trades_raw) SHALL return no tickers and a None read (deliberate kind-gating so go_metrics-backed strategies are skipped instead of crashing on missing keys). Defaults SHALL be trades_per_30min=500, ob_snapshots_per_30min=5 (matching the parser's ~1 snapshot/bar order of magnitude; the historical 60 made 50 tickers x 30 days unusably slow), seed=42, window 2024-01-01 to 2024-03-01 UTC and the 50 mock_provider.DEFAULT_TICKERS. One shared 30-minute GBM price path per ticker SHALL be pre-generated with per-step vol 0.03 / sqrt(48) off _BASE_PRICES, so every kind of one ticker tells the same price story. Each (exchange, kind, ticker) frame SHALL be generated once, cached, and served sliced inclusively to [since, until] (the cache is consulted before the ticker-membership check); an unknown ticker or unsupported kind SHALL return None. Trades SHALL use Poisson counts per bar, lognormal USD notionals divided by price and a per-bar buy-probability jitter. Orderbook SHALL emit 50 levels per side per snapshot at offsets arange(n_snaps) * 1800 / n_snaps seconds after the bar start, sides labelled bid / ask, vectorised with a single DataFrame build, and SHALL convert the index through datetime64[ns, UTC] before taking the int64 view (a raw view("int64") on a microsecond-backed tz-aware index silently lands every row in 1970). Klines SHALL carry volume_usd; funding SHALL carry only realized_funding, stepped every 16 bars (8h); markprice SHALL carry mark_price, index_price, predicted_funding and next_funding_time_ms on the 00/08/16 UTC settlement schedule.

    Scenario: Kind gating in mock mode¶

    • WHEN a strategy requires the liquidations or trades_v2 kind on mock data
    • THEN available_tickers returns [] for that kind, the strategy is skipped by the gate, and no synthetic panel is fabricated

    Scenario: Deterministic panels¶

    • WHEN the same (exchange, kind, ticker) is read twice with different windows
    • THEN the cached frame is reused and only the inclusive [since, until] slice differs

    Requirement: Mock metric provider¶

    mock_provider SHALL also offer a metric-LEVEL mock that bypasses the readers and aggregators entirely: MockMetricsDict is a lazy dict keyed by metric name that fabricates a timestamps x tickers DataFrame on first access and caches it, and MockExchangeData wraps one such container per exchange (defaulting to binance and binance-f), offsetting the seed by the exchange index so the two venues do not carry identical panels. Defaults SHALL be the 50 DEFAULT_TICKERS, the window 2023-01-01 to 2025-01-01 UTC on the 30-minute grid, and seed=42. One shared GBM price path per ticker SHALL back every metric (_generate_price_series, per-step vol 0.03 / sqrt(48) off _BASE_PRICES), generated lazily on the first metric access: close_price / mark_price / index_price are that path, open_price is it shifted one bar and back-filled, high_price / low_price scale it by 1 +/- U(0, 0.005), volume divides a lognormal USD notional by price, the funding legs are N(0.0001, 0.0005), next_funding_time_ms broadcasts the bar index in epoch milliseconds, and the orderbook and trade families are dispatched by name substrings in a deliberately order-sensitive chain (logreturn, vwap, midprice, cost, size, place, remove, spread, liq_shock, last_best_, best_). Unlike AggregatedMetricsDict this container SHALL NEVER raise: an unrecognised metric name falls through to a generic lognormal trade-metric panel. MockExchangeData SHALL expose neither has_kinds nor missing_kinds and MockMetricsDict carries no reader attribute, so this pair is a strategy-level and test-level fixture rather than a pipeline data provider (filter_runnable calls both gating methods).

    Scenario: Unknown metric never raises¶

    • WHEN a strategy asks MockMetricsDict for a name that matches no branch
    • THEN a generic synthetic panel is returned instead of the KeyError the real container raises

    Scenario: One price story per ticker¶

    • WHEN several price-derived metrics are read for the same ticker
    • THEN they all derive from the single cached GBM path, so open, high, low and close stay mutually consistent

    Requirement: Metric registry and lazy container¶

    The system SHALL expose every aggregated metric through a lazy dict-like container (AggregatedMetricsDict) indexed by a 30-minute UTC DatetimeIndex over [since, until]. First access to any metric from a group SHALL trigger aggregation of ALL metrics of that group for ALL tickers, and the group result SHALL be cached. When no explicit ticker list is supplied the ticker universe SHALL be the union of available_tickers over ONLY the trades and klines kinds. Metric-to-group resolution SHALL be deterministic with a fixed precedence: an exact registry lookup (_METRIC_SOURCE over the ten *_METRICS registries), then the explicit liquidations_ prefix, the maker_ prefix, the aggressor_ / buy_aggressor_ / sell_aggressor_ prefixes, pattern rules for bid_/ask_ (cost/size/vwap/levels/spread/logreturn), best_, last_best_, liq_shock, vwap_*_midprice, buy_/sell_ with _ml/_sl (bare or _ml_quantile_ / _sl_quantile_ tags) routing to trades_multilevel and plain buy_/sell_ to trades, the defensive no-side ml/sl names (mean_cost_ml, mean_cost_sl, mean_price_delta_ml_quantile_*), cost_imbalance, bid_ask_spread, the klines names (close_price, open_price, high_price, low_price, volume, volume_usd), the markprice names (mark_price, index_price, next_funding_time_ms, predicted_funding), and finally any name containing funding. A metric matching no source SHALL raise KeyError (never silently return a NaN frame), and a metric known to a group that its aggregator failed to produce SHALL also raise KeyError; an unknown aggregation kind SHALL raise ValueError. Per-ticker Series SHALL be pivoted into timestamps x tickers DataFrames with NaN-filled gaps: one column per ticker in the container's ticker order, an all-NaN Series for a ticker that has no data or lacks that metric, and the frame index forced onto the canonical grid. A ticker whose read returns None or an empty frame SHALL be skipped (logged, sampled to roughly 20 progress lines per group with the read/aggregate split), and a group where NO ticker produced data SHALL still be marked computed while storing nothing - so the pending access falls through to the "aggregator did not produce it" KeyError. The trades_v2 group SHALL fan out a dual read (trades for aggressors plus trades_raw for per-fill detail), skip tickers with no aggregated data and substitute an empty [timestamp, trade_id, price, size, side] frame when the raw read returns None. The maker_orders group SHALL be gated by emit_maker = exchange == "binance"; on other exchanges one read-only empty panel object SHALL be shared by every ticker (never mutated downstream) at zero I/O cost. ExchangeData SHALL wrap one container per exchange (the python offline container, defaulting to binance and binance-f) and SHALL support has_kinds / missing_kinds gating; missing_kinds lives on ExchangeData (no such method on AggregatedMetricsDict): it returns set() (fully permissive) only when the exchange's MetricsDict has no reader (md.reader is None, e.g. mock mode), otherwise it reflects the reader's available_tickers per kind and marks a kind missing when that call raises (defensive fail-closed, a bad reader must not abort gating). The probe-based GoExchangeData (_KIND_PROBES table checked against store.has_key: trades probes vwap/buy_volume_q95, klines close/quote_volume, markprice close, orderbook ob__25pct__bid__cost__mean, go_metrics ob__minor__spread_bps__mean/vwap) is NOT fully permissive and has no reader-None branch: every kind absent from the probe table (liquidations, trades_v2, market_stats, funding, trades_raw, trades_multilevel, maker_orders) is reported missing on the Go path. MockRawDataReader.available_tickers deliberately returns [] for every kind except the five it can synthesize (trades, orderbook, klines, funding, markprice), so liquidations, trades_v2, market_stats, trades_multilevel, maker_orders and trades_raw are never synthesised in mock mode - by design, so go_metrics-backed strategies are skipped rather than crash.

    Scenario: Unknown metric raises¶

    • WHEN a metric name matches no registered source
    • THEN the container raises KeyError naming the metric rather than fabricating a NaN frame

    Scenario: Group-level caching¶

    • WHEN a second metric of an already-computed group is accessed
    • THEN it is served from the cache without re-aggregating

    Scenario: Missing ticker gap¶

    • WHEN a ticker has no data for a bar
    • THEN its column holds NaN for that bar, keeping the full-index shape

    Scenario: Group with no data at all¶

    • WHEN every ticker of a group reads back empty
    • THEN the group is marked computed, no frame is stored, and the access raises the "aggregator did not produce it" KeyError instead of an all-NaN panel

    Scenario: Reader error fails closed¶

    • WHEN available_tickers raises for one kind during gating
    • THEN that kind is reported missing and the strategy is skipped rather than run against unverified data

    Requirement: Klines, funding and markprice alignment¶

    The system SHALL aggregate the pre-aggregated kinds by alignment to the 30-minute grid: klines SHALL produce exactly close_price, open_price, high_price, low_price, volume, volume_usd; funding SHALL produce realized_funding; markprice SHALL produce mark_price, index_price, predicted_funding, next_funding_time_ms, reindexed onto the full bar grid with forward-fill so the metric stays alive across gaps - but only mark_price is mandatory in the source frame (missing index_price / predicted_funding / next_funding_time_ms columns are tolerated and simply absent from the output). Each aggregator SHALL coerce timestamp with utc=True, index by it, sort, and build the grid as date_range(since, until, freq="30min", tz="UTC"). Klines SHALL require {open, high, low, close, volume} and raise ValueError naming the missing columns; it SHALL classify the source as already-30-minute when the median timestamp gap is strictly between 25 and 35 minutes (and unconditionally when the frame has at most one row), in which case the frame is reindex(grid, method="nearest", tolerance="15min"); otherwise it SHALL resample("30min") with first/max/min/last/sum over OHLCV (plus sum on volume_usd when present) and reindex onto the grid. volume and volume_usd SHALL be fillna(0) after alignment while OHLC stays NaN on empty bars. volume_usd SHALL be emitted only when the source klines frame carries the column (a legacy reader without the normalised column raises KeyError on the metric). Funding SHALL require realized_funding (else ValueError) and align with reindex(grid, method="ffill") so the last settlement carries forward. Markprice SHALL require mark_price (else ValueError) and emit each present column of MARKPRICE_METRICS in registry order via reindex(grid, method="ffill"). mark_price / index_price SHALL NOT be aliased to kline closes (each kind owns its metric names); a backtest without a markprice partition sees NaN for them rather than a proxy.

    Scenario: Markprice forward fill¶

    • WHEN mark-price rows are sparse
    • THEN the metric is forward-filled onto the 30-minute grid so later bars carry the last observed value

    Scenario: Fine-grained klines¶

    • WHEN the source klines are 1-minute bars (median gap outside 25-35 minutes)
    • THEN they are resampled with first/max/min/last/sum instead of nearest-reindexed, and volume / volume_usd are summed

    Scenario: Empty kline bar¶

    • WHEN the grid contains a bar with no source kline
    • THEN volume and volume_usd are 0.0 while open_price / high_price / low_price / close_price stay NaN

    Requirement: Trades aggregation¶

    The system SHALL compute 98 trade metrics per 30-minute bar from raw trades ([timestamp, price, size, side]; a missing required column raises ValueError): counts, volumes, quote volumes, per-side cost and size quantiles over the canonical set {0.25, 0.5, 0.75, 0.9, 0.95} (no 0.99), OHLC computed by averaging buy-only and sell-only open/high/low/close prices (NaN if one side is empty, killing bid-ask bounce), Herfindahl over size (base-coin units), intra-bar volatility as the std of minute-VWAP log returns with ddof=1 (NaN with fewer than 3 minute groups, because ddof=1 needs at least 2 returns to be finite), Kyle's lambda as an OLS of log-return on signed volume across minute groups (NaN with fewer than 3 groups or zero signed-volume variance), and ASR (asr_count / asr_volume) using a 60-second look-ahead window that may cross the bar boundary. Per-trade notional is cost = price * size. Side classification SHALL be a single equality test against buy with the sell mask as its complement (sell_mask = ~buy_mask), so any other value - a mis-cased label, an unexpected string - is booked as a sell rather than dropped; the signed-volume conventions of Kyle and ASR follow the same buy -> +1, else -1 rule. {buy,sell}_count_above_{T} SHALL use strict cost > T over T in {100, 1000, 10000, 100000, 1000000}. Quantile boundaries SHALL come from np.quantile with default linear interpolation, computed per side from that side's own cost distribution and, for the no-side family, from the joint distribution; membership SHALL be at-or-above the boundary (>=). For each quantile the emitted keys SHALL be {side}_cost_quantile_q (tail notional sum), {side}_trade_cost_quantile_q (the boundary value itself), {side}_volume_quantile_q (tail base-size sum), {side}_volume_quantile_q_usd (an exact alias of {side}_cost_quantile_q, kept for v1 sanity), {side}_count_quantile_q, plus the no-side count_quantile_q, volume_quantile_q and volume_quantile_q_usd. OHLC keys are the bare open / high / low / close (the *_price names belong to klines). VWAPs SHALL be NaN when the relevant size sum is not positive; Herfindahl SHALL be NaN on an empty or non-positive-total subset and 1.0 on a single entry; volatility and Kyle SHALL also NaN out when any minute VWAP is non-positive. ASR SHALL evaluate, for each bar trade, the latest trade in (t, t + 60s] across the bar plus the (bar_end, bar_end + 60s] slice taken from the whole raw frame (so an empty next bar does not truncate the window), count a loss when (after_price - price) * sign(side) < 0, exclude trades with an empty look-ahead from BOTH numerator and denominator, and return NaN for both ratios when the included set is empty (asr_volume also NaN when the included size sum is zero). The empty-bar contract SHALL be additive-zero / distributional-NaN: volume, {buy,sell}_volume, {buy,sell}_cost, {buy,sell}_count, the count_above_T family and max_{buy,sell}_trade_cost default to 0.0, everything else to NaN; bars of the grid with no trades at all SHALL carry exactly that default panel, and every Series SHALL be float-dtyped over the full grid.

    Scenario: Buy-sell OHLC averaging¶

    • WHEN both sides have trades in a bar
    • THEN OHLC values are the average of the buy-side and sell-side first/last/max/min prices

    Scenario: Undefined volatility¶

    • WHEN a bar has fewer than 3 minute-groups with trades (with exactly 2 groups there is only one log-return, which ddof=1 cannot use)
    • THEN the volatility metric is NaN rather than a fabricated number

    Scenario: ASR look-ahead is empty¶

    • WHEN no trade lands in (t, t + 60s] for a given trade
    • THEN that trade is dropped from both the numerator and the denominator, and both ASR ratios are NaN when this holds for every trade in the bar

    Scenario: Empty bar defaults¶

    • WHEN a bar in the grid has no trades
    • THEN additive keys (volumes, costs, counts, count_above_T, max_*_trade_cost) are 0.0 and every distributional key (vwap, OHLC, quantiles, hh, kyle, asr, volatility) is NaN

    Requirement: Orderbook aggregation¶

    The system SHALL compute orderbook metrics from L2 snapshot rows ([timestamp, side, price, size], one row per price level; a missing required column raises ValueError) with two aggregation templates: the 9-aggregation template for per-snapshot bases (_avg, _quantile_25/50/75/90/95, _skew as the bias-corrected Fisher-Pearson skew computed in closed form - value-identical to scipy.stats.skew(bias=False) with no scipy dependency, _min, _max, no _sum), and the 10-aggregation template for cross-snapshot diff/logreturn bases (_sum included, applying a zero-drop in addition to the NaN-drop). Both templates SHALL first drop non-finite samples (NaN and infinities), return all-NaN (with _sum = 0.0 on the 10-agg) when nothing remains, and compute quantiles with np.quantile linear interpolation; _skew SHALL be NaN for fewer than 3 samples and for near-constant input (population std exactly 0 or below 1e-12 * max(1, |mean|)) so scipy's precision-loss regime is never surfaced as a number. Offsets SHALL be the 12 percent zones OFFSETS = [0.01, 0.05, 0.1, 0.25, 0.5, 1, 2, 5, 10, 25, 50, 100], labelled by replacing . with _ (0.05 -> 0_05, 25 -> 25), giving names such as bid_0_05_cost_avg and ask_25_vwap_quantile_95. The liq_shock_{side}_{X} metrics SHALL be computed per snapshot as {side}_X_size[t] / mean({side}_X_size[t-W .. t]) with a fixed 10-second window inclusive of the current sample (LIQ_SHOCK_WINDOW_SECONDS = 10.0, one LiqShockRollingWindow per side/offset, O(1) memory, no pandas dependency in the hot path, NaN when the rolling mean is not positive), over the REDUCED offset set LIQ_SHOCK_OFFSETS = [0.05, 0.1, 0.25, 0.5, 1, 5, 25, 50] (8 zones, not the 12 used elsewhere), plus the liq_shock_ratio_{X} family = bid / (bid + ask) (NaN when either leg is NaN or both are zero) computed directly per snapshot - it shares only the 9-agg aggregation template, not the rolling window - all aggregated like any other 9-agg base metric. A snapshot whose own-side zone size is NaN SHALL NOT be pushed into that side's rolling window at all (pushing NaN would poison the baseline) and its liq_shock sample stays NaN. The emitted schema SHALL be exactly 210 nine-agg bases, 88 ten-agg bases and the 2 end-of-bar last_best_{bid,ask}_price values - 2772 keys in OB_METRICS - with _sum defaulting to 0.0 and every other key to NaN on an empty bar, and every key present on every bar of the grid.

    Scenario: Zero-drop on diff bases¶

    • WHEN a cross-snapshot diff base is aggregated
    • THEN both NaN and zero samples are dropped before computing quantiles and stats

    Scenario: Liq-shock ratio¶

    • WHEN a snapshot's zone volume diverges from its trailing 10-second baseline
    • THEN the liq_shock metric is the ratio of current zone volume to the rolling mean, with the current sample included in its own baseline

    Scenario: Reduced liq-shock offsets¶

    • WHEN the per-offset liq_shock family is emitted
    • THEN only the 8 LIQ_SHOCK_OFFSETS zones exist (no liq_shock_bid_0_01 and no liq_shock_bid_100), while every other L2 family covers all 12 OFFSETS

    Scenario: Near-constant skew¶

    • WHEN a base metric is constant (or varies below the 1e-12 * max(1, |mean|) threshold) across the bar's snapshots
    • THEN _skew is NaN rather than a numerically meaningless value, and it is also NaN with fewer than 3 finite samples

    Requirement: Orderbook per-snapshot base panel¶

    The system SHALL derive every orderbook base metric per snapshot (rows grouped by exact timestamp, processed chronologically) before aggregating across the bar. A snapshot SHALL be SKIPPED entirely when either best_bid_price (max bid price) or best_ask_price (min ask price) is missing, mirroring the live book's mid() contract - np.nanmean over one side would bias the mid by half a spread - and a bar where no snapshot survives SHALL return the empty panel. mid SHALL be (best_bid + best_ask) / 2. Group A (L1, 9-agg): best_{bid|ask}_price, best_{bid|ask}_size (sum of size at the best price, NaN exactly when the matching best price is NaN), bid_ask_spread_abs (best_ask - best_bid, quote ccy) and bid_ask_spread_rel (spread_abs / mid). Group B (L2 depth per offset, 9-agg): for each side and offset, the zone SHALL keep bid levels with price >= best * (1 - X/100) and ask levels with price <= best * (1 + X/100) (located by np.searchsorted on the once-sorted price array, O(log n) per zone), emitting {side}_{X}_cost (sum notional), _size (sum base), _vwap (cost/size, NaN when size is not positive), _levels_size_mean, _levels_size_count and _levels_size_count_nonzero; a NaN best price or an empty zone SHALL make all six outputs NaN (never 0.0 - downstream aggregation cannot distinguish a fabricated zero from genuine zero liquidity). Per offset the panel SHALL also carry cost_imbalance_{X}_ratio (bid_cost / ask_cost, NaN when either cost is NaN or ask_cost is 0), cost_imbalance_{X}_norm (bid_cost / (bid_cost + ask_cost), valid 0.0 / 1.0 at the edges and NaN only when both are 0) and vwap_{X}_midprice ((bid_vwap + ask_vwap) / 2, NaN if either leg is NaN). Group C (10-agg) SHALL be derived across snapshots: {side}_{X}_cost_diff and {side}_{X}_size_diff and best_{side}_size_diff as v[t] - v[t-1] with NaN at index 0, and {side}_{X}_vwap_logreturn, best_{side}_price_logreturn, vwap_{X}_midprice_logreturn as log(v[t] / v[t-1]) with NaN at index 0 and wherever either operand is NaN or non-positive. last_best_{bid|ask}_price SHALL be taken from the LAST surviving snapshot of the bar and SHALL NOT be aggregated.

    Scenario: One-sided snapshot¶

    • WHEN a snapshot carries only bids (or only asks)
    • THEN it is dropped from the bar's per-snapshot panel instead of contributing a half-spread-biased mid

    Scenario: Empty zone is NaN¶

    • WHEN no level falls inside the 0.01% zone of the best price
    • THEN all six {side}_0_01_* base values are NaN for that snapshot, not zero

    Requirement: Liquidations aggregation¶

    The system SHALL compute 50 liquidation metrics per bar from normalized @forceOrder rows ([timestamp, side, size, price] where size = cum_filled_qty with a legacy fallback renaming orig_qty to size when the column is absent, and price = avg_price, side lowercased by the parser DTO). The liquidation side SHALL be interpreted as the closing side (sell closes a long, buy closes a short). The metric pack SHALL include per-side counts, cost/notional totals and quantiles (no size or price quantiles), VWAP, OHLC, intra-bar volatility, Herfindahl, Kyle's lambda, and ASR - there are no imbalance keys and no size/price quantiles in the 50-key pack - and every key SHALL carry the liquidations_ prefix. Events with size <= 0 (FILLED with no fills) SHALL be dropped defensively BOTH on the whole frame before bar grouping (so ASR look-ahead slices never see them) and again per bar for callers that bypass the 30-minute entry point. A None or empty input frame, or a frame left empty by the size filter, SHALL yield the full default panel on every bar of the grid; only a non-empty frame is column-validated ({timestamp, side, size, price}, else ValueError). Rows SHALL be sorted by timestamp before use, and _compute_asr SHALL fail fast with ValueError if it is ever handed non-monotonic timestamps rather than silently mis-pairing look-aheads; the per-bar aggregator sorts with kind="stable" so equal-timestamp rows keep arrival order for the buy-only / sell-only OHLC first/last semantics, while the 30-minute entry point sorts with the default (unstable) sort_values before bucketing and building the cross-bar look-ahead slices. Side classification SHALL use the same buy / not-buy complement as trades (sell_mask = ~buy_mask), so a mislabelled side counts as a sell-closing liquidation. Quantiles ({0.25, 0.5, 0.75, 0.9, 0.95}), USD thresholds ({100, 1000, 10000, 100000, 1000000} with strict >), the >= boundary inclusion, the 60-second ASR look-ahead with its cross-bar slice and exclusion of empty-window events, the Herfindahl over base-coin size, the minute-VWAP ddof=1 volatility and the minute-group Kyle regression SHALL match the trades-v2 template; Kyle SHALL additionally require at least 2 log-returns (3 minute groups) and a non-zero signed-volume variance. Empty-bar defaults SHALL be 0.0 for counts, count_above_T, {buy,sell}_cost and max_{buy,sell}_trade_cost, NaN for every distributional key. Because liquidations are a sparse stream, NaN on most bars for volatility / kyle / hh / OHLC is the expected regime, not a defect.

    Scenario: Closing-side semantics¶

    • WHEN a sell force order is aggregated
    • THEN it contributes to the sell-closing side, which closes a long position

    Scenario: Zero-fill events dropped¶

    • WHEN a forceOrder row has size == 0
    • THEN it is filtered out before bar grouping, so it influences neither the bar's counters nor any ASR look-ahead window

    Requirement: Multilevel reconstruction¶

    The system SHALL reconstruct logical multilevel aggressions and maker fills from raw streams: trades_v2 SHALL rebuild per-aggressor fill detail by reindexing the raw @trade stream (kind="trades_raw", deduplicated on trade_id keeping the first) over the inclusive [first_trade_id, last_trade_id] range, skipping aggressors whose entire range is missing (no fallback to the aggregated price/qty) and tolerating partial ranges as a shorter fill list; an aggressor with last_trade_id < first_trade_id is skipped outright. Its five per-aggressor bases SHALL be aggressor_order_size (sum fill size), aggressor_order_cost (sum price*size), aggressor_order_levels (fill count), aggressor_order_price_range ((max_px - min_px) / min_px, exactly 0.0 for a single fill, NaN when min_px <= 0) and aggressor_order_worst_slip (signed by aggressor side so a buy paying up to max_px and a sell selling down to min_px both report a positive fraction, 0.0 for a single fill, NaN on a non-positive best price); the panel SHALL be 150 keys - 50 from the 5 bases times the 10-suffix AGG_SUFFIXES pack and 100 from the same bases side-split into buy_aggressor_order_* / sell_aggressor_order_* - all through the shared _multi_aggregate (which is the 10-agg with its zero-drop), with _sum defaulting to 0.0 and every other suffix to NaN. The side split SHALL test both labels strictly (side == "buy" and side == "sell"), unlike the buy / not-buy complement used by trades and liquidations, so an aggressor carrying any other side value feeds the 50 unsided keys only and is absent from both side-split halves. Either input frame missing or empty SHALL emit the full empty panel for every bar BEFORE any column validation runs (the empty short-circuit returns first, so an empty frame never raises); only non-empty frames are column-validated (ValueError on missing columns) and bucketed by floor("30min"), with a bar's aggressors matched against that same bar's raw fills only. The historical download ships no per-fill source, so backtest-time reconstruction only works when the parser ran with LIVE_RECONSTRUCT_MULTILEVEL=True. trades_multilevel SHALL glue adjacent aggTrades into one LogicalTrade iff (strictly, epsilon 0) they share side and engine timestamp, B.first_trade_id == A.last_trade_id + 1, and price deepens monotonically along the hit side (up for buys, down for sells) relative to the chain's last price; a row that matches side, timestamp and contiguity but violates monotonicity SHALL be logged at DEBUG and start a new chain. Input SHALL be sorted by (timestamp_ms, first_trade_id) with a stable mergesort after deriving timestamp_ms through datetime64[ns, UTC] then integer-division by 1e6 (so a microsecond-backed source is not off by 1000), chains SHALL be reconstructed once over the whole frame and bucketed by floor(timestamp_first, "30min"), and each chain SHALL carry n_levels, is_multilevel = n_levels >= 2, total_size, total_cost, vwap (NaN when total size is not positive), price_first, price_last and price_delta_pct ((price_last - price_first) * side_sign / price_first, exactly 0.0 for single-level, NaN when price_first == 0). The emitted 73-key ml/sl panel SHALL be 4 counts, 4 cost totals, 4 mean costs, 4 VWAPs, 20 {side}_cost_{ml|sl}_quantile_q tail sums, 20 {side}_trade_cost_{ml|sl}_quantile_q boundaries, 10 {side}_mean_price_delta_ml_quantile_q (mean price_delta_pct restricted to the top-q% by total cost) and the 7 no-side aggregates (mean_cost_ml, mean_cost_sl, mean_price_delta_ml_quantile_q), with >=-boundary membership, counts and cost totals defaulting to 0.0 and everything else to NaN. The aggregator SHALL work when handed the aggTrade stream directly ([timestamp, side, price, size, first_trade_id, last_trade_id]), but AggregatedMetricsDict currently cannot serve this group end-to-end: its generic path reads kind="trades_multilevel", which has no entry in the reader's _KIND_TO_TYPES, so the Hive lookup targets a nonexistent type=trades_multilevel partition, every ticker is skipped, and accessing the group raises KeyError (the code comment claiming it "reads the same aggregated trades stream as trades" is stale). maker_orders SHALL treat each raw fill as exactly one maker fill (the resting limit-order side, the dual of the taker view), emitting a 50-key panel; it SHALL be gated to spot (emit_maker only when the exchange is binance) - on futures every ticker receives the deterministic empty panel at zero I/O cost, keeping the schema stable across venues.

    Scenario: Logical trade gluing¶

    • WHEN two adjacent aggTrades have the same side and timestamp, contiguous fill ids, and deepening price
    • THEN they are combined into one logical multilevel trade for the ml/sl metrics

    Scenario: Maker gating on futures¶

    • WHEN the exchange is not binance
    • THEN every ticker gets the empty 50-key maker panel without reading any raw data

    Scenario: Missing raw fill range¶

    • WHEN an aggressor's whole [first_trade_id, last_trade_id] range is absent from trades_raw
    • THEN that aggressor contributes no sample at all, rather than being reconstructed from the aggregated price and quantity

    Scenario: Monotonicity violation closes the chain¶

    • WHEN an aggTrade matches side, engine timestamp and last_trade_id + 1 but does not deepen the price
    • THEN the in-flight chain is closed, a DEBUG line records the anomaly, and the row starts a new logical trade

    Requirement: Maker-orders panel¶

    The system SHALL build the maker view from the per-fill trades_raw feed by inverting the reader's taker-side label: taker buy means the maker was on the ask, taker sell means the maker was on the bid. Every trades-v2 formula SHALL then be applied to those maker fills with buy -> ask / sell -> bid renames and a mandatory maker_ prefix on every key (the bare ask_* / bid_* names of the source spec would collide with the L2 orderbook namespace). The 50-key pack SHALL be maker_{ask,bid}_count, 10 maker_{ask,bid}_count_above_{T}, maker_{ask,bid}_cost, maker_vwap / maker_{ask,bid}_vwap, maker_{open,high,low,close} (averaged per-side OHLC, NaN when either side is empty), maker_volatility, maker_hh / maker_hh_{ask,bid}, maker_kyle_lambda, maker_asr_count / maker_asr_volume, maker_max_{ask,bid}_trade_cost and, per quantile, maker_{ask,bid}_cost_quantile_q plus maker_{ask,bid}_trade_cost_quantile_q - deliberately no volume-quantile and no no-side quantile keys. Kyle's lambda SHALL use the maker-native signed-volume convention (bid maker +1, ask maker -1), which flips the coefficient sign relative to the taker version. ASR SHALL invert the taker sign convention (sign = +1 for a bid maker, -1 for an ask maker, so a bid maker is "right" when the price rises), otherwise keeping the 60-second look-ahead, the cross-bar (bar_end, bar_end + 60s] slice and the exclusion of empty-window fills. Empty or missing input SHALL emit the full panel with counts, costs and max_*_trade_cost at 0.0 and everything else NaN.

    Scenario: Side inversion¶

    • WHEN a raw fill carries taker side buy
    • THEN it is counted on the maker ask side, because the resting order that got hit was a sell

    Scenario: Maker ASR sign¶

    • WHEN the price rises within 60 seconds after an ask-maker fill
    • THEN that fill counts as adversely selected, the mirror image of the taker convention

    Requirement: Market-stats aggregation¶

    The system SHALL union the five market-stats partitions per symbol into one frame and expose open_interest, global_long_accounts, top_long_accounts, top_long_positions, daily_interest_rate as the latest non-null value per 30-minute bar (resample("30min").last()), forward-filled across short REST-polling gaps. The raw-column-to-metric map SHALL be open_interest -> open_interest, global_long_account_ratio -> global_long_accounts, top_long_account_ratio -> top_long_accounts, top_long_position_ratio -> top_long_positions, daily_interest_rate -> daily_interest_rate; the short-side columns the reader also coerces to float are NOT exported. A timestamp column, when present, SHALL be coerced to UTC and used as the index; each exported column SHALL be cast to float64 and dropna()-ed first, and a column that is absent or entirely null SHALL be omitted from the output (the container then fills that metric with NaN columns). Two forward-fills SHALL be applied and neither is redundant: resample("30min").last().ffill() closes NaN buckets interior to the source's own range (which a reindex-ffill cannot repair, since it only propagates existing labels), then reindex(grid).ffill() aligns to the canonical bar grid and fills the tail between the last observation and until. Strategies needing raw bucket values without ffill SHALL read the partition directly through RawDataReader.

    Scenario: Sparse poll gap¶

    • WHEN a REST poll is missed for one bar
    • THEN the market-stats metric is forward-filled, then continues with the next observed value

    Scenario: Partition absent for a symbol¶

    • WHEN the union carries no daily_interest_rate column (or only nulls) for a symbol
    • THEN the metric key is omitted from that ticker's panel and the container supplies an all-NaN column instead of a fabricated value

    Requirement: Orderbook updates diff counters¶

    The system SHALL provide OrderBookUpdatesAggregator, an observer registered on the parser's OrderBookManager that fires BEFORE the book mutates (so prev_size is visible), receiving (symbol, raw_data, prev_levels_snapshot, current_mid) with prev_levels_snapshot covering only the touched price levels (per-event cost O(diff_size)) and returning immediately when the payload carries neither b nor a entries. Each (price, qty) pair SHALL be classified into one of four cases: qty == 0 -> removal of the previous size; qty > prev_size -> placed volume qty - prev_size; 0 < qty < prev_size -> partial removal prev_size - qty; qty == prev_size -> no-op (Binance re-confirm); a brand-new price with qty == 0 (previous size 0 or less) is a fifth no-op that records nothing. A pair with the wrong shape or non-numeric price/qty SHALL be counted into a per-symbol dropped_pairs tally that does NOT mark the symbol dirty and SHALL be reported as a WARNING at flush ("counters are understated") rather than vanishing. Base counters SHALL accumulate cost = Sum price * delta, size = Sum delta and count = number of classified events. The aggregator SHALL accumulate per-bar diff counts and flush them on each bar boundary (flush_for_bar(bar_ts), whose bar_ts is accepted for symmetry with LiveRawDataReader.mark_bar_processed and unused), feeding the live bar evaluation in the trading runtime; flush_for_bar SHALL reset all counters itself while the separately callable mark_bar_processed stays available and idempotent, and snapshot(symbol) SHALL expose the running values without resetting (an unobserved symbol yields base counters 0.0 and every other key NaN). The flush SHALL emit all 180 metrics per observed symbol (12 base counters + 24 place VWAPs + 24 place-size skews + 120 remove quantiles, as enumerated by all_metric_names(); the module and flush_for_bar docstrings still quote a stale 82-metric / 10-VWAP count from a 5-offset era and the emitted schema, not the docstring, is normative): 12 base counters {bid|ask}_{place|remove}_{cost|size|count}, 24 VWAPs and 24 place-size skews {bid|ask}_{offset}_place_vwap / _place_size_skew over the 12 OFFSETS [0.01, 0.05, 0.1, 0.25, 0.5, 1, 2, 5, 10, 25, 50, 100] (imported from the orderbook aggregator, same . to _ labelling), and 120 remove quantiles {bid|ask}_{offset}_remove_quantile_{25|50|75|90|95}; the outer dict always carries all 180 metric names, but symbols with no diffs in the bar are absent from every inner dict (they are not zero-filled - downstream callers treat absence as "no signal this bar"), while a symbol with any activity gets all 180 keys including explicit zeros for the inactive side, since dirty-tracking is per symbol and never per side. Zone bucketing SHALL require a usable mid: a place lands in {side}_{X} iff price >= mid * (1 - X/100) (bid) or price <= mid * (1 + X/100) (ask), and when mid is None or non-positive, or the delta is non-positive, the per-zone accumulators are skipped while the base counters still increment. {side}_{X}_place_vwap SHALL be Sum price*dq / Sum dq within the zone and NaN when the denominator is zero; only places feed VWAP and skew, only removes feed the quantiles. _place_size_skew SHALL call scipy.stats.skew(bias=False) on the per-zone place-size list, returning NaN for fewer than 3 samples or near-constant input (std 0 or below 1e-12 * max(1, |mean|)); _remove_quantile_QQ SHALL be np.quantile at [0.25, 0.5, 0.75, 0.9, 0.95] and NaN when the zone saw no removal. The hot path (on_diff) SHALL be lock-free because the parser's WS dispatch is single-threaded by contract, while flush_for_bar and mark_bar_processed SHALL take the instance lock around snapshot-and-zero for cross-thread consumers; the per-zone sample lists are the only non-O(1) state and are cleared on every reset.

    Scenario: Level removal¶

    • WHEN a diff row carries qty == 0
    • THEN it counts as a full removal of the previous resting size at that level

    Scenario: Re-confirm no-op¶

    • WHEN a diff row's qty equals the previous size
    • THEN it is counted as a no-op and contributes nothing

    Scenario: No mid available¶

    • WHEN a diff arrives while the live book has only one side (mid is None)
    • THEN the 12 base counters still increment but no per-zone VWAP, skew or quantile sample is recorded for that event

    Scenario: Malformed depth pair¶

    • WHEN a depth pair has a bad shape or a non-numeric price/qty
    • THEN it is dropped, tallied in dropped_pairs, does not mark the symbol dirty, and is surfaced as a WARNING at the next flush

    Requirement: Backend-go precomputed metrics¶

    The system SHALL read already-aggregated 30-minute metrics written by Backend-go from Hive parquet ({root}/market={market}/type=metrics/dt=YYYY-MM-DD/symbol={SYMBOL}/part-*.parquet, market defaulting to spot) via GoMetricsStore, exploding each file's keys list (the canonical 791-key schema of metrics_engine/keys.py, (metric_name, float) pairs per bar, alongside the ts int64 epoch-millisecond and symbol columns; only ts and keys are actually read) into wide timestamps x tickers DataFrames exposed through the same dict-like interface the strategies use. Multiple roots SHALL be combinable: at load time every key is added to every root that carries it, and roots are loaded in order so a later root's values overwrite an earlier root's for the same key (last root wins - not first); a key carried by no root SHALL be served as a NaN frame with a warning (no KeyError - GoMetricsStore has no raise path for unpopulated keys), and that NaN frame SHALL be memoized in memory only, never written to the disk cache, so a later run over a root that does populate the key is not served an empty panel. An alias layer SHALL map alpha-engine names to Backend-go names, resolved by go_name in metrics_engine/keys.py: price-like aliases (close_price->close, open/high/low_price->open/high/low, last_price, vwap; on spot mark_price/index_price proxy to close while on any non-spot market they pass through to the real mark/index keys, because marking futures PnL at close diverges from how the venue values margin), flow aliases (volume->volume, volume_usd->quote_volume, buy_cost/sell_cost->buy_quote_volume/sell_quote_volume, and the quantile trade-size family where buy_cost_0.95, buy_cost_quantile_0.95 and buy_volume_quantile_0.95_usd all resolve to buy_volume_q95 for the q50/q95/q99 triple on both sides), the bid_/ask_ pattern {side}_{pct}_{feat}_{stat} to ob__{pct}pct__{side}__{feat}__{stat} over feat in cost|vwap|size|slope|imbalance|depth_ratio|levels_count|microprice and stat in avg|mean|median|min|max|sum|q95|skew with avg->mean (both _avg and __mean accepted) and price_like true only for vwap / microprice, and raw Backend-go keys pass through unchanged (go_name never raises despite its docstring). predicted_funding SHALL be served as an unconditional zero frame (spot has no such metric; a zero frame keeps the funding leg alive - it is never an alias or a NaN frame). realized_funding SHALL NOT be served as a plain alias: it is settled once per 8 hours on the 00/08/16 UTC bars only (FUNDING_SETTLEMENT_HOURS, matched on minute == 0), taken from the bar immediately before settlement (shift(1), NaN filled with 0.0), and zero elsewhere (so per-bar consumers charge each settlement period exactly once); spot datasets carry no funding key and fall back to an all-zero frame. Price-like metrics SHALL undergo zero->NaN->ffill: a 0.0 value in the Go writer means "not populated this bar", so GoMetricsDict replaces zeros with NaN and forward-fills for price-like keys (never surfacing 0.0 as a real price). GoMetricsDict SHALL expose reader = None, cache each resolved frame in itself, and offer preload(metrics) that resolves aliases (skipping zero-served names) and batch-loads their Go keys in one disk pass. GoExchangeData SHALL map both binance and binance-f exchanges to the SAME shared spot-backed GoMetricsDict instance, so futures metrics are proxied by their spot analogs, and SHALL preload its _PRELOAD list (close_price, open_price, volume_usd, vwap, mark_price, buy_cost, sell_cost, buy_cost_0.95, sell_cost_0.95, bid_25_cost_mean, ask_25_cost_mean, bid_25_vwap_mean, ask_25_vwap_mean, ob__minor__spread_bps__mean) at construction unless preload=False. This SHALL be the data provider for --metrics-roots backtests and the legacy live per-bar path.

    Scenario: Multi-root probing¶

    • THEN every root that carries a key is loaded, in order, so a later root overwrites an earlier root's values for the same key (last root wins), probed from sample files at initialization

    Requirement: Go metrics store discovery, caching and loading¶

    GoMetricsStore SHALL, at construction, keep only the roots whose market={market}/type=metrics partition exists (warning per skipped root) and raise FileNotFoundError when none does; select the dt= day directories overlapping the window with the same day + 1 day >= since and day <= until rule; discover symbols from the FIRST and LAST day directory only, intersect them with an explicit tickers list when given, union in extra_tickers (symbols served by other sources, carried as NaN columns so every metric shares one column set), and raise ValueError("No symbols found in the requested window") when the result is empty; and build the 30-minute UTC index over [since, until]. It SHALL probe which keys each root actually populates (_probe_nonzero) by reading the first symbol file of up to three day directories sampled at the ¼, ½ and ¾ positions of the window and marking every key whose value is neither 0.0 nor NaN - the Go writer emits the full key schema everywhere, zero-filled for groups it did not compute - exposing the result through has_key and populated_keys; an unreadable sample is skipped silently. Frames SHALL be cached on disk under cache_dir (default .metrics_cache) keyed by a sha1 over the root list, window, ticker list, a data fingerprint and the Go key, where the fingerprint is {shard_count}:{newest_mtime_ns} computed from directory stats only (so an in-place dataset rebuild invalidates every cached frame that a roots/window/tickers-only key would have served stale); a cached frame SHALL be accepted only when its columns and length still match, and a cache write failure SHALL be logged as a warning and otherwise ignored. Shard extraction SHALL run over a ThreadPoolExecutor (workers, default 8, chunksize=16), skipping unreadable shards with a warning; per symbol the collected {ts: value} map SHALL be converted with unit="ms", utc=True, deduplicated keeping the last value per timestamp, sorted and reindexed onto the bar grid, while a symbol with no rows for that key gets an all-NaN column. load SHALL deduplicate the requested key list and skip keys already materialised, so repeated preloads cost nothing, and shard listing SHALL visit only symbol= directories inside the store's ticker set - extra_tickers therefore always come back as all-NaN columns rather than being read. frame(go_key) SHALL lazily load a single key on demand.

    Scenario: Rebuilt dataset invalidates the cache¶

    • WHEN a metrics root is regenerated in place and the same window is requested again
    • THEN the shard-count/newest-mtime fingerprint changes, every cached frame key changes with it, and the data is re-read instead of served stale

    Scenario: No metrics partition¶

    • WHEN none of the supplied roots contains market={market}/type=metrics
    • THEN construction raises FileNotFoundError rather than yielding an empty store

    Requirement: Consumer contract for pipeline and live runtime¶

    The aggregation layer SHALL be consumed through one uniform dict-of-dicts view: data[exchange][metric] -> DataFrame(timestamps x tickers). AlphaPipeline SHALL require exactly one data source and raise ValueError when neither data_reader nor data_provider is given: with a RawDataReader it builds ExchangeData(reader, since, until, exchanges, tickers), with a prebuilt provider (e.g. GoExchangeData) it uses that container as-is. Strategy gating (filter_runnable, default exchange binance-f) SHALL call has_kinds / missing_kinds on the container and log a WARNING per skipped strategy naming its missing kinds, so a book-depth alpha never runs silently against an empty orderbook partition. run_strategies SHALL then best-effort batch-preload the union of the runnable alphas' required_metrics on data["binance-f"] when that container exposes preload (the Go container does; AggregatedMetricsDict does not), swallowing any failure at DEBUG so the lazy per-metric path stays the fallback. LiveEngine.step SHALL rebuild an ExchangeData over [bar_ts - lookback_days, bar_ts] on every bar boundary against LiveRawDataReader and call reader.mark_bar_processed(bar_ts) after a successful step. LiveRawDataReader SHALL implement the same RawDataReader interface over per-(exchange, kind, ticker) deques so the identical aggregators run live, emitting already-normalised column names: aggtrades -> kind="trades" rows [timestamp, price, size, side, agg_id, first_trade_id, last_trade_id]; raw @trade -> kind="trades_raw" rows [timestamp, trade_id, price, size, side] and ONLY when config.settings.LIVE_RECONSTRUCT_MULTILEVEL is true (unimportable settings default the flag off with a DEBUG line), so the canonical trades deque stays aggtrade-only; forceorder -> kind="liquidations" rows [timestamp, side, size, price] where size is the event's orig_qty (the live route differs from the offline normaliser, which prefers cum_filled_qty); closed klines only -> kind="klines" with volume_usd = close * volume; booksnapshot -> kind="orderbook" expanded to one long-format row per side/price/size; funding -> realized_funding; markprice -> [mark_price, index_price, predicted_funding, next_funding_time_ms]; depth diff updates are ignored (they are not snapshots). read SHALL evict rows older than since - eviction_grace, materialise the deque, tz-localise naive timestamps to UTC, filter [since, until] inclusively and return None when the buffer is empty or carries no timestamp column; retention SHALL default to a 60-day lookback plus a 1-day grace with a per-kind override capping orderbook at 1 day (full-depth 1 Hz books would otherwise be terabytes), with background eviction every 10000 buffered rows. bootstrap_from(MultiFileParquetReader, ...) SHALL warm-start the deques over trades, trades_raw, orderbook, klines, funding, markprice, liquidations, available_tickers SHALL report only symbols actually observed (uppercased), and events arriving with a timestamp before the last processed bar SHALL be counted as late and logged every 100 occurrences.

    • THEN it is filtered out of the run with a WARNING naming the missing kinds instead of producing all-NaN weights

    Scenario: Live and offline share the aggregators¶

    • WHEN LiveEngine.step builds an ExchangeData over the live reader
    • THEN the same aggregate_*_30min functions run on in-memory frames that already carry the normalised column names, so live and backtest panels are computed by identical code

    Scenario: Raw fills gated by the parser flag¶

    • WHEN LIVE_RECONSTRUCT_MULTILEVEL is false or unavailable
    • THEN raw @trade events are dropped instead of entering either deque, keeping the aggtrade-only invariant and leaving trades_v2 / maker_orders with empty panels
