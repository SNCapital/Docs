    Metrics Aggregation

    Purpose¶

    Defines the offline metric aggregation layer of alpha_engine (metrics/): raw data readers over the binance_parser parquet tree, the lazy metric container (AggregatedMetricsDict / ExchangeData) with its metric-to-group registry, and the per-kind 30-minute aggregators (klines / funding / markprice, trades, orderbook, liquidations, trades v2, multilevel, maker orders, market stats, orderbook updates). It covers the data contract shared by the batch backtester and the live runtime; real-time metric computation lives in alpha-engine/metrics-engine, and the live trading runtime in alpha-engine/live-trading.

    Requirements¶

    Requirement: Raw data readers and parquet layout¶

    The system SHALL expose a RawDataReader abstraction with read(exchange, kind, ticker, since, until) and available_tickers(exchange, kind). The primary MultiFileParquetReader SHALL read the Hive-partitioned layout {data_root}/market={spot|usdm}/type={event_type}/dt=YYYY-MM-DD/symbol={SYMBOL}/part-*.parquet, mapping alpha-engine exchange tags (binance, binance-f) to parser market= partitions and RawDataKind to the type= partition(s): aggtrades (lowercase, live writer) and aggTrades (camelCase, historical download) SHALL both resolve to the trades kind without double-reading; raw per-fill trades shards SHALL be a distinct kind (trades_raw) and never mixed into the aggregated trades stream; forceorder SHALL feed the liquidations kind; market_stats SHALL union five partitions (open_interest_now, global_long_accounts, top_long_accounts, top_long_positions, daily_interest_rate). The reader SHALL prune by dt= partition (keeping only days overlapping [since, until]) before reading any file and SHALL normalise columns per kind (e.g. liquidation size from cum_filled_qty, price from avg_price); the side is already lowercased by the parser DTO before the reader ever sees it (the reader does no case conversion). A ParquetFileReader SHALL additionally support the legacy flat layout data_root/{exchange}/{kind}/{TICKER}.parquet plus CSV and zip archives. MockRawDataReader SHALL generate structurally identical synthetic data for tests and --mock backtests.

    Scenario: AggTrades case-insensitive collision¶

    • WHEN both type=aggtrades and type=aggTrades partitions exist for a symbol
    • THEN they are read once as one trades stream instead of being double-counted

    Scenario: Raw fills stay separate¶

    • WHEN reading the trades kind
    • THEN raw per-fill type=trades shards are not mixed in, so aggregated and raw streams never double-count

    Scenario: dt pruning¶

    • WHEN a date range is requested
    • THEN only dt= directories overlapping the range are opened, and unparseable dt= names are skipped with a warning

    Requirement: Metric registry and lazy container¶

    The system SHALL expose every aggregated metric through a lazy dict-like container (AggregatedMetricsDict) indexed by a 30-minute UTC DatetimeIndex over [since, until]. First access to any metric from a group SHALL trigger aggregation of ALL metrics of that group for ALL tickers, and the group result SHALL be cached. Metric-to-group resolution SHALL be deterministic with a fixed precedence: an exact registry lookup (_METRIC_SOURCE over the ten *_METRICS registries), then the explicit liquidations_ prefix, the maker_ prefix, the aggressor_ / buy_aggressor_ / sell_aggressor_ prefixes, pattern rules for bid_/ask_ (cost/size/vwap/levels/spread/logreturn), best_, last_best_, liq_shock, vwap_*_midprice, buy_/sell_ with _ml/_sl (bare or _ml_quantile_ / _sl_quantile_ tags) routing to trades_multilevel and plain buy_/sell_ to trades, cost_imbalance, bid_ask_spread, the klines names (close_price, open_price, high_price, low_price, volume, volume_usd), the markprice names, and finally any name containing funding. A metric matching no source SHALL raise KeyError (never silently return a NaN frame), and a metric known to a group that its aggregator failed to produce SHALL also raise KeyError. Per-ticker Series SHALL be pivoted into timestamps x tickers DataFrames with NaN-filled gaps. ExchangeData SHALL wrap one container per exchange and SHALL support has_kinds / missing_kinds gating, returning fully permissive results when no reader is attached (mock mode).

    Scenario: Unknown metric raises¶

    • WHEN a metric name matches no registered source
    • THEN the container raises KeyError naming the metric rather than fabricating a NaN frame

    Scenario: Group-level caching¶

    • WHEN a second metric of an already-computed group is accessed
    • THEN it is served from the cache without re-aggregating

    Scenario: Missing ticker gap¶

    • WHEN a ticker has no data for a bar
    • THEN its column holds NaN for that bar, keeping the full-index shape

    Requirement: Klines, funding and markprice alignment¶

    The system SHALL aggregate the pre-aggregated kinds by alignment to the 30-minute grid: klines SHALL produce exactly close_price, open_price, high_price, low_price, volume, volume_usd; funding SHALL produce realized_funding; markprice SHALL produce mark_price, index_price, predicted_funding, next_funding_time_ms, reindexed onto the full bar grid with forward-fill so the metric stays alive across gaps. mark_price / index_price SHALL NOT be aliased to kline closes (each kind owns its metric names).

    Scenario: Markprice forward fill¶

    • WHEN mark-price rows are sparse
    • THEN the metric is forward-filled onto the 30-minute grid so later bars carry the last observed value

    Requirement: Trades aggregation¶

    The system SHALL compute 98 trade metrics per 30-minute bar from raw trades ([timestamp, price, size, side]): counts, volumes, quote volumes, per-side cost and size quantiles over the canonical set {0.25, 0.5, 0.75, 0.9, 0.95} (no 0.99), OHLC computed by averaging buy-only and sell-only open/high/low/close prices (NaN if one side is empty, killing bid-ask bounce), Herfindahl over size (base-coin units), intra-bar volatility as the std of minute-VWAP log returns with ddof=1 (NaN with fewer than 3 minute groups, because ddof=1 needs at least 2 returns to be finite), Kyle's lambda as an OLS of log-return on signed volume across minute groups (NaN with fewer than 3 groups or zero signed-volume variance), and ASR (asr_count / asr_volume) using a 60-second look-ahead window that may cross the bar boundary.

    Scenario: Buy-sell OHLC averaging¶

    • WHEN both sides have trades in a bar
    • THEN OHLC values are the average of the buy-side and sell-side first/last/max/min prices

    Scenario: Undefined volatility¶

    • WHEN a bar has fewer than 3 minute-groups with trades (with exactly 2 groups there is only one log-return, which ddof=1 cannot use)
    • THEN the volatility metric is NaN rather than a fabricated number

    Requirement: Orderbook aggregation¶

    The system SHALL compute orderbook metrics from L2 snapshot rows ([timestamp, side, price, size], one row per price level) with two aggregation templates: the 9-aggregation template for per-snapshot bases (_avg, _quantile_25/50/75/90/95, _skew as the bias-corrected Fisher-Pearson skew computed in closed form - value-identical to scipy.stats.skew(bias=False) with no scipy dependency, _min, _max, no _sum), and the 10-aggregation template for cross-snapshot diff/logreturn bases (_sum included, applying a zero-drop in addition to the NaN-drop). The liq_shock_{side}_{X} metrics SHALL be computed per snapshot as {side}_X_size[t] / mean({side}_X_size[t-W .. t]) with a fixed 10-second window inclusive of the current sample (one rolling window per side/offset, O(1) memory, no pandas dependency in the hot path), plus the liq_shock_ratio_{X} family = bid / (bid + ask) (NaN when either leg is NaN or both are zero) computed directly per snapshot - it shares only the 9-agg aggregation template, not the rolling window - all aggregated like any other 9-agg base metric.

    Scenario: Zero-drop on diff bases¶

    • WHEN a cross-snapshot diff base is aggregated
    • THEN both NaN and zero samples are dropped before computing quantiles and stats

    Scenario: Liq-shock ratio¶

    • WHEN a snapshot's zone volume diverges from its trailing 10-second baseline
    • THEN the liq_shock metric is the ratio of current zone volume to the rolling mean, with the current sample included in its own baseline

    Requirement: Liquidations aggregation¶

    The system SHALL compute 50 liquidation metrics per bar from normalized @forceOrder rows ([timestamp, side, size, price] where size = cum_filled_qty and price = avg_price, side lowercased by the parser DTO). The liquidation side SHALL be interpreted as the closing side (sell closes a long, buy closes a short). The metric pack SHALL include per-side counts, cost/notional totals and quantiles (no size or price quantiles), VWAP, OHLC, intra-bar volatility, Herfindahl, Kyle's lambda, and ASR - there are no imbalance keys and no size/price quantiles in the 50-key pack.

    Scenario: Closing-side semantics¶

    • WHEN a sell force order is aggregated
    • THEN it contributes to the sell-closing side, which closes a long position

    Requirement: Multilevel reconstruction¶

    The system SHALL reconstruct logical multilevel aggressions and maker fills from raw streams: trades_v2 SHALL rebuild per-aggressor fill detail by reindexing the raw @trade stream (kind="trades_raw") over the inclusive [first_trade_id, last_trade_id] range, skipping aggressors whose entire range is missing (no fallback to the aggregated price/qty); the historical download ships no per-fill source, so backtest-time reconstruction only works when the parser ran with LIVE_RECONSTRUCT_MULTILEVEL=True. trades_multilevel SHALL glue adjacent aggTrades into one LogicalTrade iff (strictly, epsilon 0) they share side and engine timestamp, B.first_trade_id == A.last_trade_id + 1, and price deepens monotonically along the hit side (up for buys, down for sells), emitting a 73-key ml/sl panel. The aggregator SHALL work when handed the aggTrade stream directly ([timestamp, side, price, size, first_trade_id, last_trade_id]), but AggregatedMetricsDict currently cannot serve this group end-to-end: its generic path reads kind="trades_multilevel", which has no entry in the reader's _KIND_TO_TYPES, so the Hive lookup targets a nonexistent type=trades_multilevel partition, every ticker is skipped, and accessing the group raises KeyError (the code comment claiming it "reads the same aggregated trades stream as trades" is stale). maker_orders SHALL treat each raw fill as exactly one maker fill (the resting limit-order side, the dual of the taker view), emitting a 50-key panel; it SHALL be gated to spot (emit_maker only when the exchange is binance) - on futures every ticker receives the deterministic empty panel at zero I/O cost, keeping the schema stable across venues.

    Scenario: Logical trade gluing¶

    • WHEN two adjacent aggTrades have the same side and timestamp, contiguous fill ids, and deepening price
    • THEN they are combined into one logical multilevel trade for the ml/sl metrics

    Scenario: Maker gating on futures¶

    • WHEN the exchange is not binance
    • THEN every ticker gets the empty 50-key maker panel without reading any raw data

    Requirement: Market-stats aggregation¶

    The system SHALL union the five market-stats partitions per symbol into one frame and expose open_interest, global_long_accounts, top_long_accounts, top_long_positions, daily_interest_rate as the latest non-null value per 30-minute bar (resample("30min").last()), forward-filled across short REST-polling gaps. Strategies needing raw bucket values without ffill SHALL read the partition directly through RawDataReader.

    Scenario: Sparse poll gap¶

    • WHEN a REST poll is missed for one bar
    • THEN the market-stats metric is forward-filled, then continues with the next observed value

    Requirement: Orderbook updates diff counters¶

    The system SHALL provide OrderBookUpdatesAggregator, an observer registered on the parser's OrderBookManager that fires BEFORE the book mutates (so prev_size is visible), receiving (symbol, raw_data, prev_levels_snapshot, current_mid) with prev_levels_snapshot covering only the touched price levels (per-event cost O(diff_size)). Each (price, qty) pair SHALL be classified into exactly one of four cases: qty == 0 -> removal of the previous size; qty > prev_size -> placed volume qty - prev_size; 0 < qty < prev_size -> partial removal prev_size - qty; qty == prev_size -> no-op (Binance re-confirm). The aggregator SHALL accumulate per-bar diff counts and flush them on each bar boundary (flush_for_bar(bar_ts)), feeding the live bar evaluation in the trading runtime.

    Scenario: Level removal¶

    • WHEN a diff row carries qty == 0
    • THEN it counts as a full removal of the previous resting size at that level

    Scenario: Re-confirm no-op¶

    • WHEN a diff row's qty equals the previous size
    • THEN it is counted as a no-op and contributes nothing

    Requirement: Backend-go precomputed metrics¶

    The system SHALL read already-aggregated 30-minute metrics written by Backend-go from Hive parquet ({root}/market=spot/type=metrics/dt=YYYY-MM-DD/symbol={SYMBOL}/part-*.parquet) via GoMetricsStore, exploding each file's keys list (~790 (metric_name, float) pairs per bar, plus ts and symbol columns) into wide timestamps x tickers DataFrames exposed through the same dict-like interface the strategies use. Multiple roots SHALL be combinable, with each metric read from whichever root actually carries it (probed at init from sample files). An alias layer SHALL map alpha-engine names to Backend-go names (close_price <- close, volume_usd <- quote_volume, and the ob__* namespaces pass through). This SHALL be the data provider for --metrics-roots backtests and the legacy live per-bar path.

    Scenario: Multi-root probing¶

    • WHEN several metric roots are given
    • THEN each metric is read from the first root that carries it, probed from sample files at initialization
