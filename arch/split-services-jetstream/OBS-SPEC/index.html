    OBS-SPEC — counter -> bar stamp -> Prometheus metric -> alert (wiring spec)¶

    Spec only: no exporter code exists (health.py "future exporter", pipeline_stats "intentionally excluded", no /metrics route, no rules files). Metric prefix (single, proposed): trading_ snake_case. _total = monotonic counter, _gauge/_info = point-in-time. Every numeric threshold TBD-soak except RTO 120s (replay_driver.py:43).

    Missing for Prometheus scraping (precise)¶

    1. Exporter process: no /metrics anywhere, no scrape target in compose.
    2. Metric names: all trading_* exist only in this spec; no prometheus_client counters/gauges.
    3. Rules files: no alerts.yml; §1 col (4) words-only; thresholds TBD-soak except RTO 120s.
    4. Counters to close first (else exporter ships zeros): windowed U/u/pu+agg + blind-sec loss-check + per-conn stamping (bars-contract items 3-4); num_pending probe loop; bars.* staleness drop + counter (needs bars.* consumer); 3-state + missing-shard (Q-004 build-all); replay outcome + end_seqs counters; Q-006 (b) filter + © E + counter + (d) minute bucket + counter + (e) mirror; bridge durable dedup_drops and slot_jump_drops into snapshot().
    5. Stamp-to-metric path: stamp rides "calc -> trader (marking) -> Prometheus (via trader)"; no calc publisher, no trader consumer, no stamp->counter mapping (D-003:7-8). Until bars.* flows, Prometheus exports collector-side + trader-side signals only, NOT per-bar quality.
