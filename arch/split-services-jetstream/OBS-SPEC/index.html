    OBS-SPEC — counter -> bar stamp -> Prometheus metric -> alert (wiring spec)¶

    Exporter + bridge exist now (common/metrics_exporter.py — enforces INV-E6-a name rules and supports counters, gauges, info, and histograms; common/metrics_bridge.py — HealthMetricsBridge publishing snapshot metrics and direct bounded observations); /metrics is mounted on the trader health server (trader/bars_service.py, health_port 8080), on calc's (calc/service.py, calc_health_port 8081) and on the archiver's (archiver/service.py, archiver_health_port 8083), and served by the collector via run_standalone_http_server (collector/services/live.py, port COLLECTOR_METRICS_PORT 8082); deploy/alerts.yml + tools/check_alerts_placeholders.py + CI alerts_placeholder_gate exist. pipeline_stats still "intentionally excluded". Metric prefix (single): trading_ snake_case. _total = monotonic counter, _gauge/_info = point-in-time. Every numeric threshold TBD-soak except RTO 120s (replay_driver.py:43) and the collector D9 buffer-fill early bound (TradingBufferFillHigh at >0.5, deploy/alerts.yml — deliberately below the process WARN edge collector_buffer_alert_ratio=0.7 in live_config.yaml so Prometheus fires before the log; the 1.0 overflow is the raw-drop/hole boundary, ADR-0002 §12 INV-003).

    Missing for Prometheus scraping (precise)¶

    1. Exporter coverage: /metrics is served on all four services — trader :8080, calc :8081, collector :8082, archiver :8083 (Prometheus scrapes all four). trader/consumer_lag.py probe loop runs in calc's TaskGroup (calc owns the durable calc-poller-* cursors; gauge emitted on calc :8081).
    2. Metric names: most spec names emitted (see metrics_bridge.py); still missing: trading_bar_incomplete_total{symbol,reason}, trading_replay_dedup_absorbs_total.
    3. Rules files: deploy/alerts.yml present; TBD thresholds = sentinel 999999999, gated in CI by alerts_placeholder_gate (tools/check_alerts_placeholders.py).
    4. Counters to close (else exporter ships zeros): replay-dedup absorb counter (6c, claim sites replay_driver.py:534/547); Q-006 (e) fallback-usage label (© E in liq MsgId, (c/d) crush counters and (d) minute bucket done); archiver-side late/dropped/row_lag metrics (exporter + staging-breach/s3/ack-age bridge done — the per-kind dicts are still not bridged into trading_* names).
    5. Stamp-to-metric path now real: calc publisher (calc/bars_publisher.py) -> bars.* -> trader consumer (trader/bars_consumer.py); stamp-derived counters land in trader health (record_bar_gap, record_blind_seconds, record_retention_hole, record_stale_bar_drop). Collector-side and calc-side per-bar quality metrics beyond that path are not emitted.

    Runtime observations (B3)¶

    Metric Owner Meaning and coverage
    trading_ingress_messages_total{market,kind} collector Every successful md.* JetStream publish, including recovered aggTrade messages.
    trading_ingress_lag_ms{market,kind} collector Histogram of received_ms - E when both values exist in the payload. REST poller rows without E still increment the message counter but do not enter this histogram.
    trading_ingress_clock_skew_total{market,kind} collector Published messages where received_ms < E; these are excluded from the lag histogram.
    trading_calc_bar_compute_seconds{symbol} calc Time spent in Engine.build_present_row for a live bar boundary; stamp processing and publish time are excluded.
    trading_replay_duration_seconds_gauge calc, trader Calc measures replay_on_boot; trader measures replay_bars_on_boot.
    trading_trader_step_seconds{service} trader Time in trader.step, including strategy and order submission work, excluding strategy-PnL persistence.

    Histogram boundaries are named constants in common/metrics_exporter.py: INGRESS_LAG_MS_BUCKETS and DURATION_SECONDS_BUCKETS. Histograms observe directly on the publisher/service path and retain no per-message sample list.
