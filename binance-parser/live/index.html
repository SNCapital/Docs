    Live WebSocket¶

    Real-time market data capture from Binance's WebSocket streams. Spot and USD-M futures share the same code; only the URL bases differ.

    Streams subscribed per symbol¶

    {symbol_lc}@depth        ← order-book diffs (in-memory only — see below)
{symbol_lc}@trade        ← individual trades
{symbol_lc}@aggTrade     ← aggregated trades
{symbol_lc}@kline_<i>    ← OHLCV at KLINE_INTERVAL (default 30m)

    KLINE_INTERVAL lives in config/settings.py.

    Order-book diffs are not written to parquet. They feed the in-memory OrderBook only. The book state is sampled into type=booksnapshot/ every 30 min UTC by OrderBookManager.snapshot_to_parquet_loop — that's the only source of order-book data on disk. See order-book.md for the full snapshot pipeline.

    The connection is one combined-stream socket per market — Binance multiplexes everything onto one URL of the form {WS_BASE}{a@depth/b@depth/...}. The listener loops async for raw in ws, parses, and forwards.

    Pipeline¶

    flowchart LR
  WS[Binance WebSocket] --> LIST[ws_client.listen]
  LIST -->|raw json| ENV[WsEnvelope.from_raw]
  ENV -->|MarketEvent dataclass| WR[FileWriter.write]
  LIST -.@depth raw.-> OB[OrderBookManager]
  WR --> BUF[per-event-type buffers]
  BUF -->|interval or size| FLUSH[flush]
  FLUSH --> PARQ[(Hive parquet)]

    WsEnvelope.from_raw dispatches by stream name:

    Stream suffix DTO event_type persisted?
    @depth (in-memory book) — no — book sampled into booksnapshot every 30 min
    @trade Trade trades yes
    @aggTrade AggTrade aggtrades yes
    @kline_<interval> Kline klines yes (closed bars only)

    Unknown streams raise UnknownStream (silently ignored — not every combined-stream payload is one we registered for). The book_manager side branch only fires on @depth and bypasses the DTO truncation because the book needs all levels.

    @trade vs @aggTrade¶

    The default subscription includes only @aggTrade, controlled by LIVE_PREFER_AGGTRADES in config/settings.py (NSC-14). @aggTrade is the aggregated tick stream — Binance pre-rolls simultaneous fills into a single message, which matches the format of the data.binance.vision historical archive (type=aggTrades shards), so backtest and live read the same partition.

    Subscribing to both @trade and @aggTrade would let the parser write to both type=trades/ and type=aggtrades/, but the alpha engine routes both event types into one in-memory kind="trades" deque — so the same fill ends up double-counted. To capture raw per-fill ticks (e.g. microstructure research) pass prefer_aggtrades=False to default_stream_names / listen; the alpha engine still reads only aggtrades.

    Reconnect policy¶

    The loop in listen retries on every kind of failure (ConnectionClosed *, OSError, WebSocketException, Exception). Backoff is exponential, capped at 60 s:

    backoff = 1
on disconnect:
    sleep(backoff)
    backoff = min(backoff * 2, 60)
on successful connect: backoff = 1

    There's no global retry budget — the loop runs forever. If you want to fail fast in dev, kill with Ctrl+C; the parser exits cleanly via KeyboardInterrupt in main.

    Writer¶

    live/writer.py::FileWriter is an async batched parquet writer. Records flow through await writer.write(market, record) → per-event-type in-memory buffers → flushed to parquet on either:

    • a buffer size threshold, or
    • a flush interval (FLUSH_EVERY_SEC in config/settings.py).

    Flush goes to per-bucket files: at flush time, buffered records are grouped by event UTC date and the bucket lands in the matching dt=YYYY-MM-DD partition. A flush that straddles midnight produces two output files in two dt= directories — neither one bleeds across days.

    data/market={market}/type={event_type}/dt={YYYY-MM-DD}/symbol={SYMBOL}/
    part-{HHMMSS}.parquet

    HHMMSS is the flush-start UTC time, so multiple flushes within one date co-exist as separate part-*.parquet files.

    Compression¶

    zstd level 3 by default (a fair memory / ratio trade-off for float32 prices and int64 ms timestamps). All schemas are declared as pa.Schema ClassVars on the DTO classes so the writer doesn't infer them at flush time.

    Mark price stream (USD-M only)¶

    When --market usdm is on, the WS listener also subscribes to <symbol>@markPrice@1s for every symbol. Each tick is persisted as a MarkPrice row with the real mark price, the spot index, the predicted next-settlement funding rate, and the timestamp of that settlement. The partition is data/market=usdm/type=markprice/.

    The alpha engine treats markprice as a first-class RawDataKind: the 30-min aggregator carries forward the last-known value at each bar boundary, so strategies see mark_price, index_price, predicted_funding and next_funding_time_ms directly without round-tripping through klines.

    Funding poller (USD-M only)¶

    live/funding_poller.py is a separate task. It hits https://fapi.binance.com/fapi/v1/fundingRate ~30 seconds past each UTC settlement boundary (00 / 08 / 16) and writes one FundingRateRow per symbol via the same FileWriter. This is the realised funding source of truth — it backfills the funding partition with the rate Binance actually settled at. The continuous mark-price WS stream above feeds the predicted funding (used by funding_reversion), so neither is a substitute for the other.

    Enable with --with-funding on a python main.py live --market usdm run.

    Health watchdogs¶

    Live-data-quality counters live in binance_parser/live/health.py and collect the four signals an operator needs (NSC-13):

    Counter Source Log level
    trade_id_gaps ws_client.listen — non-contiguous trade_id per symbol WARNING
    ws_reconnects ws_client.listen — outer connect-loop iterations WARNING
    book_force_resyncs OrderBookManager.watchdog_loop — quiet live or stuck resyncing book ERROR
    last_event_ts_per_symbol All paths — most-recent timestamp_ms per symbol (probe)

    The watchdog runs every 30 s and forces a re-bootstrap if a book has seen no diff in the last 30 s while live, or has been resyncing for more than 60 s. After a successful run on a stable network all three numeric counters should stay at zero; ticking up is the operator's cue that something upstream is wrong.

    HealthCounters.snapshot() returns a copy ready for a Prometheus exporter or a one-shot grep-style probe.

    Exchange-info poller (USD-M only)¶

    live/exchange_info_poller.py is a daily task started automatically whenever the live parser is launched with --market usdm. It polls /fapi/v1/exchangeInfo and /fapi/v1/leverageBracket once on startup and again at every 00:05 UTC, joins the two responses, and writes one row per symbol into

    data/market=usdm/type=exchange_info/dt=YYYY-MM-DD/symbol=…/part-*.parquet

    The row carries everything the future executor needs to round/validate orders without an extra REST call: tick_size, step_size, min_notional, headline max_leverage and maintenance_margin_rate, default maker/taker fees (USD-M VIP-0 until the account-fee endpoint is wired in) and the full leverage curve as a list<struct> column with {bracket, notional_cap, mmr, max_leverage}.

    Spot has its own filters but no leverage tiers, so the poller is USD-M-scoped for now.

    Local L2 order book¶

    Opt-in via --order-book. When enabled, OrderBookManager:

    • Bootstraps each book with a REST snapshot.
    • Replays buffered diffs in order.
    • Detects gaps (U != prev.u + 1), flips state to resyncing, and re-bootstraps from a fresh snapshot.

    Full algorithm in Local order book.

    A snapshot loop emits a BookSnapshotEvent to the writer at a configurable cadence (default 5 s in LIVE_ORDERBOOK_SNAPSHOT_INTERVAL_MS). These are what the alpha engine's orderbook aggregator consumes.

    CLI¶

    python main.py live [-h]
    [--market {spot,usdm,both}]    # default spot
    [--symbols SYMBOLS …]           # default config.settings.SYMBOLS
    [--order-book]                  # local L2 book + snapshot loop
    [--with-funding]                # 8h REST funding poll (usdm only)

    Examples:

    # Defaults: spot, all symbols, no book, no funding
python main.py live

# USD-M, two symbols, with funding
python main.py live --market usdm --symbols BTCUSDT ETHUSDT --with-funding

# Spot + USD-M concurrently with local L2 books
python main.py live --market both --order-book

    What you'll see in stdout¶

    [WS spot] Connecting to 20 symbol(s): BTCUSDT, ETHUSDT, SOLUSDT, BNBUSDT, XRPUSDT...
[WS spot] Connection established ✓
[Writer] Flushed 12,450 records to data/market=spot/type=trades/dt=2026-04-26/...

    Errors are printed to stdout too (no logging framework — keeps the parser stand-alone). Reconnects are noisy on purpose — silent re-connections are the worst kind of monitoring failure.
