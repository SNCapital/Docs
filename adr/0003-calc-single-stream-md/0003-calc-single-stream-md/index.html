    1. Overview¶

    Calc переходит с трёх JetStream-стримов (MD_DIFF/MD_TRADE/MD_EVENTS) и двухфазного replay-boot на один стрим MD с одним push-consumer: догон — это просто позиция consumer ниже tip, отдельного replay-режима нет. Ключевое свойство: скалярный курсор — это published-watermark (не consumed-tip), поэтому рестарт переигрывает ранние тики открытого окна вместо публикации partial-бара.

    2. Goals / Non-Goals / Deferred¶

    Goals:

    • G1. Один стрим MD (9 явных subject-паттернов), один consumer md.{market}.>, старт с cursor+1 или DeliverPolicy.ALL.
    • G2. Инварианты I1-I18 плана сохранены: каждая граница — бар или gap-marker; per-symbol вердикт replayed/hole/cold/skip, fail-closed.
    • G3. Wiring и deletion реализованы вместе в PR #106 для fresh deploy; эксплуатационный cutover требует проверок из RUNBOOK.

    Non-Goals: trader bars-path, BARS-контракт, supervision за пределами pump-side resubscribe, Go-parity suite.

    Deferred: точные числа (pending limits, K deque, MIN_DRAIN_RATE) — измерить на стенде в PR-5a; в плане только формулы.

    3. Constraints¶

    • JetStream отвергает overlapping subjects: старый и новый миры не сосуществуют — переезд односторонний, delete-first неизбежен.
    • nats.py: FC-ответы флашатся только через next_msg; js.subscribe kwarg затирает config.flow_control — оба факта load-bearing, закрыты pin-тестами, не доверием к версии.
    • Правила репо: TDD, ASCII-логи, без комментариев/docstrings, конфиг только через live_config.yaml.

    4. Context (C4-L1)¶

    Calc как чёрный ящик: вход — один consumer стрима MD (+ ephemeral pull-backfill для cold/add); состояние — PG (book_checkpoint, calc_stream_cursor, calc_stream_epoch); выход — bars.* + вердикты. Акторы: collector (пишет MD), trader/archiver (читают выход calc), оператор (процедура переезда, односторонняя).

    5. Containers (C4-L2)¶

    Ответственности: pump (один next_msg-loop: seq-tracker, dedup, pending-check, kind-dispatch, block-write в bus, gap-hook); bridge (consumption-барьер через bus-sentinel → bridge_drained); completion pass (вердикты → engine-flush до settled cutoff → publish expected ∪ settled drained + markers); boundary-clock + checkpoint-writer (hold до boot_published, одна транзакция на границу); catalogue-applier (pending-протокол для add/cold, асинхронно).

    6. Components¶

    Нетривиальная логика только в трёх местах: деривация watermark (deque + walk-back + fallback, D-A), pending-протокол (S-pin, tail-fetch, flush с dedup, D-B), poison-дезагрегация (D-C). Остальное — порты существующего кода (_publish_replay_rows, market_clock_ticks, checkpoint-слой) без смены семантики.

    7. Runtime¶

    Happy path boot: seed books → probes (cursor/epoch/first/last) → BY_START_SEQUENCE(cursor+1) → pump → triple-barrier drain_done → sentinel → bridge_drained → cold backfill/tail/flush → отдельный consumption sentinel → pass → boot_published → live. Failure paths: stall/cap → pump-fatal/raise (fail-closed, не молчание); poison-decode → quarantine+marker; poison-dispatch-шторм → fatal; chase-превышение на add → per-symbol skip, задача каталога живёт. Дедуп: Nats-Msg-Id (LiveDedup) + seen для backfill/fetched; буферные msgs входят в seen только на flush.

    8. Data¶

    PG: book_checkpoint без seq-колонок; calc_stream_cursor(market, shard_index) — published-watermark, монотонный guard verbatim, ON CONFLICT DO NOTHING на book_checkpoint-insert; calc_stream_epoch re-PK (market, shard_index), ensure в прод-пути. At-least-once доставка + идемпотентный publish (completed_bar_history upsert + retained-check, first-wins) = exactly-once эффект на барах.

    9. NFR + Scale¶

    Профиль: ~26k msg/s peak во время pass; bus 10k; pass — минуты (775 символов × ~96 баров × publish-RTT). Механизмы: bounded yields в pass, pending-limits = peak_rate × worst_pass_duration, flow-control pacing, SlowConsumer→fatal как последняя линия (не downgrade в маркеры). Первым при ×5 ломается связка pass/pump (рестарт-ретрай, не потеря).

    10. Decisions¶

    D-A. Курсор — published-watermark, не consumed-tip¶

    • Status: accepted.
    • Context: last_stream_seq на границе уже содержит тики окна (B, B+W], прилетевшие по skew раньше wall-clock B. Коммит consumed-tip заставляет рестарт терять ранние тики открытого окна.
    • Decision Drivers: корректность рестарта (главное); цена — bounded deque + walk-back (дешево); parity-аргумент отвергнут (тащить баг — не паритет).
    • Options: (1) consumed-tip + доказательство паритета — отвергнуто: per-subject курсоры сегодня имеют тот же дефект, чиним не тащим; (2) per-window max-seq учёт в drain_rows — отвергнуто: тяжелее deque, тот же эффект; (3) deque (seq, tick_ts) пост-decode + walk-back — принято: минимальная machinery с тем же свойством.
    • Decision: pump держит deque последних (stream_seq, tick_ts), глубина calc_watermark_skew_s (~3x наблюдаемого skew); cursor_seq = seq первого entry с ts > bar_ts, минус 1; fallback — snapshot на старте boundary-итерации + watermark_fallback_total.
    • Consequences: рестарт переигрывает ранние тики открытого окна — окно собирается целиком; residual skewed-straggler дыра сжимается до величины skew, класс не закрывается (принято явно).
    • Re-evaluation Trigger: если fallback-метрика горит хронически — K мал или skew вырос.

    D-B. Wiring и deletion для fresh deploy¶

    • Status: revised by PR #106, 2026-09-28.
    • Context: исходный план разделял wiring (5a) и deletion (5b). PR #106 реализует оба шага вместе и предполагает пустую PG/JetStream-инфраструктуру.
    • Decision: старый replay-код и per-symbol cursors удалены в этом PR. Миграция живых старых стримов/таблиц не поддерживается. Merge не означает deployment; stop-first, создание новой инфраструктуры и проверки boot/quality выполняются отдельно по RUNBOOK.
    • Consequences: промежуточного режима со старым кодом нет. Rollback и утрата прежней истории при fresh deploy требуют отдельного эксплуатационного решения.
    • Re-evaluation Trigger: нужен in-place upgrade с сохранением старого состояния — сначала проектировать миграцию, затем выполнять cutover.

    D-C. Poison-дезагрегация вместо uniform-fatal¶

    • Status: accepted.
    • Context: под AckNone NAK нет; uniform-fatal на любом dispatch-исключении превращает детерминированный poison-msg в crash-loop (переигрывается каждый re-drain с некоммиченного курсора).
    • Decision Drivers: fail-visible всегда; crash-loop никогда за детерминированный вход; системный сбой должен орать, не маркировать.
    • Options: (1) fatal на всё — отвергнуто: crash-loop на poison; (2) skip-with-marker на всё — отвергнуто: системный engine-сбой тихо маркируется; (3) дезагрегация — принято.
    • Decision: DECODE-исключение — quarantine немедленно (N=1): skip + marker + poison_msgs_total + alert, seq-tracker идёт за poison-seq; DISPATCH — rate-breaker calc_poison_rate_per_min (default 30) → pump-fatal. Массовый decode-баг = маркеры + алерт-шторм, не crash-loop (честный fail-mode, принят явно).
    • Consequences: детерминированный яд isolated; порог breaker'а — стендозависимый тюнабл в yaml.
    • Re-evaluation Trigger: если алерт-шторм при декодер-деплое неприемлем операционно — добавить канареечный гейт деплоя, не менять механику.

    D-D. Ordered state owner and paired bounded recovery¶

    • Status: selected revision-4 candidate, 2026-09-30; F1 resource acceptance remains open. The deployed path above is unchanged until the integrated release passes F1-F6.
    • Evidence: paper-finish design records actual callers, remove/replace/keep, state/event/action/position/barrier/failure transitions, ordered full-key/stamp equality, paired warmup and resource probes. Storage evidence distinguishes steady native storage and contingency restoration. Component results do not certify simultaneous production acceptance.
    • Decision: one ordered USD-M owner uses the official public ephemeral AckNone pull API, one outstanding request and bounded raw/decoded batches. Depth application, book scalar sampling, metric/funding transition and stamp commit finish before the next event. REST IO returns an immutable symbol/generation result; only the owner changes book state. Boundary, completion and catalogue commands run between complete transitions. New pulls pause during owner IO; durable backlog remains in MD.
    • Remove: calc-only bus intake/subscription, bridge driver task, drain sentinels, bridge-drained flags and separate pending/cold raw queues together with the asynchronous section they guarded. Preserve shared bridge/bus callers, the single metrics implementation, completion verdicts, retained-bar authority and settlement. SDK/TaskGroup and existing runner own transport/lifecycle; no actor framework or alternate live/replay engine.
    • Position: fetched is instrumentation, applied advances only after a whole transition or explicit terminal discard, and the existing PG cursor remains persisted publication authority. Reconnect of the same owner starts at applied+1. A process crash reconstructs from PG, not broker delivery. Unknown partial state terminates; failed application is not committed into dedup. Spot interleaving makes numeric USD-M sequence gaps legitimate.
    • Recovery cut: supersede D-A's later-book/older-watermark pair in the candidate. At one ordered sequence cut S, freeze eligible books with their cut sequence/epoch and the bounded effective market head, book sample state and pending funding domain state needed for exact reconstruction. Publish required settled outputs before committing this generation and publication cursor in one existing PG transaction. No Python heap serialization and no new durable cursor store.
    • Restart seed: choose a common older paired generation R from retained existing checkpoint rows, beneath persisted publication authority S. Seed books/domain state at R before replay R+1. A first missing bar needs a complete engine window plus liquidation-tail/skew overlap; newest-valid per-symbol snapshots cannot be mixed with an older scalar cursor. Replay once through MD with fresh engines; retained valid warmup bars remain authoritative. Missing/unpaired generation, epoch reset or expired source produces the explicit existing hole/cold outcome, never a fabricated complete bar.
    • Completion: retain full-horizon completed rows for this candidate because the measured 100-symbol, 48-window retained state fits the component budget. Intake pauses for verdict/publication; completed apply replaces the bus barrier. Readiness waits for whole drain, all symbol verdicts, settlement and final post-pass lag/catchup. Empty or expired fetch alone cannot release boot. Real service recovery/crash and simultaneous state peaks remain F6 gates.
    • Dedup: preserve identity semantics with measured bounded OrderedDict storage and commit after successful apply. No new cache or journal. Historical presence stamps need no duplicate identity sets when admission already establishes uniqueness; shared external stamp API remains intact. Any ownership consolidation needs a regression proving equal stamps, not a blanket removal.
    • Resource gate: decimal whole-stack normal <=10,000,000,000 bytes, peak <=12,000,000,000, including charged cache and archive merge/upload, with host MemAvailable >=2,147,483,648. Current candidate shares remain unaccepted until the cache/full-collector terms are measured; F6 verifies simultaneous peak and return to steady. Preserve configured 1.3 GB collector accounting, source coverage, books, history and risk semantics.
    • Ownership: Sol low owns calc pump/service/completion and shared bridge extraction in sequential 2a/2b/2c work; complex archive ownership covers cohort decode and writer/closure ACK serialization. Sol medium integrates schema/config/overrides/ADR and independently accepts. No component deployment; one pinned release after F1-F6.
    • Re-evaluation: failed service surplus/retention margin, full retained-state or simultaneous resource gate requires a concrete revised decision before release. Do not quietly activate more shards, drop completed history, reduce top-N or add a healing framework.

    11. Risks + Failure Modes¶

    • Pass/pump contention на одном loop (26k msg/s): восстановление — честный рестарт-ретрай с некоммиченного курсора; класс — retry, не потеря. Митигация первична (yields+limits), fatal — последняя линия.
    • 40-мин outage → длинный drain → cold-буферы: восстановление — fail-closed skip с вердиктом; класс — видимая деградация. Сайзинг формулой peak × backfill-duration, не словами.
    • slot_jump_drops на seq-order drain: восстановление — jumped-окна в drain_jumped_boundaries → gap-markers, не partial-бары.
    • Split-brain два calc: не детектится (как сегодня) — msg_id dedup + first-wins; худшее не стало.
    • Graceful shutdown мид-txn: cancel = abort, cursor некоммичен → re-drain; НЕ shield'ить.

    12. Observability¶

    Каждый инвариант виден: вердикты — trading_replay_outcome_total; retention — retention_hole_total; reset — stream_reset_total; длительность — replay_duration_seconds_gauge + trading_rto_violation_total; прогресс — calc_drain_pending, calc_caught_up_symbols; watermark — watermark_fallback_total; poison — poison_msgs_total; chase — catalogue_chase_exceeded_total. Имена trading_replay_* сохранены, продюсеры переподключены в PR-5a вместе с алертами (продюсер и потребитель лейблов — один PR).

    13. Security¶

    Не применимо: изменение read-path внутри доверенной зоны (коллектор → NATS → calc → PG/BARS). Trust boundaries, auth, секреты — без изменений от ADR-0002.

    14. Glossary¶

    drain (позиция consumer ниже tip, не режим); tip (последний retained seq); watermark (max seq полностью опубликованных окон); pass (completion pass); S-pin (фиксация last_stream_seq в момент buffer-ON); chase (добор окон, закрывшихся во время add-pass, bound N=2); quarantine (skip poison-msg + marker); Cold/hole/replayed/skip (вердикты pass, fail-closed).

    15. Review corrections, 2026-09-28¶

    • Backfill and pending flush each await a fresh consumption sentinel before completion or catalogue activation. Sentinels carry separate asyncio events; overlapping waiters cannot acknowledge one another's work.
    • Funding travels through the same bus as market events. Calc buffers funding until the market clock reaches it, then applies it before advancing to the next market tick. Old context is clamped to the first/current market tick; funding-only input never starts the engine clock. The buffer retains the 64-record bound and is cleared when a catalogue symbol is removed.
    • Completion flushes and publishes only windows at or before the settlement cutoff. Captured later rows survive pending finalization and are consumed by the live boundary publisher.
    • Decode quarantine uses X-Gap-Count/X-Gap-Lost and the payload's event time when available. A missing timestamp uses the symbol's last market time, then wall clock when no market event has been observed.
    • Startup RTO is measured only while draining and counted once on deadline crossing. Live probes continue updating pending gauges.

    Repeat review also verifies boundary rollover during the completion chase: newly settled engine windows are flushed before the next publication sweep, avoiding false gap markers.

    Live boundary publication releases captured rows older than the boundary, including delayed rows captured after their publication, while retaining future unsettled rows.
