    ADR-0001 — замеры потоков Binance¶

    Все цифры ниже — измеренные, не расчётные. Методика, сырые итоги прогонов, максимальные периоды подписок и экстраполяции на 60/600 символов. Дата live-сессии: 2026-09-03, активный рынок. Скрипты: инлайн python -c и live_capture*.py (временная директория, в репо не входят); воспроизведение — подпиской из §2 на те же стримы на ту же длительность.

    1. Офлайн-замеры (без сети)¶

    Окружение: Python 3.12, Windows. Фикстуры binance_parser/tests/test_models.py.

    1.1 Размер сырого JSON WS-envelope {stream, data}¶

    Поток Средний размер
    diff (2bid+1ask) 188 Б spot / 196 Б usdm (+8 Б за pu)
    diff параметрически (/сторону) 1 ур. ~175 Б, 5 ур. ~345 Б, 10 ур. ~555 Б, 20 ур. ~975 Б, 50 ур. ~2235 Б
    aggTrade 169 Б (живьём 203–205 Б — в фикстуре короткие числа)
    trade 159 Б
    kline closed 1m 295 Б (живьём 335–349 Б)
    markPrice 179 Б (живьём 207–223 Б)
    forceOrder 224 Б (живьём 242–247 Б)

    1.2 Скорость парсинга/применения (синтетика, медиана 5 повторов)¶

    Операция Медиана
    json.loads + извлечение data.u (diff 3bid+2ask) 3.78 мкс/сообщ. (n=20000)
    json.loads + WsEnvelope.from_raw (aggTrade) 4.87 мкс/сообщ. (n=20000)
    OrderBook._apply_levels (diff 3 уровня) 2.82 мкс/сообщ. (n=20000)
    Полный pipeline diff 5 уровней 8.68 мкс/сообщ. (n=5000, ~115k дифф/с в микробенче)

    Без WS, сети, NATS и observer-цепи (_fire_diff_observers, TODO(NSC-51)); с цифрой §9 «17 мкс» — один порядок.

    2. Live-замеры WS¶

    2.1 Прогоны¶

    # Профиль Символы Длит. msg/s Байт/s
    L1 unrouted .../stream?streams= depth+aggTrade+mark+kline+forceOrder BTC,ETH,ADA 68 с 10.0 (только depth!) 38 КБ/с
    L2 unrouted depth BTC 30 сообщ. только depth —
    L3 /market aggTrade+mark+kline+forceOrder BTC 40 сообщ. 39 aggTrade + 1 kline —
    L4 /market 13 стримов BTC,ETH,ADA 90 с 36.7 8.3 КБ/с
    L5 /public depth + /market depth (проверка роутинга) BTC — depth только на /public —
    L6 /public depth BTC,ETH,ADA,SOL,DOGE 600 с 19.34 48.2 КБ/с
    L7 /market aggTrade+mark+kline+forceOrder BTC,ETH,ADA,SOL,DOGE 600 с 48.29 11.2 КБ/с
    L8 /public depth@500ms BTC,ETH 45 с 4.0 36.5 КБ/с
    L9 /market markPrice без суффикса BTC,ETH 30 с 0.667 145 Б/с

    L1 — артефакт до понимания роутинга (см. §4): не смешивать с остальными.

    2.3 Market-стримы, 10 мин (L7)¶

    Стрим BTC ETH SOL DOGE ADA mean Б
    aggTrade /s 15.9 10.3 3.7 2.5 1.8 ~204
    markPrice@1s /s 1.00 1.00 1.00 1.00 1.00 ~215
    kline_1m running /s 2.40 2.16 1.96 1.36 1.17 ~343
    forceOrder /10 мин 9 1 1 1 5 ~245

    Running kline код дропает (в очередь только closed 1/мин/символ). Итого market на 5 символов: 48.29 msg/s, 11.2 КБ/с; в очередь (без running): ~39 msg/s, ~8.1 КБ/с.

    3. Максимальные периоды подписок (принятый профиль)¶

    Стрим Было (код) Макс. период Замер эффекта
    depth (USD-M) голый @depth (= 250 мс веню) @depth@500ms ровно 2/s (L8); байты/s те же (BTC 22.5 vs 21.2, ETH 13.9 vs 15.9 КБ/с — шум активности)
    markPrice @markPrice@1s голый @markPrice (= 3 с) ровно 0.333/s (L9), ~218 Б/сообщ.
    kline kline_1m, только closed без изменений: интервал — контракт данных для стратегий, не свободный рычаг closed 1/мин/символ
    aggTrade всегда без изменений: trade-driven, ручки нет —
    forceOrder всегда (usdm) без изменений: снапшот 1 с, событие редкое 17 шт/10 мин на 5 символов

    Эффект максимального периода: msg/s режется (diffs 4/s → 2/s, mark 1/s → ⅓s), байты/s почти не меняются (апдейт несёт больше изменений). Выигрыш — на per-message бюджетах (publish ~22k/s, consume ~26k/s, парсинг), не на трафике. Применение в коде: суффикс @depth@500ms + голый @markPrice (2 строки + обновление тестов подписок) — на момент замера НЕ внесено, числа ниже даны для обоих профилей.

    4. Роутинг fstream (критично для кода)¶

    С 2026-03-06 (legacy retired 2026-04-23) wss://fstream.binance.com без пути отдаёт только Public (@depth). Проверено: L1/L2/L5. Код (binance_parser/config/settings.py:25-26) использует unrouted base — на фьючерсах приходил бы только depth. Нужно два соединения: /public для depth, /market для остального (/market depth не отдаёт — проверено таймаутом). Spot (stream.binance.com:9443) работает полностью без роутов (проверено: depth 1/s + aggTrade + kline).

    6. Экстраполяции в очередь (без running kline, без booksnapshot)¶

    Измеренная база на символ: depth ~3.9 msg/s (дефолт) / 2.0 (max-период), market ~7.9 msg/s (из них mark 1/s, closed kline ~0.017/s). Микс 60 символов: 10 мажоров (~22 КБ/с) + 50 альтов (~5 КБ/с).

    5 измеренных 60 символов 600 символов
    msg/s, дефолт подписок ~59 ~500–600 (240 diffs + 60 mark + ~240 trades) ~5000–6000
    msg/s, max-период — ~380 (120 diffs + 20 mark + ~240 trades) ~3800
    Байты/s (оба профиля, ±активность) ~56 КБ/с ~250–450 КБ/с ~2.5–4.5 МБ/с
    Сутки сырья ~2.9 ГБ ~22–40 ГБ ~220–400 ГБ
    Буфер D9 (1 ч) ~200 МБ ~1–1.6 ГБ RAM н/п

    Живой поток 6000 msg/s @600 — в 4+ раз ниже потолка реплея 26k/s/процесс; выводы §9 по RTO не меняются.

    7. NATS JetStream (перепроверено)¶

    Стенд: nats-server v2.10.27 windows-amd64, стоковый конфиг, file storage, loopback; клиент nats-py (pip, сентябрь 2026), Python 3.12, Windows. Payload 500 Б (~530 Б на проводе, как датасет ADR §9). Скрипт: nats_bench.py (временная директория). Сырые итоги — nats_bench.json.

    # Утверждение ADR §9 Перезамер Вердикт
    N1 limits: ack не удаляет (500/500); workqueue: ack удаляет (0/500) limits: после ack осталось 500, get_msg(seq=1) OK; workqueue: осталось 0, seq=1 → 404 подтверждено точно
    N2 Веер 0.7–0.8 мс/консьюмер до 1200, доставка полная, 11–25 КБ памяти/шт 2.3–2.6 мс/шт (60/200/600/1200, 1200 за ~3.2 с), доставка OK везде, ноль ошибок; память по /varz на Windows не различима (нули) тот же порядок (×3 медленнее — Windows + новее клиент); вывод «шторма нет» в силе
    N3 Доставка ~31k/s без заголовков, ~26k/s с Nats-Msg-Id (цена 14%) 31.1k/s без, 26.9k/s с заголовком (20k сообщ., batch 500) → цена 13.4% подтверждено почти в цифру
    N4 Публикация ~22k msg/s/процесс медианы 3 повторов по 10k: 18.7–23.9k/s (разброс между повторами ±15%) подтверждено; штраф заголовка не воспроизвёлся (в шуме) — планировать по нижней границе
    N5 Держать бар un-acked: 955 Б/сообщ. (413 МБ @60, 4.1 ГБ @600) ~352 Б/сообщ. RSS (20k unacked, tasklist) → ~152 МБ @60, ~1.5 ГБ @600 порядок тот же, вывод D5 не меняется (всё равно нет места рядом с трейдером и PG)

    8. Что не измерено здесь¶

    • Уникальность forceOrder-композита за 7 дней (блокер D7).
    • Набор глубины после холодного старта (граница «недостоверны»).
    • booksnapshot-партиция (48 full-depth/сутки/символ) в суммы выше НЕ входит.
