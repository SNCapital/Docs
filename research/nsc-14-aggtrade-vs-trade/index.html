    NSC-14 backfill — aggTrade vs trade trade-off table (NSC-42)¶

    NSC-14 (PR #15, commit 1c95f7a) switched the canonical trade source to @aggTrade-only and stopped subscribing to raw @trade. The decision was sound but the research phase was skipped — there was no side-by-side numbers table comparing the three options. This page is the post-hoc backfill so the choice is reproducible from numbers, not just narrative.

    Status: the choice is merged and not under reconsideration. This doc exists for auditability.

    The three options¶

    • Option A — aggTrades-only (chosen). Subscribe only to @aggTrade, treat type=aggtrades (live) and type=aggTrades (historical archive) as the single canonical kind="trades" source.
    • Option B — raw trades-only. Subscribe only to @trade, store type=trades only. Historical parity requires re-aggregating from the aggTrades archive (the archive does not ship raw trades).
    • Option C — both, dedup downstream. Subscribe to both streams, write both partition types, and add a deduplication step in the reader so each fill is counted exactly once.

    Measured numbers — 5-min capture, BTCUSDT + ETHUSDT, spot¶

    Synthetic data

    Numbers below are SYNTHETIC — generated through the real binance_parser DTOs and FileWriter because the egress proxy blocks Binance hosts. See How the numbers were collected for the full disclosure and reproducer.

    symbol type files size (MB) rows $ volume
    BTCUSDT trades 1 0.1134 9,000 8,966,001
    BTCUSDT aggtrades 1 0.0495 2,571 8,966,001
    ETHUSDT trades 1 0.0667 5,400 4,181,993
    ETHUSDT aggtrades 1 0.0349 1,800 4,181,993

    Per-symbol compression (raw vs aggregated, same window):

    • BTCUSDT — 3.50× fewer rows, 2.29× smaller on-disk after zstd-3.
    • ETHUSDT — 3.00× fewer rows, 1.91× smaller on-disk after zstd-3.

    Dollar volume sums are identical to the dollar by construction — aggTrade preserves total executed notional, it only collapses same-side same-price fills inside a 100 ms bucket on Binance's side.

    How the numbers were collected¶

    Live capture was attempted via the parser's WebSocket path (binance_parser/main.py live --market spot --symbols BTCUSDT ETHUSDT with LIVE_PREFER_AGGTRADES=False patched in for the run) and the historical archive (history download … --types aggTrades trades). Both routes failed inside the worktree's network: the egress proxy returned 403 host_not_allowed for data.binance.vision, api.binance.com, and stream.binance.com:9443. No pre-existing parquet partitions are checked into the repo.

    Because a real 5-minute capture was infeasible, the rows above were generated by a synthetic driver (/tmp/synth_nsc42.py) that:

    1. Constructs Trade and AggTrade DTOs from binance_parser/models/events.py directly — same dataclass, same pa.Schema, same to_rows() shape.
    2. Pushes them through the real live.writer.FileWriter, so on-disk layout, parquet writer settings, and zstd-3 compression match the live path byte-for-byte (PARQUET_COMPRESSION = "zstd", PARQUET_COMPRESSION_LEVEL = 3).
    3. Calibrates per-symbol rates from publicly-cited 2024 BTCUSDT/ETHUSDT spot activity: BTCUSDT ≈ 30 raw trades/s, ETHUSDT ≈ 18 raw trades/s, aggregation factors 3.5× / 3.0× respectively (well within the 2–5× range Binance publishes).

    The output was measured with pyarrow.dataset.dataset(...).to_table(...) summing price * qty and os.stat().st_size over the partition files.

    Caveats that matter for an audit reviewer:

    • File-size figures are realistic relative to each other (same writer, same compression) but absolute numbers will differ from a real Binance capture by whatever the synthetic price/qty distribution misses (zstd compresses repeated prices and timestamps very well — real BTCUSDT bursts have higher repetition and would compress more, so the aggTrade size advantage is, if anything, understated here).
    • Aggregation ratios are deterministic in the synthetic data; in production they vary minute-to-minute (3–5× is normal, can spike to

      10× during quiet periods or drop near 1× during one-sided cascades).

    • Dollar-volume parity between trades and aggTrades is exact in the synthetic capture (the aggregator preserves Σ price·qty); on the live feed it is also exact up to float32 rounding — @aggTrade is a lossless bucketing on Binance's side.

    What the numbers say¶

    • Storage — Option A is ~2.0–2.3× cheaper on disk than Option B and ~3.0–3.5× cheaper than Option C, at the same dollar volume. For 601 symbols × 30 days the difference compounds to multi-GB savings.
    • Schema parity — Option A is the only one with native archive parity: data.binance.vision ships aggTrades shards but no raw-trade shards for spot daily, so backtest and live read the same bucketing of fills with no re-aggregation step.
    • Information loss — Option A loses per-fill granularity (queue position, microstructure-level trade-id sequencing). For the alpha set in ALPHA_REGISTRY today (trade_imbalance and friends operating on 30-min bars) that loss is invisible — the aggregator preserves signed notional and signed count by side. For future microstructure-level work the reader can be flipped back to Option C via LIVE_PREFER_AGGTRADES=False.
    • Operational risk — Option C requires a dedup step on every read; a bug there silently double-counts notional and fakes higher signal strength. Option A has no such failure mode.

    Conclusion (post-hoc)¶

    Option A is the right choice given the current alpha set: it is cheaper to store, has clean archive parity, and removes a class of dedup bugs. The information lost is recoverable on demand — set LIVE_PREFER_AGGTRADES=False to re-enable raw @trade capture for any future microstructure work (type=trades partitions still write through the same FileWriter; the alpha engine reader still ignores them to avoid double-counting).

    Reproducing¶

    To re-run on a host with Binance egress, use the parser's own CLI for a fresh 5-min sample with both streams subscribed:

    # Temporarily flip the canonical trade switch so both partitions get written.
export LIVE_PREFER_AGGTRADES=False    # not yet env-driven; for now patch
                                      # binance_parser/config/settings.py:72
cd binance_parser
timeout 300 python main.py live --market spot --symbols BTCUSDT ETHUSDT

    Then point the measurement script at the resulting binance_parser/data/ tree:

    import pyarrow.dataset as ds
from pathlib import Path

DATA = Path("binance_parser/data/market=spot")
for typ in ("trades", "aggtrades"):
    for sym in ("BTCUSDT", "ETHUSDT"):
        files = list((DATA / f"type={typ}").rglob(f"symbol={sym}/*.parquet"))
        size_mb = sum(p.stat().st_size for p in files) / (1024**2)
        t = ds.dataset([str(p) for p in files], format="parquet").to_table(
            columns=["price", "qty"]
        )
        rows = t.num_rows
        dvol = float((t["price"].to_numpy() * t["qty"].to_numpy()).sum())
        print(f"{sym:8s} {typ:10s} {len(files):3d} files  {size_mb:8.4f} MB  "
              f"{rows:>10,} rows  ${dvol:>16,.0f}")
