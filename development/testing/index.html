    Testing¶

    Unified test layout. One command from the repo root runs everything.

    Running¶

    pytest                                 # all 100 tests
pytest -v                              # with names
pytest tests/test_pipeline.py          # alpha engine pipeline only
pytest binance_parser/tests/test_orderbook.py -v   # parser order book only
pytest -k markowitz                    # by keyword

    pyproject.toml declares:

    [tool.pytest.ini_options]
testpaths = ["tests", "binance_parser/tests"]
addopts  = "-ra --strict-markers"

    conftest.py (repo root) injects binance_parser/ onto sys.path so the parser's bare imports resolve from any CWD — see Setup.

    What's covered¶

    tests/test_pipeline.py — pipeline plumbing¶

    TestMockMetrics       — Layer 1 lazy access, shape consistency, caching
TestOperators         — normalize / trunc_normalize / rank / norm_ratio
TestAlphaStrategies   — every alpha in ALPHA_REGISTRY produces sane weights
TestMarkowitz         — _solve_markowitz failure modes + shape
TestPipeline          — end-to-end run, summary, allocations sum to 1
test_pipeline_requires_data_reader — pipeline raises if data_reader=None

    The pipeline fixture is module-scoped — pipeline runs once per test session, all TestPipeline methods reuse it. Fast.

    tests/test_aggregators.py — Layer 1 / Layer 2 correctness¶

    Trade aggregator, orderbook aggregator, market data aggregator, the lazy AggregatedMetricsDict, multi-exchange access, and one end-to-end pipeline-with-reader sanity check.

    tests/test_markowitz_theory.py — the math¶

    35 tests, the most interesting suite:

    • TestTangencyFormula — closed-form matches, identity / diagonal / full covariance.
    • TestTangencyProperties — sums to one, scale invariance, permutation equivariance, symmetric assets get equal weight.
    • TestMaxSharpeOptimality — tangency beats random portfolios, equal weight, minimum variance.
    • TestEfficientFrontier — minimum-variance point, parabola formula, tangency lies on the frontier.
    • TestStrictErrors — every documented failure mode raises with the expected message.
    • TestBoxConstraints — water-filling preserves ordering on the free set, max_weight respected, unbinding bounds match unconstrained.

    If you change _solve_markowitz, this is the suite that will break first. Keep it green.

    binance_parser/tests/test_models.py — DTO parsing¶

    Realistic Binance combined-stream payloads → DTOs:

    • Order book diffs (default + array format + @depth5@100ms etc.)
    • Trades (price / size / side parsing, side flip from is_buyer_maker)
    • AggTrades (routed to AggTrade, not Trade)
    • Klines (volume extensions: quote_volume, taker_buy_*)
    • Funding (REST shape, with and without mark_price)
    • ExchangeInfoSymbol (spot, perpetual, halted)
    • Unknown stream ⇒ UnknownStream raised

    binance_parser/tests/test_orderbook.py — local L2 book¶

    Bootstrap + replay, gap detection + resync, qty=0 removes a level, top() ordering, mid and spread_bps, empty-book API, snapshot event array shape.

    Adding tests¶

    A new strategy¶

    tests/test_pipeline.py::TestAlphaStrategies already iterates the entire ALPHA_REGISTRY. Your new strategy is covered by the existing "produces weights / approximately neutral / respects max_w" tests.

    For a strategy-specific assertion, add a method:

    def test_my_alpha_inverts_funding(mock_data):
    alpha = MyAlpha(data=mock_data)
    w = alpha.gen_weights()
    # check the per-strategy invariant

    A new aggregator metric¶

    Add a fixture in tests/test_aggregators.py covering the new metric. The existing TestMarketDataAggregator / TestTradesAggregator / TestOrderbookAggregator classes are good templates.

    A new parser DTO¶

    Add a fixture in binance_parser/tests/test_models.py with a representative wire payload, then a test_parse_<thing>_fields assertion checking field-by-field deserialisation.

    Conventions¶

    • Use the mock fixtures. MockExchangeData for strategy-level tests, MockRawDataReader for pipeline-level tests. Don't ship tests that hit Binance.
    • Module-scoped fixtures for expensive setups. The pipeline fixture saves ~15 s per session.
    • No time.sleep. Use FakeBarClock (alpha_engine/live/bar_clock.py) for deterministic time-driven tests.
    • Document test intent in the docstring. "What invariant does this test, and why is it sufficient?" — not "what does the code do".

    CI¶

    There's currently a .gitlab-ci.yml from a previous host. The repo now lives at github.com/SNCapital/-Backend; the GitLab pipeline file is unused. If you set up GitHub Actions, the simplest workflow is:

    # .github/workflows/test.yml
name: tests
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.13" }
      - run: pip install -r requirements.txt -r binance_parser/requirements.txt
      - run: pytest

    Removing .gitlab-ci.yml is a separate cleanup task — left alone here because nothing depends on it being absent.
