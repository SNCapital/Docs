    Docker - live contour + dashboard (NSC-87)¶

    The root main.py is the entrypoint for the live contour (python main.py live): it embeds the WS parser, streams raw ticks through the in-process Python metrics engine (LiveMetricsBridge - no Go handoff), and runs the LiveTrader on the computed metrics. Execution defaults to paper (no exchange contact, no keys); mode: testnet|mainnet in live_config.yaml opts into real orders. The trader is configured only by that single repo-root file (the image ships it at /app/live_config.yaml; compose bind-mounts ./live_config.yaml over it so edits take effect without a rebuild); env carries BINANCE_* secrets only. The dashboard runs as a separate read-only container sharing only the trader-state volume. Data retention (upload old parquet to S3, then delete locally) is an opt-in archiver service that runs the parser's own python main.py archive (binance_parser/services/archive.py).

    Data path - one source of truth¶

    The parser's FileWriter writes to binance_parser/data (hardcoded in binance_parser/config/settings.py). So the raw_data volume mounts at /app/binance_parser/data, so the live writer, the warm-start reader and the archiver all operate on the same partitions and data survives container recreation.

    Quick start on a clean server¶

    git clone <repo> backend && cd backend
cp .env.example .env        # fill BINANCE_API_KEY / DASH_PASS (+ B2_* for archiving)
docker compose build
docker compose up -d        # live + dashboard

# check
docker compose ps
curl -s http://localhost:8000/healthz   # dashboard health
docker compose logs -f live
docker compose logs -f dashboard

# retention is opt-in and needs S3 storage configured (see Archiver):
docker compose --profile archive up -d archiver

    Stop without losing data:

    docker compose down         # volumes (raw_data, trader_state) stay
docker compose up -d        # data survives recreation

    Services¶

    service image command volumes (RW unless :ro)
    live backend-live python main.py live raw_data:/app/binance_parser/data, metrics:/app/data/metrics, trader_state:/app/data/state
    dashboard backend-live uvicorn dashboard ... trader_state:/app/data/state:ro
    archiver backend-live python main.py archive* raw_data:/app/binance_parser/data

    The live container writes three kinds of state, each on its own volume: raw ticks (raw_data -> binance_parser/data), computed metrics parquet the bridge produces and warm-starts from (metrics -> /app/data/metrics, config metrics_root), and the full trader state the dashboard reads (trader_state -> /app/data/state, config state_path). Both paths come from the single repo-root live_config.yaml (relative paths resolved against the /app workdir).

    * the archiver runs the parser's main.py (working_dir: /app/binance_parser), which is a different entrypoint from the root main.py the live service runs.

    live and dashboard have a Docker HEALTHCHECK; archiver has healthcheck: disable: true (cron-like job). All services have restart: unless-stopped. The archiver is behind the archive compose profile, so the default docker compose up starts only live + dashboard.

    Live healthcheck¶

    The live process serves GET /healthz (200) on health_port (config, default 8080) - a tiny aiohttp server running in the same event loop as the WS listener and engine. The container healthcheck curls it. Liveness is deliberately business-logic agnostic: a 200 only proves the process is up and its loop is responsive; it does not depend on bars, strategies or weights (so it never goes stale on the 30-min bar cadence). start_period covers warm-start before the server binds.

    Separately, the LiveTrader writes its full per-bar state (equity, positions, fills, target weights, risk violations) to state_path (config) as the data feed for the read-only dashboard (/api/state, /api/weights, /api/orders). The dashboard container is pointed at the same file via its own LIVE_STATE_PATH env. That file is not a healthcheck input.

    Secrets¶

    Pass via .env or environment (docker compose --env-file, systemd, Swarm secrets, etc.). Never COPY keys into the image - Dockerfile contains no ENV with secrets and .dockerignore excludes .env.

    Required:

    BINANCE_API_KEY / BINANCE_API_SECRET   (real trading only)
DASH_USER / DASH_PASS                  (dashboard auth)
S3_STORAGES + per-storage N_* vars     (only if the archiver profile is enabled)

    Archiver (retention)¶

    The archiver is binance_parser/services/archive.py, run standalone as python main.py archive from the parser package. Every dt=YYYY-MM-DD partition strictly older than ARCHIVE_RETENTION_DAYS (default 3) is uploaded to every configured S3-compatible storage and only then deleted locally; empty partitions are pruned. Background mode runs one cycle per day at ARCHIVE_HOUR_UTC:ARCHIVE_MINUTE_UTC (default 00:10 UTC).

    Storage config is mandatory: the process exits at startup unless every required variable is present (it must never delete local data without a confirmed upload target). That is why the service is gated behind the archive profile instead of crash-looping in the default up. S3_STORAGES lists the storage names (comma-separated, default b2); for each name N set N_ENDPOINT, N_REGION, N_BUCKET, N_PREFIX, N_KEY_ID, N_APPLICATION_KEY. Full example: deploy/secrets/binance.env.example.

    One-shot / preview:

    docker compose --profile archive run --rm archiver python main.py archive --once --dry-run
docker compose --profile archive run --rm archiver python main.py archive --once

    Overriding for local bind mounts¶

    volumes:
  - ./data:/app/binance_parser/data
  - ./state:/app/data/state

    Named volumes (backend_raw_data, backend_trader_state) survive docker compose down and are the default for production.

    Notes¶

    • The trader is configured only by the single repo-root live_config.yaml. The image ships it at /app/live_config.yaml; compose bind-mounts ./live_config.yaml over that path so editing the one file changes a running container without a rebuild. Its paths are relative, so the same file works locally (./data/...) and in the container (/app/data/..., where the named volumes mount).
    • Env is secrets/wiring only: BINANCE_* for testnet/mainnet, DASH_* for the dashboard, ARCHIVE_* / S3_STORAGES / B2_* for the archiver. See .env.example. No trader parameter is read from env.
