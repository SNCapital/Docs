    SN Capital — Backend¶

    A quantitative research and live-trading stack on top of Binance market data.

    • Get going in 5 minutes

      Install, run a synthetic backtest, then point the same CLI at real parquet data once you have it.

      Quick start

    • Backtest your alpha

      Vectorised three-layer pipeline — data → strategies → Markowitz combination → PnL. Six reference strategies in the registry.

      Pipeline overview

    • Trade live (signal-only today)

      The same strategy code runs on a UTC-aligned bar clock fed by the parser's WebSocket bus. Phase 4 wires real orders.

      Live trading

    • Collect Binance data

      Live WebSocket capture, ZIP backfill from data.binance.vision, REST funding poll, and an opt-in local L2 order book — Hive-partitioned parquet.

      Binance parser

    What's in here¶

    The repo holds two top-level packages that are deliberately decoupled:

    backend/
├── alpha_engine/         strategy engine (backtest + live runtime)
└── binance_parser/       Binance data pipeline (WS + history + funding)

    The strategy engine reads the parquet tree the parser writes. They run independently — you can collect data without ever running a strategy, or backtest on data the parser produced months ago.

    flowchart LR
  subgraph BP[binance_parser]
    WS[WebSocket\nspot+usdm] --> WR[FileWriter\nasync, Hive parquet]
    REST[REST funding] --> WR
    HIST[history\ndownload] --> WR
  end
  WR -. parquet .-> DATA[(data/<br/>market=…/type=…/dt=…/symbol=…)]

  subgraph AE[alpha_engine]
    DATA --> READ[RawDataReader]
    READ --> AGG[Aggregators<br/>30-min bars]
    AGG --> STR[ALPHA_REGISTRY]
    STR --> MK[Markowitz combine]
    MK --> PNL[PnL + plots]
  end

  subgraph LIVE[alpha_engine.live]
    BUS[LiveTickBus] --> LR[LiveRawDataReader]
    LR --> ENG[LiveEngine<br/>per-bar tick]
  end

  WS -. shares .-> BUS

    Why a custom stack?¶

    Off-the-shelf options don't quite fit:

    • Backtrader / vectorbt make per-tick or per-bar event-loop abstractions central. We want the vectorised version (everything is a (time × ticker) DataFrame) and the live version to share strategy code with no rewrites. The pipeline does exactly that — see run_strategies().

    • Cryptofeed / ccxt abstract over many venues. We only need Binance, and we need the parser's output schema — Hive-partitioned parquet with float32 prices and int64 ms timestamps — to be optimised for partition-pruned reads from the strategy side.

    • Open-source order books are fine but rarely come with the official bootstrap-and-replay algorithm wired correctly. The local L2 book here follows Binance's spec to the letter, see Local order book.

    Getting help¶

    • Docs — you're reading them. The left nav covers everything.
    • Source — python -c "import alpha_engine; help(alpha_engine.pipeline)" works for any module. Most files have a top-of-file docstring that matches a section in these docs.
    • Tests — tests/test_* and binance_parser/tests/test_* are the executable spec. Read them when a docstring is unclear.
    • Issues — SNCapital/Backend on GitHub.
