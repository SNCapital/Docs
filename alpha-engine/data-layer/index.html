    Data layer¶

    Layer 1 of the pipeline: read raw ticks, aggregate to 30-minute bars, expose via a lazy dict.

    The four shapes¶

    graph LR
  R["RawDataReader"]
  AGG[Aggregators]
  AMD["AggregatedMetricsDict<br/>per-exchange dict"]
  ED["ExchangeData<br/>dict[exchange] → AMD"]
  R --> AGG --> AMD
  AMD --> ED
    • RawDataReader — abstract interface over storage. Three concrete impls.
    • Aggregators — pure functions: raw ticks for one ticker → metric dict.
    • AggregatedMetricsDict — lazy dict[metric_name → DataFrame(t × tickers)].
    • ExchangeData — dict of exchange tag → AggregatedMetricsDict.

    Strategies see ExchangeData. They write data["binance-f"]["mark_price"] and stay agnostic to whether the backing reader is parquet, mock, or live deque.

    Readers — pick the right one¶

    Reader Backed by When to use
    MultiFileParquetReader parser's Hive layout data/market=…/type=…/dt=YYYY-MM-DD/symbol=…/part-* Default for production. Reads what binance_parser writes. Partition-prunes by dt=.
    ParquetFileReader flat data_root/{exchange}/{kind}/{TICKER}.{parquet,csv,zip} Single-file-per-ticker archives consolidated by some other process.
    MockRawDataReader synthetic random walks Tests and the --mock flag on the CLI.
    LiveRawDataReader rolling deques fed by LiveTickBus Live runtime — see Live trading. 
    from alpha_engine.metrics.raw_data_reader import (
    MultiFileParquetReader, ParquetFileReader, MockRawDataReader,
)

reader = MultiFileParquetReader("data")          # parser output
reader = ParquetFileReader("legacy_archive")      # flat layout
reader = MockRawDataReader(tickers=["BTC-USDT"])  # tests

    The reader interface is intentionally tiny:

    class RawDataReader(ABC):
    def read(self, exchange, kind, ticker, since, until) -> pd.DataFrame | None: ...
    def available_tickers(self, exchange, kind) -> list[str]: ...

    kind ∈ {"trades", "orderbook", "klines", "funding"}.

    Aggregators — what they produce¶

    Aggregators take raw ticks for one ticker over [since, until] and return a dict[metric_name → pd.Series] indexed at 30-min bars.

    from alpha_engine.metrics.trades_aggregator    import aggregate_trades_30min
from alpha_engine.metrics.orderbook_aggregator import aggregate_orderbook_30min
from alpha_engine.metrics.market_data_aggregator import aggregate_klines_30min, aggregate_funding_30min

    AggregatedMetricsDict lazily aggregates all metrics in a group the first time any metric in that group is requested, then caches. Groups: trades, orderbook, klines, funding. The mapping metric_name → group lives in metrics_dict.py::_METRIC_SOURCE.

    Empty-group behaviour¶

    If no ticker has data for a given group, _aggregate_group records the group as "computed" without populating any metrics. Subsequent data["binance-f"]["bid_25_cost"] raises a clear KeyError rather than silently returning a NaN frame — see metrics_dict.py:99.

    Exchange tags¶

    Two exchange tags ship by default:

    Tag Parser market= What it covers
    binance spot Binance spot streams
    binance-f usdm Binance USD-M perpetual futures

    MultiFileParquetReader knows the mapping via _EXCHANGE_TO_MARKET in raw_data_reader.py. To add a venue (e.g. COIN-M):

    1. Add the entry to _EXCHANGE_TO_MARKET.
    2. Make sure the parser writes under the corresponding market=…/.
    3. Pass exchanges=["…", …] to AlphaPipeline / LiveEngineConfig.

    Lazy access semantics¶

    data = ExchangeData(reader, since, until, exchanges=["binance-f"])

# These two lines are FREE — no I/O yet.
md = data["binance-f"]
print(type(md))                        # AggregatedMetricsDict

# This triggers ALL kline metrics to be aggregated for ALL tickers and cached.
close = md["close_price"]              # DataFrame(t × tickers)
high  = md["high_price"]               # cached — instant

# Mark price lives in its own kind (USD-M only, NSC-9), so the next line
# pulls in ALL markprice metrics for ALL tickers in one pass.
mark  = md["mark_price"]
pred  = md["predicted_funding"]        # cached — instant

# This triggers ALL trade metrics for ALL tickers.
buys  = md["buy_cost_quantile_0.95"]
hh    = md["hh_buy"]                   # cached

    The "all metrics in a group at once" choice is deliberate: a strategy that uses 5 trade metrics pays the per-ticker iteration once instead of 5 times.

    Metric catalogue (short list)¶

    Full table in Metrics catalogue. Highlights:

    Group Examples
    klines close_price, volume_usd, high_price
    markprice mark_price, index_price, predicted_funding, next_funding_time_ms (USD-M)
    funding realized_funding
    trades buy_cost, buy_cost_quantile_0.95, buy_volume_quantile_0.95_usd, vwap, kyle_lambda, hh_buy, volatility
    orderbook bid_25_cost_avg, ask_25_vwap_avg, cost_imbalance_10_ratio_avg, bid_ask_spread_rel_avg, last_best_bid_price

    The orderbook depth percentages are percent-of-mid (e.g. bid_0_5_cost_avg = bar-mean of bid notional within 0.5% of mid; bid_25_cost_avg = within 25% of mid). Each per-snapshot base is expanded into a 9-aggregate suffix pack (_avg, five quantiles, _skew, _min, _max). Underscores in the name come from str.replace(".", "_").

    Adding a new metric¶

    1. Compute it inside the right aggregator (e.g. aggregate_trades_for_bar in trades_aggregator.py).
    2. Add its name to the matching *_METRICS registry list.
    3. The lazy dict picks it up automatically.

    If the name doesn't match a registered prefix in _resolve_source (bid_*, ask_*, buy_*, sell_*, cost_imbalance_*, the kline allow-list, or *funding*), add a branch — the dict refuses to guess.
