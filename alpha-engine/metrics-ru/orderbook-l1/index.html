    L1-метрики ордер-бука (top of book)¶

    Этот документ описывает L1-подмножество метрик ордер-бука — метрики, которые зависят только от лучшей цены и объёма на верхушке стакана, без глубины и распределений по уровням. L2-метрики живут в отдельном файле.

    Документ описывает целевую спецификацию — то, как метрики должны считаться. Текущая реализация в коде может отличаться; расхождения вылавливаются отдельно.

    Общий контекст для всех L1-метрик¶

    Источник данных¶

    Сырые L2-апдейты @depth от биржи. Темп прихода зависит от рынка и режима подписки:

    • spot @depth — real-time, типично около 100 мс
    • usdm @depth — 250 мс по умолчанию (можно подписаться на @depth@100ms или @depth@500ms явно)

    Из апдейтов алгоритмом Binance восстанавливается живая книга (см. бэклог локального стакана в парсере).

    Сэмплирование¶

    Книга сэмплируется в снапшоты с настраиваемой частотой, выровненные к UTC-сетке.

    config:
  snapshot_freq_hz: float = 1.0     # частота сэмплирования, Гц
                                    # default 1 Гц → 1 снапшот в секунду
                                    # на 30-минутный бар: ~1800 снапшотов

    Снапшоты time-aligned: при 1 Гц они попадают на HH:MM:SS.000.

    Фильтр «пыли»¶

    Сейчас не применяется. Все L1-метрики считаются по всем уровням снапшота, включая микро-ордера. Реализация фильтра пыли занесена в backlog.md, пункт B1.

    NaN-семантика (для базовых per-snapshot метрик)¶

    • Если в снапшоте обе стороны пустые → best_bid_* = best_ask_* = NaN. Тик в массиве сохраняется — длина массива равна числу запланированных снапшотов в баре.
    • Если в снапшоте одна сторона пустая, другая есть — пустая даёт NaN, заполненная даёт значение. Длины массивов bid и ask совпадают и time-aligned (нужно для diff/logreturn).
    • Перед агрегацией NaN отбрасываются. Если массив после отбрасывания пустой → все per-bar ключи этой стороны = NaN.

    Дубликат цены в одном снапшоте¶

    (side, price) в L2-снапшоте по контракту встречается ровно один раз. Если по какой-то причине обнаружен дубликат → InvariantError (не складываем, не максимизируем — кричим).

    Нотация (используется во всех формулах ниже)¶

    Снапшот в момент t — пара множеств:

    snapshot(t).bids = { (p, s) : p — цена bid-уровня, s — объём (size > 0) }
snapshot(t).asks = { (p, s) : p — цена ask-уровня, s — объём (size > 0) }

    Lookup-функция (по контракту L2 цена в стороне уникальна):

    size_at(t, side, p) := s   такой что (p, s) ∈ snapshot(t).<side>

    Бар B = [t_start, t_end). Множество снапшотов бара:

    Snapshots(B) = { t_1 < t_2 < ... < t_N }
   N = floor(bar_duration_sec × snapshot_freq_hz)
   default 30min × 1.0 Hz → N = 1800

    Для произвольной per-snapshot скалярной метрики M(t) — массив бара:

    S_M(B)  = [ M(t_1), M(t_2), ..., M(t_N) ]            # упорядоченный массив длины N, может содержать NaN
F_M(B)  = [ M(t_i) : 1 ≤ i ≤ N, M(t_i) finite ]      # подпоследовательность без NaN (с дубликатами)
F'_M(B) = [ M(t_i) : 1 ≤ i ≤ N, M(t_i) finite AND M(t_i) ≠ 0 ]   # без NaN и без нулей
n_M(B)  = len(F_M(B))                                # число валидных значений
n'_M(B) = len(F'_M(B))                               # число валидных и ненулевых

    Это мульти-наборы (списки с дубликатами), не математические множества. На стабильном рынке best_bid_price(t) много секунд подряд может быть одним и тем же числом — все эти повторы попадают в F_M(B), и mean считается с правильным весом.

    9-агрегационный шаблон (для базовых per-snapshot метрик)¶

    Применяется к L1.1, L1.2, L1.4. Для базовой per-snapshot метрики M(t) определяются 9 ключей:

    M_avg(B)         = mean(F_M(B))                        if n_M(B) > 0 else NaN
M_min(B)         = min(F_M(B))                         if n_M(B) > 0 else NaN
M_max(B)         = max(F_M(B))                         if n_M(B) > 0 else NaN
M_quantile_q(B)  = quantile(F_M(B), q),  q ∈ Q          if n_M(B) > 0 else NaN
M_skew(B)        = skew(F_M(B), bias=False)            if n_M(B) ≥ 3 and std(F_M(B)) > ε
                 = NaN                                  otherwise

Q = {0.25, 0.5, 0.75, 0.9, 0.95}      # фиксированный набор перцентилей
ε = 1e-12 × max(1, |mean(F_M(B))|)    # порог "почти константа" для skew

    Произвольные quantile_q (вне Q) не поддерживаются.

    _sum к базовым метрикам не применяется — он зарезервирован для diff/logreturn (см. ниже).

    10-агрегационный шаблон (для cross-snapshot diff/logreturn)¶

    Применяется к L1.5, L1.6. Для cross-snapshot метрики M(t) — нулевые значения отбрасываются вместе с NaN. Используется F'_M(B) (без NaN и без нулей):

    M_avg(B)         = mean(F'_M(B))                        if n'_M(B) > 0 else NaN
M_min(B)         = min(F'_M(B))                         if n'_M(B) > 0 else NaN
M_max(B)         = max(F'_M(B))                         if n'_M(B) > 0 else NaN
M_quantile_q(B)  = quantile(F'_M(B), q),  q ∈ Q          if n'_M(B) > 0 else NaN
M_skew(B)        = skew(F'_M(B), bias=False)            if n'_M(B) ≥ 3 and std(F'_M(B)) > ε
                 = NaN                                   otherwise
M_sum(B)         = sum(F'_M(B))                         (всегда определена; пустая сумма = 0.0)

    _sum определён всегда — на пустом массиве равен 0.0.

    Обоснование zero-drop: для diff/logreturn нулевое значение означает «ничего не изменилось между соседними снапшотами» — это шум, не информативный сигнал.

    L1.1 — best_{ask/bid}_price¶

    Смысл. Лучшая цена на стороне bid/ask в момент t.

    Per-snapshot¶

    P_bid(t) = { p : (p, s) ∈ snapshot(t).bids }
P_ask(t) = { p : (p, s) ∈ snapshot(t).asks }

best_bid_price(t) = max(P_bid(t))      if P_bid(t) ≠ ∅
                  = NaN                otherwise

best_ask_price(t) = min(P_ask(t))      if P_ask(t) ≠ ∅
                  = NaN                otherwise

    Уровни с s = 0 в snapshot(t) отсутствуют по контракту (удалены при применении соответствующего L2-апдейта).

    Per-bar¶

    Подставляем M(t) := best_bid_price(t) или M(t) := best_ask_price(t) в 9-агрегационный шаблон. 9 ключей × 2 стороны = 18:

    best_{bid|ask}_price_avg
best_{bid|ask}_price_min
best_{bid|ask}_price_max
best_{bid|ask}_price_quantile_{0.25, 0.5, 0.75, 0.9, 0.95}
best_{bid|ask}_price_skew

    L1.2 — best_{ask/bid}_size¶

    Смысл. Объём (в монете) на best-уровне в момент t.

    Per-snapshot¶

    best_bid_size(t) = size_at(t, "bid", best_bid_price(t))   if best_bid_price(t) ≠ NaN
                 = NaN                                     otherwise

best_ask_size(t) = size_at(t, "ask", best_ask_price(t))   if best_ask_price(t) ≠ NaN
                 = NaN                                     otherwise

    Парность (price, size): best_*_price = NaN ⟺ best_*_size = NaN.

    Если (side, best_*_price) встречается в снапшоте дважды → InvariantError (на L2 такого быть не должно по контракту).

    Per-bar¶

    Подставляем M(t) := best_bid_size(t) или M(t) := best_ask_size(t) в 9-агрегационный шаблон. 9 ключей × 2 стороны = 18:

    best_{bid|ask}_size_avg
best_{bid|ask}_size_min
best_{bid|ask}_size_max
best_{bid|ask}_size_quantile_{0.25, 0.5, 0.75, 0.9, 0.95}
best_{bid|ask}_size_skew

    L1.3 — last_best_{ask/bid}_price¶

    Смысл. Последняя известная лучшая цена стороны bid/ask в баре. Семантика — «backward-fill от конца бара»: если последний снапшот бара не содержит данных по стороне, берём ближайший по времени снапшот в прошлом, в котором сторона была.

    Не разворачивается в 9 ключей — это per-bar single value, не агрегация.

    Per-bar¶

    Для bid (симметрично для ask):

    S_bid(B) = [ best_bid_price(t_1), ..., best_bid_price(t_N) ]
I_bid(B) = { i : 1 ≤ i ≤ N AND S_bid(B)[i] finite }   # множество индексов

last_best_bid_price(B) = S_bid(B)[i*]   where i* = max(I_bid(B))
                       = NaN            if I_bid(B) = ∅

    Здесь i* — максимальный индекс, при котором значение finite. Это эквивалентно pandas.Series(S_bid(B)).ffill().iloc[-1]. Если на протяжении всего бара не было ни одного валидного снапшота → NaN.

    Финальные ключи¶

    last_best_bid_price                     (1 ключ, не агрегируется)
last_best_ask_price                     (1 ключ, не агрегируется)

    Итого по L1.3: 2 ключа.

    L1.4 — bid_ask_spread_abs / bid_ask_spread_rel¶

    Смысл. Спред между лучшими ценами bid/ask. Эмитится в двух формах: - _abs — абсолютный, в котируемой валюте (USDT для USDT-пар); - _rel — относительный, безразмерный (доля от мида).

    Per-snapshot¶

    mid(t) = (best_bid_price(t) + best_ask_price(t)) / 2

bid_ask_spread_abs(t) = best_ask_price(t) - best_bid_price(t)
                          if best_bid_price(t) finite AND best_ask_price(t) finite
                       = NaN otherwise

bid_ask_spread_rel(t) = (best_ask_price(t) - best_bid_price(t)) / mid(t)
                          if best_bid_price(t) finite AND best_ask_price(t) finite
                       = NaN otherwise

    Дополнительная защита mid(t) > 0 не нужна: если обе цены finite, они строго положительны (биржа не пускает отрицательные/нулевые цены), поэтому mid(t) = (positive + positive) / 2 > 0 автоматически.

    Per-bar¶

    Каждая базовая метрика проходит через 9-агрегационный шаблон. 9 × 2 базовых = 18 ключей:

    bid_ask_spread_abs_avg
bid_ask_spread_abs_min
bid_ask_spread_abs_max
bid_ask_spread_abs_quantile_{0.25, 0.5, 0.75, 0.9, 0.95}
bid_ask_spread_abs_skew

bid_ask_spread_rel_avg
bid_ask_spread_rel_min
bid_ask_spread_rel_max
bid_ask_spread_rel_quantile_{0.25, 0.5, 0.75, 0.9, 0.95}
bid_ask_spread_rel_skew

    Замечание про относительный спред в bps¶

    bid_ask_spread_rel хранится как доля (например 0.0001 = 1 bps). Для отображения в bps домножь на 10000 на стороне потребителя.

    L1.5 — best_{ask/bid}_size_diff¶

    Смысл. Разница best size между соседними снапшотами.

    Per-snapshot¶

    best_bid_size_diff(t_i) = best_bid_size(t_i) - best_bid_size(t_{i-1})
                            if best_bid_size(t_i) finite
                            AND best_bid_size(t_{i-1}) finite
                            AND i ≥ 2
                          = NaN otherwise

best_ask_size_diff(t_i) = best_ask_size(t_i) - best_ask_size(t_{i-1})
                            if best_ask_size(t_i) finite
                            AND best_ask_size(t_{i-1}) finite
                            AND i ≥ 2
                          = NaN otherwise

    Первый снапшот бара (i = 1) — всегда NaN, предшествующего нет.

    Per-bar¶

    10-агрегационный шаблон (с zero-drop и _sum). 10 ключей × 2 стороны = 20:

    best_{bid|ask}_size_diff_avg
best_{bid|ask}_size_diff_min
best_{bid|ask}_size_diff_max
best_{bid|ask}_size_diff_quantile_{0.25, 0.5, 0.75, 0.9, 0.95}
best_{bid|ask}_size_diff_skew
best_{bid|ask}_size_diff_sum

    L1.6 — best_{ask/bid}_price_logreturn¶

    Смысл. Log-доходность best price между соседними снапшотами.

    Per-snapshot¶

    best_bid_price_logreturn(t_i) = log(best_bid_price(t_i) / best_bid_price(t_{i-1}))
                                  if best_bid_price(t_i) finite > 0
                                  AND best_bid_price(t_{i-1}) finite > 0
                                  AND i ≥ 2
                                = NaN otherwise

best_ask_price_logreturn(t_i) = log(best_ask_price(t_i) / best_ask_price(t_{i-1}))
                                  if best_ask_price(t_i) finite > 0
                                  AND best_ask_price(t_{i-1}) finite > 0
                                  AND i ≥ 2
                                = NaN otherwise

    Первый снапшот бара (i = 1) — всегда NaN.

    Per-bar¶

    10-агрегационный шаблон (с zero-drop и _sum). 10 ключей × 2 стороны = 20:

    best_{bid|ask}_price_logreturn_avg
best_{bid|ask}_price_logreturn_min
best_{bid|ask}_price_logreturn_max
best_{bid|ask}_price_logreturn_quantile_{0.25, 0.5, 0.75, 0.9, 0.95}
best_{bid|ask}_price_logreturn_skew
best_{bid|ask}_price_logreturn_sum

    _sum имеет содержательную интерпретацию: суммарная log-доходность best price за бар, посчитанная пошагово. На практике ≈ log(last_best_price / first_best_price) бара (с поправкой на NaN-снапшоты в середине).
