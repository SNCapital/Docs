    trades_v2 — основные метрики на трейдах¶

    trades_v2 — основной trade-aggregator. Метрики из этого файла используются в продакшн-альфах. Содержит общие метрики (cost, count, vwap, OHLC, volatility, HH, kyle, ASR), но исключает ml/sl-разделение — это в trades-multilevel.md.

    Документ описывает целевую спецификацию.

    Общий контекст¶

    Источник данных¶

    Парсер пишет parquet: 

    data/market={spot|usdm}/type=aggtrades/dt=YYYY-MM-DD/symbol=SYM/part-*.parquet  (live)
data/market={spot|usdm}/type=aggTrades/dt=YYYY-MM-DD/symbol=SYM/part-*.parquet  (historical)

    Reader через kind="trades" объединяет обе партиции (_KIND_TO_TYPES["trades"] = ("aggtrades", "aggTrades")).

    Колонки после нормализации: timestamp, side, price, size. - side ∈ {"buy", "sell"} — сторона агрессора - size — объём трейда в base coin - price × size — notional в quote coin (USD-эквивалент)

    Что такое «трейд» в v2¶

    В v2 «трейд» = результат multilevel-реконструкции: одна логическая агрессия может быть склеена из нескольких aggTrades, если она исполнилась об несколько ценовых уровней. Алгоритм реконструкции — в trades-multilevel.md.

    Это значит buy_count_v2 ≤ buy_count_v1 (см. trades-v1.md): v2 склеивает несколько aggTrades в один логический трейд.

    Все формулы ниже применимы к итоговому списку «логических трейдов» после реконструкции. Если реконструкция выключена (опция парсера) — формулы применимы напрямую к aggTrades, и v2 ≡ v1 в этих метриках.

    Per-bar нативно¶

    В отличие от orderbook-метрик, trades — это поток событий, не снапшоты. Все метрики bar-level: одно число на бар на тикер. Никаких 9-агг шаблонов сверху не накладывается.

    Конвенция имён¶

    Суффикс Значение Пример
    _quantile_q порог по q-й перцентили распределения внутри бара buy_cost_quantile_0.95
    _above_T фиксированный USD-порог buy_count_above_1000

    Параметры: - q ∈ {0.25, 0.5, 0.75, 0.9, 0.95} (стандартный набор) - T ∈ {100, 1000, 10_000, 100_000, 1_000_000} (USD)

    Нотация¶

    Trades(B) = [(t_1, side_1, price_1, size_1), ...]   # все трейды в баре B, t_1 < t_2 < ...
BuyTrades(B)  = [trade ∈ Trades(B) : trade.side == "buy"]
SellTrades(B) = [trade ∈ Trades(B) : trade.side == "sell"]

notional(trade) = trade.price × trade.size

    Per-side (buy/sell) и overall¶

    Большинство метрик существуют в двух формах: - per-side: buy_*, sell_* — считается отдельно по BuyTrades / SellTrades - overall: метрика без префикса (vwap, volatility) — на всех Trades(B)

    Если в баре нет трейдов нужной стороны → метрика этой стороны NaN (или 0.0 для аддитивных, см. конкретную метрику).

    L_T2.1 — Counts¶

    Смысл. Количество трейдов за бар.

    buy_count(B)  = |BuyTrades(B)|              ≥ 0  (0 для пустого бара)
sell_count(B) = |SellTrades(B)|             ≥ 0

    Per-USD-threshold:¶

    buy_count_above_T(B)  = |{ trade ∈ BuyTrades(B)  : notional(trade) > T }|
sell_count_above_T(B) = |{ trade ∈ SellTrades(B) : notional(trade) > T }|

    Для каждого T ∈ {100, 1000, 10_000, 100_000, 1_000_000} — 5 ключей × 2 стороны = 10.

    Итого Counts: 2 + 10 = 12 ключей.

    L_T2.2 — Costs (notional sums)¶

    Смысл. Суммарный USD-ноционал прошедших через бар трейдов.

    buy_cost(B)  = Σ notional(trade)  for trade ∈ BuyTrades(B)             ≥ 0  (0 если нет buy)
sell_cost(B) = Σ notional(trade)  for trade ∈ SellTrades(B)            ≥ 0

    Per-quantile (топ q% по размеру):¶

    sorted_buy = sorted(BuyTrades(B), key=notional, descending)
threshold_buy_q = quantile([notional(t) for t in BuyTrades(B)], q)

buy_cost_quantile_q(B)  = Σ notional(trade)  for trade ∈ BuyTrades(B)
                                              with notional(trade) ≥ threshold_buy_q
                        = NaN  if BuyTrades(B) is empty
                                              # nothing to compute quantile from
sell_cost_quantile_q(B) = аналогично

    Семантически: «сумма USD-ноционала из топ-q% самых крупных buy-трейдов». Например, q = 0.95 → сумма ноционала топ-5% buy-трейдов.

    Для каждого q ∈ {0.25, 0.5, 0.75, 0.9, 0.95} — 5 × 2 = 10.

    Итого Costs: 2 + 10 = 12 ключей.

    L_T2.3 — Trade-cost quantile boundaries¶

    Смысл. Значение notional на границе квантиля (не сумма, а сама граница).

    buy_trade_cost_quantile_q(B)  = quantile([notional(t) for t in BuyTrades(B)], q)
                              = NaN  if BuyTrades(B) is empty
sell_trade_cost_quantile_q(B) = аналогично

    Различие с предыдущим разделом: buy_cost_quantile_0.95 это сумма, buy_trade_cost_quantile_0.95 это значение границы (USD).

    Для каждого q ∈ {0.25, 0.5, 0.75, 0.9, 0.95} — 5 × 2 = 10 ключей.

    L_T2.4 — Maximum trade cost¶

    Смысл. Размер крупнейшей сделки за бар.

    max_buy_trade_cost(B)  = max(notional(trade) for trade in BuyTrades(B))
                       = 0.0  if BuyTrades(B) is empty
max_sell_trade_cost(B) = аналогично

    Согласовано с _sum-конвенцией пустых баров: 0.0, не NaN.

    2 ключа.

    L_T2.5 — VWAP (volume-weighted average price)¶

    Смысл. Средневзвешенная по объёму цена сделок. Эффективная цена исполнения для агрегата трейдов.

    buy_vwap(B)  = buy_cost(B)  / buy_volume(B)            # buy_volume = Σ size for buy
             = NaN  if buy_volume(B) = 0

sell_vwap(B) = sell_cost(B) / sell_volume(B)
             = NaN  if sell_volume(B) = 0

vwap(B)      = (buy_cost(B) + sell_cost(B)) / (buy_volume(B) + sell_volume(B))
             = NaN  if total volume = 0

    Формула эквивалентна Σ (price × size) / Σ size за один проход.

    3 ключа.

    L_T2.6 — OHLC из трейдов¶

    Смысл. Open, High, Low, Close цены бара, усреднённые между buy- и sell-агрегаторами, чтобы нивелировать bid-ask bounce trade-tape'а.

    first_buy_price(B)  = price первого buy-трейда в B (по времени)
last_buy_price(B)   = price последнего buy-трейда
high_buy_price(B)   = max price среди buy-трейдов
low_buy_price(B)    = min price среди buy-трейдов

(аналогично для sell)

open(B)  = (first_buy_price(B) + first_sell_price(B)) / 2
close(B) = (last_buy_price(B)  + last_sell_price(B))  / 2
high(B)  = (high_buy_price(B)  + high_sell_price(B))  / 2
low(B)   = (low_buy_price(B)   + low_sell_price(B))   / 2

    Edge cases¶

    Любая из четырёх метрик = NaN, если в баре нет хотя бы одной buy- или одной sell-сделки. То есть OHLC требует наличия обеих сторон.

    Для пустого бара или однонаправленного бара — все четыре NaN.

    4 ключа.

    L_T2.7 — Volatility¶

    Смысл. Стандартное отклонение минутных log-доходностей цены внутри бара.

    Алгоритм¶

    1. Сгруппировать Trades(B) по минутам (внутри 30-минутного бара получается ≤ 30 групп).
    2. Для каждой минуты m с трейдами вычислить vwap_m = VWAP трейдов этой минуты.
    3. Построить последовательность log-доходностей: 
      r_m = log(vwap_m / vwap_{m_prev})    # m_prev — предыдущая непустая минута
      Минуты без трейдов пропускаются — нет точки в последовательности.
    4. volatility(B) = std(r_m, ddof=1) = NaN if меньше 2 непустых минут

    Используем sample std (ddof=1), не population. На практике различие ничтожно при ≥10 наблюдениях.

    1 ключ.

    L_T2.8 — Herfindahl-Hirschman index (HH)¶

    Смысл. Концентрация объёма по трейдам. HH = 1 — весь бар это один трейд; HH = 1/n — равномерное распределение.

    hh(B) = Σ (size_i / total_volume)²    for trade_i ∈ Trades(B)
        where total_volume = Σ size_j for j ∈ Trades(B)
      = NaN  if Trades(B) is empty (total_volume = 0)
      = 1.0  if there's only one trade

hh_buy(B)  = Σ (size_i / buy_volume)²    for trade_i ∈ BuyTrades(B)
           = NaN if BuyTrades(B) empty
           = 1.0 if only one buy trade

hh_sell(B) = аналогично для sell

    Диапазон: [1/n, 1]. Чем выше — тем более концентрирован объём в нескольких крупных сделках. Можно использовать как proxy для «активности китов».

    3 ключа.

    L_T2.9 — Kyle's lambda (price impact)¶

    Смысл. Регрессионный коэффициент price impact: насколько цена двигается на единицу нетто order flow.

    Алгоритм (по решению T2.E — вариант (а), классика Kyle 1985)¶

    1. Сгруппировать Trades(B) по минутам (≤ 30 групп).
    2. Для каждой минуты m с трейдами: 
      signed_volume_m = Σ (size  if side == "buy"  else  -size)
                  for trade in минуте m
vwap_m          = VWAP трейдов минуты m
    3. Построить последовательность log-returns: 
      r_m = log(vwap_m / vwap_{m_prev})    # m_prev — предыдущая непустая минута
      (Эквивалентно volatility.)
    4. OLS-регрессия: 
      r_m = λ × signed_volume_m + ε
    5. kyle_lambda(B) = slope λ.

    Edge cases¶

    kyle_lambda(B) = OLS slope                        if ≥ 3 непустых минут
                                                  AND non-zero signed_volume variance
               = NaN                              otherwise

    При ≤ 2 минутах OLS вырождается; при signed_volume = const — denominator = 0.

    1 ключ.

    L_T2.10 — Adverse Selection Ratio (ASR)¶

    Смысл. Доля «убыточных» taker-сделок. Сделка считается убыточной, если через 60 секунд после неё цена пошла против агрессора.

    Алгоритм (по решению T2.F — вариант (а), lookahead-window)¶

    Окно фиксировано 60 секунд.

    side_sign(side) = +1  if side == "buy"
                = −1  if side == "sell"

# Для каждого trade ∈ Trades(B) с timestamp t:
window_trades(trade) = [tr ∈ AllTrades : t < tr.timestamp ≤ t + 60s]
                       (берётся из ВСЕХ доступных трейдов, не только бара B —
                        поэтому возможен lookahead в следующий бар)

if window_trades(trade) is empty:
    trade исключается из ASR-расчёта (нет 60s-горизонта)

else:
    after_price = window_trades(trade)[-1].price       # цена последнего трейда в окне
    is_loss(trade) = (after_price - trade.price) × side_sign(trade.side) < 0
                     # buy убыточна, если цена упала; sell — если выросла

# Считаем по непустым trade'ам:
included = [trade ∈ Trades(B) : window_trades(trade) ≠ ∅]

asr_count(B)  = |{ trade ∈ included : is_loss(trade) }| / |included|
              = NaN  if included is empty

asr_volume(B) = Σ size  for trade ∈ included with is_loss(trade)
                / Σ size  for trade ∈ included
              = NaN  if included is empty  OR  total size = 0

    Семантика «убыточной»¶

    trade.side = "buy", trade.price = 95000:
   after_price = 95005  →  Δ = +5,  side_sign = +1,  Δ × sign = +5  →  ✓ выигрыш (не loss)
   after_price = 94990  →  Δ = -10, side_sign = +1,  Δ × sign = -10 →  ✗ убыток (loss)

trade.side = "sell", trade.price = 95000:
   after_price = 95005  →  Δ = +5,  side_sign = -1,  Δ × sign = -5  →  ✗ убыток (loss)
   after_price = 94990  →  Δ = -10, side_sign = -1,  Δ × sign = +10 →  ✓ выигрыш

    Покупатель «прав», если цена выросла; продавец — если упала.

    Cross-bar lookahead¶

    ASR использует трейды из следующих баров, чтобы найти after_price для трейдов конца текущего бара. В backtest это работает (доступ ко всему датасету). В live режиме ASR доступен с задержкой ≥ 60s.

    2 ключа: asr_count, asr_volume.

    Сводка финальных ключей trades-v2¶

    Раздел Метрика Ключей
    Counts (L_T2.1) buy_count, sell_count 2
    Counts (L_T2.1) {buy/sell}_count_above_T × 5 порогов 10
    Costs (L_T2.2) buy_cost, sell_cost 2
    Costs (L_T2.2) {buy/sell}_cost_quantile_q × 5 квантилей 10
    Quantile boundaries (L_T2.3) {buy/sell}_trade_cost_quantile_q × 5 10
    Max (L_T2.4) max_{buy/sell}_trade_cost 2
    VWAP (L_T2.5) buy_vwap, sell_vwap, vwap 3
    OHLC (L_T2.6) open, high, low, close 4
    Volatility (L_T2.7) volatility 1
    HH (L_T2.8) hh, hh_buy, hh_sell 3

    ASR (L_T2.10) asr_count, asr_volume 2
    Итого 50

    Плюс ml/sl-метрики из trades-multilevel.md и production-эквивалентов из v1 (см. trades-v1.md).

    Ограничения и зависимости¶

    • Все метрики per-bar, без 9-агг разворачивания.
    • volatility и kyle_lambda требуют минутной группировки трейдов внутри бара. На малых барах (< 5 минут с трейдами) ненадёжны.
    • ASR требует lookahead на следующий бар для трейдов конца текущего бара. В live доступна с задержкой 60s.
    • Реконструкция multilevel влияет на buy_count, buy_cost (в меньшей степени — в основном на count). Алгоритм — в trades-multilevel.md.
