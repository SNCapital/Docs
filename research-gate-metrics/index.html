    Gate history and compact research metrics¶

    This work implements a separate offline Gate USDT Futures book reader and a compact candidate feature set. It does not change live Binance collection, replace the 791-key engine, or certify a profitable feature set.

    The current collection freezes forty Binance USD-M USDT perpetuals ranked by USDT quote volume over 2026-09-02 through 2026-10-01, after excluding BTC, ETH, BCH, LTC, ETC and LINK. Both sources collect only that saved selection. The current selection is applied to historical research without historical reranking. Individual membership begins only when Binance and the preceding Gate book interval are available; no substitute coin replaces an unavailable member. This retrospective selection has current-universe selection bias.

    The saved experiment lives in data/research-gate-fixed-20261003/. fixed-universe.json pins the selection and thirty daily-volume inputs per established candidate, acquisition.json restricts Binance acquisition, and universe.json builds the Gate source and availability masks. The scoring cohort is 2025-10-01 through 2026-09-30, with up to sixty days of source warmup clipped to confirmed Gate archive availability. Warmup provides operator history; each strategy chooses its own signal horizon and smoothing. Train ends on 2026-06-01; adaptive Validation ends on 2026-10-01. A subsequent Final period remains sealed. The first configured twelve-iteration free-model wave is exploratory because admission requires at least thirty comparable trials and the other statistical and cost gates.

    collector/history/gate_history.py owns the archive format and streaming reader. metrics/research_features.py owns the feature calculations. calc/gate_history_metrics.py reconstructs books, combines the reader with the feature engine and writes validated research artifacts. tools/gate_history_metrics.py provides only the offline CLI.

    Source contract and reconstruction¶

    Gate publishes hourly gzip CSV book logs with a full initial snapshot followed by merged updates. The six fields are timestamp in seconds, action, price, signed contract count, begin ID, and merged count. Positive counts are bids; negative counts are asks. set supplies the initial absolute quantity, make adds the absolute quantity, and take subtracts it. A book reduction does not identify an executed trade. The final sequence of an update is begin_id + merged_count - 1.

    Reconstruction keeps exact Decimal prices and contract quantities in sorted in-memory maps. Native quantity is contract count. In base mode, base quantity is contract count times the explicit historical contract multiplier, and USD depth is price times that base quantity. In contract_counts mode no base quantity or USD depth is asserted. Each update must start at the preceding final sequence plus one. A missing sequence, inconsistent initial snapshot, duplicate snapshot level, negative depth, invalid timestamp, malformed action, or invalid gzip CRC fails the job. Completed timestamp groups must have a positive, uncrossed, unlocked two-sided book. There is no guessed resynchronization or skipped corrupt input.

    Updates merged by the source can span an independent snapshot ID. The verifier compares top levels at exactly aligned IDs and counts snapshots lying inside a merged span as unaligned. It never pretends it can reconstruct intermediate states. A requested verification with no aligned independent snapshots fails. Independent slices contain top levels, so equality certifies those observed levels rather than all deep orders.

    One observed source boundary is explicit: the 2023-04-25 05:00 UTC BTC file contains 26 update rows stamped exactly 06:00 UTC. These rows are validated for sequence continuity, book invariants and matching independent snapshots, but do not enter the minute ending at 06:00. The receipt counts boundary tail rows. Events later than the advertised hour end fail. Each next hour starts from its own source snapshot; the v1 minute features require no additional hidden cross-hour state.

    Official format and URL construction:

    Native contract names remain exact source identifiers, including Unicode names such as \u5e01\u5b89\u4eba\u751f_USDT. Archive URLs encode the native filename as UTF-8 percent escapes; partition names and receipt symbols retain the native identifier. The asset component accepts letters and numbers, with uppercase ASCII names, and rejects path separators, traversal, whitespace, control characters and URL syntax. Validation errors escape non-ASCII input for ASCII runtime output. An internal Binance research alias such as BINANCE_LIFEUSDT requires an explicit mapping to the native Gate contract; it never changes the filename.

    • Gate archive format announcement

    The current contract endpoint exposes quanto_multiplier, but a current value is not evidence of a historical value. The official public archive products and contract API documentation checked here do not expose a historical multiplier timeline. This does not prevent native count reconstruction or scale-free features. Official contract API

    Two explicit quantity contracts are supported:

    • quantity_mode=contract_counts: reconstruct official native contract counts, expose 21 scale-free candidates and omit every USD field. No multiplier or multiplier-verification fields are accepted. Reconstruction quality can be validated; that certifies native counts, not historical USD depth.
    • quantity_mode=base: require a historical multiplier source and validity interval covering the hour, then expose all 39 candidates. A current-value assumption remains permitted only in a labeled format pilot with multiplier_verification=pilot_assumption and quality pilot_units_unverified; research loading rejects it.

    Legacy v1 jobs with the original required multiplier fields are base jobs. New builders declare quantity_mode explicitly. A manifest uses one mode, so available predictor names stay fixed within an experiment.

    Causal one-minute feature contract¶

    The canonical v1 catalogue has 39 candidates; native-count output provides the 21 candidates whose values do not depend on a common quantity multiplier. Uniform samples occur once per second; the state sampled at boundary t includes only event groups strictly before t. Updates at t belong to the following interval. Each minute has 60 samples. The opening midpoint is known at the minute start. OFI compares completed source timestamp groups rather than unstable intermediate rows within a merged group.

    Candidate family Definition Count
    Spread Mean, close, population standard deviation, maximum of (ask-bid)/mid * 10000 4
    L1 imbalance Mean and close of (bid_base-ask_base)/(bid_base+ask_base) 2
    Weighted midpoint offset Mean and close of ((ask*bid_base + bid*ask_base)/(bid_base+ask_base)-mid)/mid * 10000 2
    Near depth Bid and ask USD depth inside 5, 10, 25 bps of midpoint, mean and close 12
    Near depth imbalance Mean and close of (bid_usd-ask_usd)/(bid_usd+ask_usd) for each band 6
    L1 depth Mean bid and ask USD depth 2
    OFI Quote-notional L1 and mean top-five rank OFI, divided by mean observed per-side depth 2
    Depth additions/reductions Bid/ask make and take USD totals within the minute, over the full observed book 4
    Update rate Source merged update count divided by 60 seconds 1
    Depth flow imbalance (bid_make-bid_take-ask_make+ask_take) divided by total additions and reductions 1
    Midpoint movement Log return in bps, realized volatility from one-second log returns in bps, closing midpoint 3

    The 18 omitted native-count predictors are all USD depth and flow magnitudes: 12 near-depth values, two L1 depths, and four additions/reductions totals. The remaining 21 consist of four spread statistics, two L1 imbalances, two weighted midpoint offsets, six near-depth imbalances, two normalized OFIs, update rate, depth-flow imbalance, and three midpoint price/return/volatility features. Multiplying all quantities by the same positive factor cancels in these ratios and normalized flows. Predictor semantics remain native-contract observations; continuity of count units within aggregation intervals is an assumption, not proof of historical underlying-asset amounts.

    Native-count Parquet also contains one auxiliary native_flow_weight column: sum(price * abs(raw_contract_count_delta)) over the minute, in units price_times_contracts. It is not USD, not a predictor and not offered to agents. Its purpose is exact thirty-minute depth-flow ratio aggregation: sum(minute_ratio * native_weight) / sum(native_weight), zero for a fully observed zero-flow interval. This equals base-unit aggregation under a common quantity multiplier, without inventing dollar magnitudes.

    Near-depth features are measured from midpoint, not from the best quote. Wide spreads can leave both sides of a narrow band empty: both depth values are zero, and the imbalance is NULL. If any second of a minute has an undefined band imbalance, its minute mean is NULL. A zero depth-flow imbalance is meaningful when a fully observed minute has no depth changes. Neither rule invents missing trade or funding observations.

    The OFI variants use quote-notional contributions rather than the raw-share units of the cited equities papers. For a bid rank, improved price contributes new depth, worsened price removes old depth, and unchanged price contributes the quantity change. Ask signs reverse. Top-five OFI is the average of those rank contributions. These are candidate adaptations that need validation.

    Feature references:

    • Cont, Kukanov and Stoikov, The Price Impact of Order Book Events
    • Xu, Gould and Howison, Multi-Level Order-Flow Imbalance in a Limit Order Book

    Every row provides bar_start_ms, ts (bar end), observed_through_ms, source_last_sequence, sample_count, bar_complete, and universe_member. Input strictly after the bar boundary cannot alter an earlier feature row. Execution must follow the completed feature bar; midpoint is a feature price and not an executable VWAP.

    Dynamic universe and resource boundaries¶

    The converter takes an explicit historical job manifest. It does not extrapolate a current top-40 list backward. The universe uses Binance historical traded volume and listing availability. The exclusion is the saved minimum-order coin exclusion from live_config.yaml, not a market-cap filter. Its exact snapshot and source hash belong in the universe provenance; exclusions are not silently recomputed from present-day prices. No historical market-cap purchase or API is needed for this requirement.

    The builder supplies all historical membership intervals for each requested symbol and enough earlier hourly jobs for warmup. The converter retains those warmup minutes but marks membership separately. Membership intervals are half-open [start_ms,end_ms), minute aligned and checked at the minute start. An hour may contain entries and exits. The final number of distinct instruments across several years can exceed 40, so footprint projections must use actual historical jobs and warmup, not a fixed list of 40 survivors.

    A manifest has this shape; values below illustrate the schema and are not historically certified production input:

    {
  "schema": "gate-research-jobs-v1",
  "universe_policy": {
    "status": "pilot",
    "provenance": "format pilot; no certified universe selection"
  },
  "jobs": [{
    "symbol": "BTC_USDT",
    "hour": "2023-04-25T05:00:00Z",
    "quantity_mode": "base",
    "contract_multiplier": "0.0001",
    "multiplier_verification": "pilot_assumption",
    "multiplier_source": "current contract endpoint; historical constancy unverified",
    "multiplier_valid_from_ms": 1682398800000,
    "multiplier_valid_until_ms": 1682402400000,
    "membership_intervals": [],
    "verify_snapshots": true
  }]
}

    Historical manifests set status=historical, provide universe provenance and declare quantity_mode=contract_counts without multiplier fields, or quantity_mode=base with multiplier_verification=historical for every job. An empty membership list explicitly denotes warmup or format-pilot output. Snapshot checks are explicit per job so a finite deterministic validation schedule can be used without downloading slices for every hour forever.

    Run a bounded manifest:

    python tools/gate_history_metrics.py --manifest jobs.json \
  --output-root data-gate-research --max-hours 1

    The tool refuses a manifest exceeding its explicit hourly budget. It streams HTTP gzip directly into reconstruction; raw compressed or decompressed files are not written to disk. Feature rows are bounded to one hour in memory and stored as one zstd Parquet file with a source/quality manifest under exchange=gate/market=usdm/type=research_metrics/dt=.../symbol=.... Near-depth scans run once a second inside 25 bps rather than traversing the full book on every event; OFI needs only five levels per completed timestamp group.

    Parquet metadata records exchange, market, feature version, actual feature availability, quantity mode and units, quality, and universe policy. Base mode also records multiplier and verification status; count mode records auxiliary flow-weight units and omits multiplier metadata. The manifest also records compressed source SHA-256 and byte count, snapshot receipt, sequence and boundary diagnostics, feature count, row count, and measured elapsed time. Gzip EOF checks and advertised Content-Length checks precede output creation. Existing output is refused; temporary writes become final files by rename. A durable part-<hour>.write-intent.json records the exact job, universe policy and validated source receipt before any output is written. Its atomic staging filename includes a SHA-256 of the schema, job and policy. A prepublication restart may overwrite only that owned staging file when no output or published intent exists. Unknown staging files remain fatal and are preserved.

    The Parquet file and its manifest are synced before their renames; the manifest is published last. Both file contents and the parent directory are durable before the verified pair retires its intent. On resume, a complete pair passes the existing strict source, digest, schema, membership and causal-coverage checks. A matching remaining intent is removed only after verification. An incomplete publication may remove exactly its two final and two partial output paths only with a matching ownership intent. It is then regenerated. Unowned partials, mismatched intent provenance and corrupt complete pairs require inspection; none are repaired or accepted as good data.

    Binance execution with Gate feature inputs¶

    alpha_mining/gate_data.py attaches the compact book candidates under data["gate-f"][native_key]. DSL inputs use gate__<native_key>. The execution source remains Binance USD-M: Binance prices, traded volume, funding and costs continue through the shared execution evaluator. Gate midpoint is never substituted for Binance VWAP, and Gate book flow is never substituted for Binance traded volume. Transfer across venues is an empirical research question; evaluate it on the Binance execution results.

    The provider takes the builder-produced gate-research-source-v1 descriptor through the research gate_source_manifest option. It pins the mapping Parquet, job manifest and membership Parquet with their SHA-256 hashes. The descriptor contains mapping_file, mapping_sha256, jobs_manifest, jobs_sha256, membership_file, membership_sha256, and the explicit symbol_lifetime_policy=historical_disjoint_trading_lifetimes. Disjoint relistings reset maturity; reused exchange tickers for different underlying assets receive separate research identities. Paths are relative to the descriptor. Mappings are one-to-one; name similarity is not a mapping. Jobs and artifacts require certified source quality and their explicit quantity mode. Historical multipliers are required only for base/USD predictors; native contract counts enable the scale-free candidates without that dependency. The adapter verifies each artifact's Parquet digest, receipt job and universe provenance, metadata, source archive digest, exactly 60 ordered complete minute rows per hour, strictly earlier observed event timestamps and membership mask equality. Pilot units are rejected.

    A feature at Binance decision t uses exactly 30 Gate minute bars ending in (t-30 minutes,t]. The first requested execution timestamp therefore needs additional preceding Gate history. The adapter streams one hour at a time, aggregates its two half-hours, and populates 21 or 39 preallocated frames on the Binance decision grid. It retains neither multi-year minute rows nor a growing list of per-hour receipts. A rolling digest records verified artifact receipts. Outside explicit mapping and requested job coverage, values remain NaN. Missing hours or minutes within expected jobs fail; a selected member without covered book inputs fails. No forward filling or fake zero measurements occur. The exact verified descriptor membership is exposed to the research strategy layer for selection instead of reconstructing a different top-N universe.

    Thirty-minute aggregation is mandatory per feature:

    Minute feature Thirty-minute operation
    *_mean Mean of 30 equally sampled minute means; undefined values propagate
    *_close, including midpoint Last completed minute value
    Spread maximum Maximum
    Spread standard deviation Pool within-minute variance plus variance of minute means
    Depth additions/reductions Sum USD flow
    Source update rate Mean
    Normalized L1 and top-five OFI Mean minute-normalized OFI; this is not an exact reconstructed thirty-minute OFI
    Depth-flow imbalance Recompute from summed USD flows in base mode or native-count auxiliary weights in count mode
    Midpoint return Log close-to-close return across contiguous covered intervals; first available interval uses its observed opening midpoint
    Midpoint realized volatility Root-sum-square minute volatility, with observed opening/previous-close boundary jumps added across contiguous intervals

    The provider preserves the original execution-data store, exposes the verified membership and source provenance, and supplies a static canonical Gate metric catalogue. Any coverage-based offering or feature selection must use only Train. The closed final-test data cannot influence availability probing or aggregation choices.

    Verified archive boundary overlap¶

    Gate hourly files can contain updates timestamped after their nominal end. The ADA archive for 2025-08-02 02:00 UTC contains one update at 03:00:00.100; its complete reconstructed native book and final sequence 11787977128 exactly match the next file's initial snapshot. The next delta is at 03:00:00.200 with sequence 11787977129. The 03:00 file also contains fourteen updates at 04:00:00.100. This is observed source overlap, not a reason to introduce a 100 ms timestamp tolerance. The snapshot's timestamp denotes its nominal hour and can precede the effective availability of its included updates.

    Sampling remains one second, represented by RESEARCH_SAMPLE_CADENCE_MS. An overlap must end strictly before the next hour's first scheduled sample. An update at or beyond that first sample is unsupported and fails. Post-end updates are replayed only to verify continuity: sampling is capped at the nominal hour end, and those updates never enter closed-minute flow, OFI, book samples or observation watermarks.

    Any post-end overlap requires lazy acquisition of the next hourly archive. Its entire compressed stream is consumed and checked before its SHA256 and byte count are recorded. Its full initial native book, sequence and nominal snapshot timestamp must match the reconstructed tail and next boundary; the first subsequent delta must continue the sequence without preceding the tail's event time. The proof records the snapshot's effective availability as the last overlapping update timestamp. A missing or inconsistent proof fails acquisition. Exact-end updates retain the existing behavior and do not request this additional archive.

    Sequence-effective event timestamps¶

    The XRP 2025-08-04 15:00 UTC archive has one backwards timestamp among 1,659,798 records: row 550176 is timestamped 15:17:51.700 after 15:17:51.800. Its sequence is continuous, and replaying every unchanged record in source ID order produces the exact full initial book and sequence of the following hourly archive. Both archives pass gzip and SHA verification.

    The historical parser preserves source sequence order. An event whose raw timestamp falls behind the sequence clock is assigned the preceding effective timestamp only when both belong to the same one-second sampling bucket. There is no fixed millisecond tolerance. A regression across a completed sample, including a one-millisecond crossing, fails. Source IDs are never sorted or repaired. The parser retains the original millisecond timestamp through raw_timestamp_ms and records its displacement through timestamp_regression_ms.

    The converter reports the number of displaced records and maximum displacement in diagnostics. Its receipt declares event_clock_policy=sequence_effective_within_one_second_sample. Minute features use this causal sequence clock; late updates never enter an already completed second or minute. Full source checksums continue to identify the original bytes, including any raw timestamp anomalies.

    Source rejection versus transport retry¶

    Market-record validation raises GateSourceQualityError; sequence gaps retain the more specific GateSequenceGapError subtype. This includes malformed records, invalid snapshot or reconstructed book states, unsupported event times and unsuccessful independent checks. Configuration validation and local output failures remain ordinary errors and must not be quarantined as data.

    GateArchiveUnavailableError identifies an HTTP 404. Rate limits and HTTP server failures preserve their HTTP exceptions for transport retry. GateArchiveCorruptionError identifies invalid gzip data or CRC, invalid text, and abnormal gzip EOF after the complete declared compressed body was received. An abnormal EOF without a declared body length is unverified source data and receives the same quality rejection. A short declared body, including an HTTP incomplete read or short receipt, raises GateArchiveTruncationError, a ConnectionError that remains eligible for retry. Body decoder classification occurs only during archive reads; unrelated caller exceptions remain fatal.

    Typed exceptions retain source_metadata through worker-process serialization: the URL, compressed bytes read, their SHA256 and declared content length when available. complete identifies a complete declared body; otherwise this hash describes received bytes only, not a verified complete archive.

    The XRP 2025-08-08 00:00 UTC archive that previously ended with EOF was read successfully twice during investigation. Both reads produced 5,813,787 lines, 38,135,426 compressed bytes matching Content-Length, valid gzip CRC, and SHA256 58ec57e6de8d2a09d0ecde5fd6cfa760036a2df7652e5d8ac00b5431f94395cf. It is therefore not a reproducibly corrupt source file; a short transport response must not permanently blacklist this archive.

    Acceptance and remaining work¶

    A successful format pilot is evidence of reconstruction and resource usage, not historical coverage or alpha quality. Before a long conversion:

    1. Validate sample hours over multiple dates and several large and small instruments against aligned independent slices. Record coverage, final sequence, boundary tails, network bytes, throughput and peak resident memory.
    2. Supply asset mappings and exact dynamic minimum-order exclusion and universe provenance. Historical multiplier evidence is needed only when using USD predictors, not for native-count scale-free acquisition. Check archive availability for selected intervals.
    3. Require actual Binance USD-M trade-price/VWAP and funding coverage for execution. The book-only Gate output fabricates none of these fields. Native Gate execution would additionally require actual Gate trades/funding.
    4. Verify end-to-end Gate/Binance transfer on the selected historical universe, including exact membership and source availability at every decision.
    5. Compare the legacy 791 candidates, compact 21/39 candidates and a combined set under equal data, execution costs and search budgets. Fit imputation, normalization, redundancy clustering and all feature selection only on Train. Assess incremental information, prediction/portfolio performance after costs, temporal stability and sensitivity to liquidity regimes on permitted validation windows. Freeze selection before the closed Final test.

    No mass history acquisition, paid metadata access, live deployment or mining claim is made by this tool. The acquisition and source integration dependencies above remain acceptance gates.
