    Dual-market top-100 capacity evidence - 2026-09-29¶

    Result¶

    The selected 200 market-symbol-pair shape passed the archiver's 768 MiB memory cap and exact archive checks in one clean rerun on isolated NATS 2.10.29 with JetStream always-sync enabled. Its cgroup memory peak was 533,950,464 bytes (509.0 MiB, 66.3% of the 768 MiB limit); there were no cgroup max or OOM events and the external 80% guard did not fire.

    The publisher did not sustain the intentionally offered 2,700 events/s baseline under concurrent archival: queue slope after the 5-second burst was +740.4 events/s. The trial's sample is not a representative normal-arrival capture, so this is a capacity result for that stress profile, not a claim about expected production rate. The sample timestamp proxy and its limits are below.

    Sample and provenance¶

    Input was the preserved local corpus /opt/trading/codex-operations/offline-20260929-0050/mixed-corpus-final2/mixed-6000.jsonl, SHA-256 7c6c459386d7798919a1d07ec4705ce4cc3e397197656c2c5a064a601453a2eb. The corpus manifest describes 5,520 retained original rows, 480 removed original heartbeats, and synthetic appended poller, depth-tail, and trade-tail rows. Its contents are a bounded proxy, not a continuous venue capture.

    The sample builder selected by source event frequency, pinned USD-M-only poller symbols and the maximum trade/depth tails, and emitted 100 market-symbol pairs per market. It produced 4,235 rows from 100 shared symbol names. The sample is at /opt/trading/codex-operations/offline-20260929-0050/topn-capacity-200/topn-200-final.jsonl, SHA-256 6280140ac5a83b0646b619c1c27cee78119a5c93f7c894abe5249e111ab31e50.

    Spot rows are explicitly synthetic mirrors of cached USD-M diff, trade, kline, and heartbeat rows. No spot venue observations are implied. USD-M contains all nine relevant kinds; spot contains the four configured kinds.

    Rates in the timestamp column divide each market's selected rows by that market's received_ms span: 32,054.392 seconds for spot and 34,964.372 seconds for USD-M. The combined selected sample has 4,235 rows over 34,964.372 seconds, or 0.1211 events/s. These are sparse-corpus normalizations only: the corpus is constructed and non-contiguous, several poller kinds have only 32 synthetic examples, and spot is mirrored. This trial did not use an actual ranking cache. These figures do not establish a realistic sustained top-100 arrival rate.

    The 2,700/s offer rate was retained from the previous offline capacity profile as an intentional stress baseline, with a 5,400/s burst from second 10 through second 15. It was not inferred from the corpus timestamps or the collector's separate 600 weight/min REST quota. At the configured mix, the 2,700/s baseline allocates about 1,277.6 events/s to spot and 1,422.4 events/s to USD-M. The actual ranking cache and a continuous dual-market trace are needed before assigning a realistic normal-rate target.

    The selected tails include a 1,334-level diff with a 28,207-byte payload and a 202-byte maximum trade payload. The builder manifest records these bounds and per-market kind counts.

    Isolated trial¶

    An initial attempt completed publisher readback but timed out in the offline archiver harness because external mode compared processed rows with its 100,000-event maximum instead of the publisher's 80,999 actual messages. All JetStream consumers were at zero pending after final segment close and ACK. The first artifact is preserved at /opt/trading/codex-operations/offline-20260929-0050/topn-capacity-200/ and is not used for the passing result.

    Two focused regressions were added before the authorized rerun: external drain completion uses the actual publisher count, and external stream readback computes canonical Parquet row digests. Both failed before their corresponding fixes. The focused capacity/sample tests then passed 16/16 in the offline test image.

    The clean rerun used a fresh internal-only Docker network, no published ports, and a fresh NATS bind directory. NATS was nats:2.10, image ID sha256:5498ba57b9471840be3d15b033a4eec554d1c02fa6c2cc0ca2d888637f6c6e2f; /varz reported NATS 2.10.29, commit f91ddd8, and /jsz reported sync_always=true. JetStream file storage was capped at 200 MB. NATS had a 1 CPU / 512 MiB cap; publisher had 2 CPU / 1 GiB; archiver had 2 CPU / 768 MiB.

    NATS's maximum sampled CPU was 45.59% in docker stats; its cgroup ended with nr_throttled=0 and throttled_usec=0. There is no evidence this 1-CPU test cap throttled the broker. This also keeps the isolated broker more constrained than a production container without an explicit CPU cap.

    The exact run artifacts are preserved at /opt/trading/codex-operations/offline-20260929-0050/topn-capacity-200-rerun1/: publisher.json, publisher-expected.jsonl, archive-run/result.json, archive-run/source-manifest.json, archive-run/resource.jsonl, final NATS /jsz and /varz snapshots, and external-guard.tsv. The NATS data directory and stopped containers were preserved. No production/live container, volume, external configuration, or venue endpoint was touched.

    Archiver durability, readback, and merge¶

    The archiver drained and closed the remaining segments in 26.341 seconds after the publisher result was available. At the durable_drained snapshot it had zero open writers, pending rows, and pending ACK messages. All nine durable consumers reported ack_pending=0, pending=0, and redelivered=0.

    Segment close flushes pending rows, closes the Parquet writer, fsyncs the temporary file, atomically renames it, and fsyncs the parent directory before _ack_closed_segment ACKs messages. The archiver source hashes for this run are recorded in archive-run/source-manifest.json.

    The archive contains 38,337 spot rows and 42,651 USD-M rows. Per-kind rows are diff 18,982; trade 52,487; heartbeat 3,990; mark 1,881; kline 1,216; and 608 each for liquidation, info, funding, and stats.

    A 120,000-row prior-day depth fixture was merged during intake. The configured local sink delayed upload by 3 seconds, copied and fsynced the destination, then verified size and SHA-256 before source purge. Merge took 5.085 seconds. The verified merged object and preserved source are both 41,561,899 bytes with SHA-256 54c772c00c3aa96e6e83bd99a99c36c08d77da5ff3eeeca335c3fd6d2faf505f; missing, extra, duplicate, and row mismatch counts are all zero. The .shipped marker is present.

    Memory envelope¶

    The archiver cgroup limit was 805,306,368 bytes (768 MiB). Its exact memory.peak was 533,950,464 bytes; the verified-phase memory.current was 533,946,368 bytes, 4,096 bytes below that peak. Maximum RSS observed across resource samples and phase snapshots was 388,558,848 bytes.

    At the verified snapshot, cgroup anon was 324,509,696 bytes, file was 176,013,312 bytes, and inactive_file was 0. Maximum recorded inactive_file during intake/drain was 41,734,144 bytes. memory.events had zero max, oom, and oom_kill counts, and the external 80% guard completed without a stop event. The selected 200-pair shape therefore passes the 768 MiB archiver envelope for this trial, including merge and exact readback.

    Scope and remaining rate evidence¶

    No writer batching or NATS protocol change was tested, and this evidence does not validate production event rate. The observed queue growth applies to the explicit 2,700/s stress profile. The corpus-derived timestamp number is not a normal-rate estimate. No capacity remedy is claimed from this run; a realistic sustained target still depends on acquiring the actual ranking cache and a continuous source trace.
