    Trader full-history startup audit¶

    The imported legacy metrics are consumed as warmup. They are not rejected for their imported quality stamp. Live execution remains gated by each current window.

    main.py:_run_bars_service discovers the active venue catalogue before constructing BarsReader and before the PG history restore. Starting that service is therefore unsuitable as a probe during a REST ban. The separate offline probe does not invoke main, live connections, an executor, or any venue endpoint.

    trader/bars_service.py:restore_bar_history enumerates PG historical symbols and restores every completed payload through BarsReader.ingest. Imported bar_complete=false and full-window blindness remain in the durable payload but are not retained in the reader's projected numeric rows. BarsReader.exchange_data and trading_universe therefore use these imported numeric values. AlphaStrategy._history_mask checks maturity from the first valid close and does not assess quality metadata.

    The live path LiveTrader.collect_window computes the universe from those historical values, then asks intake for the current universe plus held symbols and evaluates the current WindowSet using DataQualityGate. Full-window blindness is POOR. LiveTrader.step skips strategy evaluation while POOR and reconciles the held book. A later current NORM window permits evaluation against the retained imported history. This is an explicit acceptance limitation; this audit does not propose discarding all imported history.

    Actual durable readback established 488,604 rows across 120 symbols, June 16 22:00 UTC through September 28 14:30 UTC. The grid contains 4,978 half-hour slots. The configured three alphas use 14 projected metric names, a 30-day maturity gate and a top-40 volume universe. BarsReader stores all imported rows without a history truncation. Each dense 4,978-by-780 float64 frame costs 31,062,720 bytes before index/column overhead; 14 such frames would cost 434,878,080 bytes. Numeric row dictionaries, their strings/floats, snapshots, masks and strategy temporaries are additional allocations. These estimates are not a memory acceptance result.

    A bounded read of the new broker retained exactly 780 last md.usdm.info.* observations, all TRADING: 570 PERPETUAL, 206 TRADIFI_PERPETUAL and four quarterly contracts. Production compatibility uses explicit USDT quote asset plus PERPETUAL type. Retained info omits quote asset, so the offline probe records a USDT-symbol-suffix approximation selecting 527 compatible contracts, while retaining all 780 catalogue symbols and all historical symbols in memory. This qualification must accompany the offline universe result.

    The external tools/probe_trader_history.py restores through the production reader using a PG session with default read-only transactions. It mounts the reviewed cursor-cycle cleanup candidate read-only, retains the exact main projection, computes the universe and invokes the configured live portfolio weight function. It logs restored row count, active/history symbol counts, retained numeric values, frame shapes, finite targets, hold state, strategy snapshot and RSS. The container is capped at 2.25 GiB with equal memory-swap allowance, and the probe checks its process peak against that same bound. It creates no PG schema and makes no REST calls. Its current run evidence is trader-history-probe.log; acceptance remains pending until restoration and evaluation both complete.

    Saved state at user pause¶

    Full actual projected restoration completed: 488,604 rows, 120 historical symbols, 782 total catalogue/history symbols, 6,351,852 retained metric values, 1,106,710,528 bytes process RSS after restore. The offline top-40 universe completed and was nonempty; its first five symbols were BTCUSDT, ETHUSDT, ZECUSDT, SOLUSDT and XRPUSDT. Observed cgroup peak was 1,278,447,616 bytes (about 1.191 GiB), with zero limit/OOM events.

    Portfolio evaluation did not run: the external probe incorrectly requested cfg.max_strategy_weight, whereas the live startup leaves that argument at the builder default. This is a probe error, not evidence of a production strategy failure. The container had already exited at 16:51:13.962 UTC with code 1 and no OOM before the pause instruction was handled. The cgroup observer also ended. No probe restart or correction was attempted after the user pause. Final logs and state are preserved in trader-history-probe.log and trader-history-probe-final-cgroup.json. The full evaluation/finite-weight acceptance gate remains open.

Final acceptance is pending the complete restored-history evaluation.

    Final resumed result - 2026-09-28 23:13 UTC¶

    The corrected probe completed with exit 0 on backend-trader:paper-20260928-e7dfee035140, image ID sha256:ed461154ea69c423646971dd9e7d44a77be95cfa0ea397afc1a1f373dbbb1515. Full restoration retained all 488,604 rows, 120 historical symbols, 782 total symbols and 6,351,852 projected metric values. Restoration took 1,152.418 seconds. The same nonempty top-40 universe was selected; the three configured strategies and live portfolio weight function evaluated in another 19.363 seconds after universe construction. Total measured runtime was 1,175.903 seconds.

    The target contained 40 finite nonzero weights, all within the selected universe, and did not request a hold. Gross weight was 0.6528320584786628 and net weight was -0.02665115052081013. Final strategy allocations were 0.5 for wf_depth_carry_all, 0.26943226371234674 for wf2_retskew_pos and 0.23056773628765329 for ask_side_depth_curve_steepness_neg.     Exact cgroup peak was 1,573,535,744 bytes (about 1.465 GiB), below the 2.25 GiB cap. Process peak RSS was 1,643,048,960 bytes (about 1.530 GiB). Both the in-process final sample and independent 50 ms host observer reported the same cgroup peak. Memory-limit, OOM and OOM-kill event counts were all zero; Docker exit status was 0 and OOMKilled was false. The seven actually requested dense metric frames each had shape 4,978 by 782.

    The actual full-history restoration plus current selected-strategy evaluation memory gate is now demonstrated for this snapshot. It does not establish an indefinite memory bound: full-history rows continue accumulating, and this was one evaluation rather than a soak. Imported unknown quality metadata remains a limitation; the offline feature probe deliberately bypassed the current-window quality gate, so it does not authorize trading on the incomplete imported bars. The retained exchange-info quote-asset approximation and dated catalogue boundary described above also remain explicit.

    The existing Markowitz path logged equal-allocation fallback for several early or degenerate history windows, and reported masked NaN strategy-weight cells being treated as zero. The final portfolio nevertheless had finite returns, allocations and 40 nonzero in-universe targets. These logged behaviors were preserved; no production code was changed by this probe.
