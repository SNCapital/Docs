    Quality stamp parity (NSC-33)¶

    Baseline 04e45d37, implementation reviewed 2026-09-28. Scope is shared bar classification and backtest validation; whole-universe causal admission and production acceptance remain separate work. Live uses common.bar_filter.assess_bar through assess_window. Daily frames and backtest reports now use the same classification. Unknown metadata is explicitly DEGRADED; no history field is synthesized from absent observations.

    Input anomaly Shared classification Strict backtest Non-strict backtest
    Complete, known stamp, below thresholds NORM Continues Continues
    No stamp, missing one field, null stamp value or null completeness DEGRADED, metadata_unknown Raises DataQualityError with bar_metadata_unknown Warns; report preserves unknown and classification
    Incomplete only DEGRADED Raises with bar_complete_false Warns and reports
    Blind >=60s or total gaps >=1 DEGRADED Raises with bar_quality_degraded Warns and reports
    Blind >=900s or total gaps >=20 POOR Raises with bar_quality_poor Warns and reports
    Incomplete plus POOR stamp POOR, retains incomplete reason Both findings reported Both findings reported
    Timestamp gap, including a fully stamped frame At least DEGRADED Timestamp-grid finding raises Warns and reports
    Missing prices/bar or disappearing symbol Existing grid/missing/run/disappearance checks retained Raises on findings Warns and reports

    Thresholds above are defaults. The backtest CLI loads gate thresholds from the existing live_config.yaml only when execution begins and passes them through DataQualityThresholds.bar_filter; the report serializes the effective values. Library AlphaPipeline defaults retain the shared defaults. Custom library runs must supply an explicit DataQualityThresholds(bar_filter=...) matching their live configuration for numerical parity. --help does not load runtime config.

    Live DEGRADED restricts targets to closing; POOR holds positions and continues reconciliation. Backtest non-strict mode deliberately continues computation with an explicit report; it does not emulate the live hold/rebalance policy. Optional DailyParquetReader filtering keeps only NORM, so legacy rows without proof are excluded when that filter is explicitly enabled. The ordinary raw backtest remains usable in non-strict mode and reports the unavailable evidence. Filtering does not pretend the remaining timestamps prove a complete original history.

    Metadata sources:

    • Raw aggregators and custom dictionaries: read only actually supplied metadata frames. Missing fields are unknown. Carried mark prices still have the existing observation-age limitation; receive-time and gap provenance cannot be recovered.
    • Go/Hive parquet: actual bar_complete column/legacy map, and actual blind_sec, diff_u_gaps, trade_agg_gaps columns, keys-map or stamp struct. All-zero values are metadata, not absent metrics. Metadata bypasses nonzero probes and cached regular metric frames; later roots preserve earlier metadata only for rows they do not contain. A newer winning row with absent quality metadata remains unknown; fields are never combined from different source rows.
    • PG and live bars: canonical BARS records carry the same stamp; decoder requires the complete wire stamp. Malformed wire records fail before gate assessment. Direct shared classification of incomplete/unknown records cannot label them NORM. Present malformed completeness and negative/fractional/non-numeric counters raise key-specific errors rather than being converted to clean metadata.

    Evidence: trader/tests/test_quality_stamp_regressions.py covers unknown/partial/null, POOR precedence, stamped gaps, strict/non-strict actual pipeline hooks, and actual parquet zero-metadata extraction across three layouts and multiple roots. Existing test_data_quality.py grid, prices, volume, disappearance and all-false completeness regressions remain in the validation set. No causal universe, live service/state, historical timestamps or quality hold behavior was changed.

    Validation after all edits, 2026-09-28:

    • Isolated pinned baseline plus the final new regression file: 27 failed, 3 passed in 2.94s. Existing incomplete-only and clean-metadata controls pass; the unknown, precedence, stamped-gap, pipeline stamp and real parquet contracts fail without the changes. Baseline extraction is outside the shared worktree.
    • Final focused unit gate: 103 passed in 4.26s, including 30 new regression cases plus existing parity, quality, daily reader, live three-state/universe gate and Go alias suites. The gate uses parallel unit selection and timeout=5.
    • No server or real account was altered. No full-universe historical or production parity is claimed; historical stamp absence and raw receive-time limitations are retained in the report.

    Peer-review additions, 2026-09-28:

    • Present malformed metadata fails loud: completeness must be boolean or numeric 0/1; counters must be finite nonnegative integers. Fractional values are never truncated into a clean counter.
    • Winning-row provenance is enforced across roots: a later row can replace prices and carry unknown quality, while disjoint earlier rows retain their metadata.
    • CLI execution uses the four gate thresholds from the existing live configuration and serializes them in the backtest report. Custom library callers explicitly provide DataQualityThresholds.bar_filter. The CLI help remains independent of configuration availability.
    • Review regressions failed against the pre-review validation/source-combining behavior. The focused final set passed 102 tests in 1.35s. Full-suite and actual full-catalogue resource/production acceptance are separate gates.

    Shared per-bar threshold values are immutable; a regression prevents mutation of the pipeline default object from changing another run. The regression fails with the pre-freeze mutable class and passes with the immutable value configuration.
