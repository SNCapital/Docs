    Funding availability and economic cashflow audit (P2.3 / NSC-29)¶

    Inspected baseline 04e45d37 and the shared working changes on 2026-09-28. This is a code audit and one bounded cashflow fix. It does not establish causal availability for historical observations, actual venue funding payments, or production acceptance of the wider NSC-29 epic.

    Distinct times and meanings¶

    • Exchange event time: mark-price WS E / timestamp_ms, when the venue says the predicted rate was observed. Prediction is not a paid rate.
    • Economic settlement time: REST fundingTime / funding_time_ms, identifying the realized funding event. It is not when the collector learned its rate.
    • Collector receive time: __received_ms, recorded after the REST response or when the WS message is received. It can be later than settlement/event time.
    • Realized economic cashflow: rate times the position actually held at settlement, with the correct sign. The single PnL kernel models this from weights; actual account payment/attribution must be reconciled separately.

    Bounded raw cashflow correction¶

    The prior raw aggregator forward-filled realized_funding onto every 30-minute bar. For a long with a single 0.001 event at 08:00 and another 0.002 event at 09:00, flat price and constant position, that charged 08:30 again and carried 09:00 into later bars. The repaired series charges 08:00 and 09:00 once. Total normalized cashflow is -0.003 for long 1 and +0.003 for short 1 with zero trading costs.

    Economic timestamps are binned with ceil('30min'), right-closed: 08:00 stays on 08:00; 08:05 maps to 08:30. This changes cashflow event aggregation, not predicted-rate availability. Multiple distinct events in one bin sum; exact same timestamp+rate observations deduplicate as repeated observations of one settlement. There is no inferred event identity beyond those recorded fields.

    Only non-event bins between the first and last supplied economic event are zero. Before/after that observed span, values stay NaN. A null event rate stays NaN rather than becoming a zero payment. If any distinct event in a shared bin has an unknown rate, the total for that bin stays NaN even when another event has a known rate. Interior zeros do not prove a missing settlement did not occur; complete source coverage remains a separate requirement. The synthetic raw reader now emits actual events at its documented fixed 00/08/16 schedule, instead of emitting a repeated rate as a new event every half hour.

    Remaining blockers and verdict¶

    The bounded raw repeated-charge defect is repaired. P2.3 code-path audit can be marked complete with these explicit findings; causal funding availability and full realized cashflow parity cannot be marked complete. Remaining work needs:

    1. Preserve actual receive time alongside economic time into both live/drain funding and mark adapters; test delayed delivery across a decision boundary.
    2. Census historical receive fields and coverage; mark unavailable history as unknown rather than fabricating timestamps or moving every row one bar.
    3. Reconcile actual symbol-specific settlement intervals and Go/Python event placement against actual funding events before replacing Go conventions.
    4. Define paper payment booking and real-account funding attribution with stable event IDs, held-position timing, and restart idempotency.

    No venue documentation claim, live payment, server operation, parameter rollout or real-data causal guarantee is made by this report.
