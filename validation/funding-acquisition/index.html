    Funding history acquisition receipts¶

    The offline funding downloader publishes a receipt for a successfully exhausted endpoint response. It does not certify unavailable historical economic data or produce a funding-coverage mask for the backtester.

    Binance documents inclusive start/end milliseconds, ascending responses, a maximum limit of 1,000, and truncation from the requested start when the result exceeds the limit. It also distinguishes Regular funding from Special dividend payments. The documented response has no explicit guarantee of the available historical horizon. Source checked 2026-09-29: Get Funding Rate History.

    Completion and preservation¶

    _backfill_symbol requests its exact inclusive interval. A full page before the end requires another page starting at the last economic timestamp plus one millisecond. A valid empty response, short final page, or event exactly at the inclusive end terminates successful acquisition. A failed request is different from an empty response and raises. Malformed, oversized, wrong-symbol, unordered/duplicate-time, out-of-bounds or nonfinite responses raise before files are published. An increasing historical interval is required. The backfill cutoff is based on the current UTC date, rather than interpreting a local calendar date as UTC.

    The supported current payment type is Regular. Explicit Special, null or unknown types fail; the existing timestamp-only event identity cannot safely represent dividend payments at the same economic time. Older responses without rateType remain accepted but are counted as legacy_untyped_rows; they do not become known regular payments or establish complete economic coverage.

    All pages are validated before publication. Every successful acquisition has a unique ID and new part-backfill-<id>.parquet filenames under the existing market=usdm/type=funding/dt=<day>/symbol=<symbol> hierarchy. Existing files are preserved on pagination failure and are never replaced by a narrower successful acquisition. Repeated observations are compatible with the existing reader and same-event aggregation; conflicting rates still fail there. The existing funding parquet schema is unchanged, including its float32 rate/mark-price precision.

    The receipt is atomically published only after its files are written and hashed. I/O failures propagate. A failed receipt publication can leave new unreferenced parts; those are not certified. Readers must verify every bound artifact before accepting a receipt. No earlier successful acquisition is overwritten.

    Receipt schema version 1¶

    Location relative to the raw root: market=usdm/type=funding/_coverage/symbol=<symbol>/<acquisition_id>.json. Artifact paths are relative to that same raw root, not the receipt directory.

    Field Meaning
    schema_version, acquisition_id Version 1; unique acquisition identity
    market, symbol, source_endpoint Exact acquired source and symbol
    interval_start_ms, interval_end_ms, interval_bounds Requested economic interval; inclusive applies to both ends
    started_ms, completed_ms Local acquisition wall-clock bounds, not historical decision availability
    acquisition_complete Validated endpoint response was exhausted; always true for a published receipt
    economic_coverage_complete False: historical endpoint availability/completeness remains unproven
    historical_availability unproven; no guessed lookback horizon
    rate_type_policy, legacy_untyped_rows regular_or_legacy_unspecified; count of missing-type legacy observations
    terminal_reason empty_page, short_page, or end_reached
    row_count Number of acquired observations
    pages Requested cursor/end/limit, response availability time, count, first/last economic timestamp, canonical response SHA256
    files Relative path, bytes, SHA256, observation count and first/last economic timestamp for each parquet part

    A successful empty query creates a receipt with row_count=0, files=[], and a zero-count terminal page. It proves an empty endpoint response, not zero economic payments in unavailable historical data. An end-midnight event is inside this inclusive request but does not certify the remainder of its day partition.

    Mandatory request budget¶

    One make_usdm_limiter instance owns every symbol and retry in a backfill run. Its collector weight quota and default ban backoff are loaded from the existing live configuration; the factory supplies the shared fundingRate/fundingInfo pacer. Every attempt acquires before its request. A 418/429 response updates the shared ban before waiting, including the configured default when Retry-After is absent. Rate-limit and transient retry budgets remain independent. No optional unlimited mode or new quota is added.

    This is process-local coordination. The offline job must not run concurrently with another IP-sharing process as though their independent budgets were shared. No external acquisition was run to validate this change.

    Raw backtest source coverage¶

    The raw backtest uses an explicit reference-source assumption: a valid exhausted funding-history acquisition supplies all payments exposed by the endpoint in its requested economic interval. This is endpoint/source coverage. It does not change economic_coverage_complete=false, assert a historical retention horizon, recover past receive times, or certify complete instrument cashflow accounting.

    The funding-specific reader validates receipt identity, pagination, bounds/counts, terminal conditions, safe relative paths and every bound artifact's bytes/SHA and contents before accepting an interval. Bound artifacts are verified in full even outside the requested output window. Recorded raw-response hashes remain acquisition evidence: the normalized float32 parquet cannot independently reconstruct original JSON rate strings or per-row rateType. Artifact data is parsed from the exact bytes verified. Missing, changed, unreadable, escaping, duplicated or contradictory source evidence fails explicitly.

    For a right-closed bar (previous_close, close], the whole integer-millisecond interval must be covered by the union of this symbol's verified source intervals. Only then does no event produce known zero. Distinct event rates are summed; duplicated observations of the same event count once; conflicts fail; an unknown actual rate remains unknown. A partially observed or uncovered bar is unknown. There is no funding-cadence guess, timestamp-extrema coverage, interval-gap fill, predicted-rate substitution, or extension past the exact inclusive endpoint. A successful empty receipt supplies a valid empty reference-source interval under this disclosed assumption. Receipt-only symbols participate in funding availability checks; invalid receipt evidence is not turned into a skipped strategy.

    MetricsDict handles funding even for empty input. The pipeline report serializes receipt IDs/hashes, source intervals, acquisition cutoff, source/type assumption, aggregation bounds, source-covered/uncovered counts and unknown-rate counts. Past causal availability stays unproven. The existing PnL guard checks lagged held positions: unknown held funding fails with symbol/time, whereas flat unknown bars contribute zero. Close/vwap execution and the sole PnL kernel are unchanged.

    Unreceipted single-file/daily sources supply observed events with unknown source coverage. The synthetic reader declares its actual simulated interval. Legacy files are not certified by this change. Go's fixed-hour approximation remains open; a verified raw sidecar for Go-backed prices/features is a separate task.

    Regression coverage lives in collector/tests/test_funding_acquisition.py: empty, short/full pagination and inclusive boundary; failed/nonadvancing/malformed pages; file preservation and artifact hashes; zero rates, type limitations and duplicate acquisitions through the real raw reader/aggregator; shared pacing/ban notification and configured missing-header backoff. Existing request retry regressions remain in collector/tests/test_funding_fetch.py.

    Raw coverage regressions in metrics/tests/test_funding_source_coverage.py use actual downloader receipts/parquet through the real reader, MetricsDict and AlphaPipeline with both execution models. They cover empty and irregular events, boundaries, full pagination, repeated acquisitions, source gaps, cross-symbol isolation, malformed/changed/escaping artifacts, leading off-grid events and uncovered held-position failure. Test price/weight fixtures isolate funding math; they do not certify strategy causality or actual historical dataset availability.
